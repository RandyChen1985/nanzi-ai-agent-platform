# 疑难缺陷诊断

临时拼凑的调试有个通病：改了一堆地方，突然好了，但不知道是哪一处起的作用，也不知道以后会不会再犯。

## 适合用它的时候

- bug 偶发、难复现，或者复现了但看不出原因
- 性能莫名变慢（接口变慢、页面卡顿）
- 前面已经有人试过几轮没搞定

## 诊断循环

1. **稳定复现**：能重复触发，才谈得上验证
2. **缩小范围**：二分、日志、断点，一次只排除一部分
3. **形成假设**：写下"如果 X，那么 Y 会变"这种可被证伪的判断
4. **验证**：跑一次，看预测是否成立
5. **修根因**：不是把症状压下去

## 注意

「改了就好了」不等于修好了。最后要能说清因果链：为什么这里导致那里，以及怎么证明换成别的输入也不会复发。
