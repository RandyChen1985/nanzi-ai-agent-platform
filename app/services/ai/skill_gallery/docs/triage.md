# 需求分诊

issue 堆积往往不是没人做，是**没人把它变成能开工的样子**：缺复现步骤、缺边界、缺验收标准。

## 适合用它的时候

- issue 列表看不过来，需要先分诊再动手
- 收到外部 PR，要判断值不值得合、缺什么
- 想把「这事到底要怎么做」先定下来，再交给智能体实现

## 状态机

每条 issue/PR 会被推到某个状态：需要更多信息 / 确认是 bug / 确认是需求 / 重复 / 不做。停在"待定"是不允许的。

对要做的，再产出 brief：背景、要改哪里、验收标准、已知风险。这份 brief 就是后面 `implement` 之类技能的输入。

## 注意

分诊的产出是**给人看也能给智能体看**的文档。如果 brief 里还有「这里看情况」，那就是没分完。
