# 深模块设计

判断一个模块好不好，看的是**接口与实现的厚度比**：接口很窄、里面很厚 = 深；接口一堆、里面只是转发 = 浅。

## 适合用它的时候

- 设计一个新模块的对外接口
- 老代码"改一处牵动五处"，想找接缝
- 觉得某段逻辑没法测，想调整结构
- 让 AI 改代码时它总是找不到重点（往往是结构没有地图感）

## 几个判断

- 调用方需要知道实现细节 → 接口太浅，细节漏出来了
- 一个类/模块的公开方法多得记不住 → 需要合并或收窄
- 测试必须 mock 一堆东西 → 接缝位置不对
- 改一个行为要动 N 个文件 → 概念没有收在一处

## 注意

这套词汇值得团队统一：讨论重构时用同一套词，比各说各的"封装""解耦"有效率得多。
