# 架构深化扫描

遗留代码库的架构问题不是"写错了"，而是**该深的地方还很浅**：一堆薄封装、到处泄露细节、改一处要动五个文件。

## 适合用它的时候

- 接手一个不太熟的代码库，想快速摸到结构问题
- 感觉"改起来越来越慢"，但说不清卡在哪
- 要做架构评审，需要一份能摆给人看的清单

## 两段式

**扫**：找出「深化机会」——可以合并的零散逻辑、可以藏起来的实现细节、可以收窄的接口。结果是一份 HTML 报告，按影响面排序。

**钻**：从报告里挑一个，用追问的方式往下推：改完之后谁受益、边界怎么划、分几步做、怎么验证没弄坏。

## 注意

扫描报告只是**候选清单**，不是"必须改"。架构改动风险高，真要动手前建议配 `codebase-design` 一起定接口。
