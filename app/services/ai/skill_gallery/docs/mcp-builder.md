# MCP 服务开发

把外部 API 变成模型能可靠调用的工具，难点不在「能跑通」，而在**工具该怎么设计**。

## 适合用它的时候

- 要从零写一个 MCP 服务（Python FastMCP 或 Node/TypeScript MCP SDK）
- 已有 REST API，想包装成模型可用的工具集
- 现有 MCP 服务的工具「模型老是调错」，需要重新设计入参与返回

## 它会强调的几件事

- 工具名与描述是给模型看的，必须说明「什么时候该调」
- 入参要收敛，宁可多个窄工具，不要一个大而全
- 错误返回要能让模型自我纠正，而不是抛一串堆栈
- 不要简单把接口 1:1 映射成工具

## 装了之后大概怎么用

说清楚要接入哪个服务、几个核心操作、调用频率与鉴权方式。它会先给工具清单让你确认，再落实现代码。
