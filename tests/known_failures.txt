# 已知失败基线（Known Failures Baseline）
#
# 用途：把"长期存在的失败"与"本次改动引入的回归"区分开。
#   - 命中本清单的用例默认被标记为 xfail，不阻塞 `pytest tests/`；
#   - 任何**不在**清单中的失败都会照常报红 —— 那才是回归信号。
#
# 用法：
#   pytest tests/                          默认：清单内 xfail，清单外报红
#   pytest tests/ --run-known-failures     照常运行清单内用例（看真实修没修好）
#   pytest tests/ --strict-known-failures  清单内用例已修好则报错（督促清理）
#
# 维护规则（重要，否则这套机制会退化成垃圾桶）：
#   1. 修好一个用例 → 立刻从本文件删除它，别留恋；
#   2. 新增条目必须归类并写清原因，格式：<nodeid>  # <分类>: <说明>；
#   3. 本文件只增不减 = 治理失败。--strict-known-failures 会替你盯着。
#
# 分类：
#   A-断言过时       断言/文案与当前实现漂移，机械但量大
#   B-依赖升级适配   主要是 AgentScope 2.0.6→2.0.9 之后测试替身/断言未跟上
#   C-环境与配置     依赖事件循环、外部配置或注入状态
#   D-测试状态污染   共享库里残留数据（标识符占用等），需要清理 fixture
#   E-疑似真实缺陷   失败发生在应用代码而非断言 —— 优先复核，可能影响生产
#
