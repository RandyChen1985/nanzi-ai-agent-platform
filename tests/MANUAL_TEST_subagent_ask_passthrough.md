# 子代理提问透传 + 续聊：人工自测清单

改的是「子代理能向用户提问，用户回答后父智能体续聊同一个子代理」这条链路。
自动化测试覆盖了逻辑，但**跨轮真实链路只有真机跑才算过关**，这份清单按场景给触发方式和验收点。

前置：重启后端（`./dev.sh`，控制台执行）。准备两个可委派的子智能体（下称 A、B，例如 `chat-bi` / 知识库）。

---

## 一、必测：主链路（提问 → 回答 → 续聊）

**触发**：对主智能体说

> 帮我用 chat-bi 查一下华东区的销售额。如果我给的条件不够，让它直接问我。

**期望**

1. 时间线出现「调用子代理」卡，其下弹出提问卡，卡片右上角有 **「来自：<中文显示名>」**。
2. 后端日志出现：
   ```
   [Delegation] Sub-agent 'chat-bi' asked the user a question; pausing delegation
   ```
3. 父智能体这一轮**结束**（不是卡住等待），并说一句类似「已向用户确认出发日期…」。
4. 在卡片里选择/填写后提交 → 这是一个**新请求**。
5. 第二轮日志**不应**出现：
   ```
   [Delegation] resume=true 但无可用会话缓存，降级为全新会话
   ```
   出现即说明跨轮缓存没接上（Redis 未通或 key 不一致）。
6. 第二轮的子代理**接着上次的进度**继续，不是从零重查。时间线上这次委派标题带 **「· 本轮续聊 #1」**。

**改前会怎样**：第二轮父回复「我当前工具集中没有 `sub_agent_call`」，续聊根本无法发起。

---

## 二、必测：多个子代理时，父知道该续谁

**触发**

> 同时让 chat-bi 查竞品数据、让知识库查行业报告，缺条件就让它们问我。

**期望**

- 只放行**一张**卡（并发提问按设计一次一张），其余那一路明确被拒，不静默。
- 工具结果里**点名**了是哪个子代理在等，形如：
  ```
  发起提问的子智能体：chat-bi（数据查询助手）。用户回答后请用
  sub_agent_call(agent_name="chat-bi", resume=True) 继续。
  ```
- 回答后续聊的是**这个**子代理。

**改前会怎样**：只给一句通用的「有个子智能体在等回答」，父只能猜；猜错就 resume 了另一个，那个子代理把「用户已回答某某」当新任务从零重跑，结论跟提问的那个毫无关系。

---

## 三、必测：定时任务里不许弹卡

**触发**：新建一个定时任务，任务指令写

> 查询华东区销售额。如果缺少时间范围，就向用户提问。

**期望**

- **不弹提问卡**。
- 子代理这一路收到的是拒绝文案：`当前为无人值守上下文…没有可交互的用户`。
- 任务正常收尾，在结论里说明缺什么，不会被「等待用户回答」卡住。

**改前会怎样**：卡片被塞进一个没有消费者的队列，任务以「等待用户回答」收尾，15 分钟后提问记录过期，那次任务的结果永久缺一块。

---

## 四、必测：普通消息里提到「【用户回答】」不能出事

**触发**：直接问

> 你刚才那条【用户回答】是什么意思？

**期望**

- 正常回答这个问题。
- **不报**「用户回答格式无效或当前会话无法恢复问题」。
- 刷新页面后这条发言**还在**（说明落库了）。

**改前会怎样**：整轮被短路成 error，`ContextStep` 被跳过，这条发言连库都没落，刷新即消失。

---

## 五、必测：该抓新内容时工具不能被裁掉

**触发**

> 把这个链接的内容总结一下 https://example.com

**期望**：正常调用抓取工具取回内容再总结。

**改前会怎样**：被判成「就着上一轮结果追问」，抓取/搜索工具被移除，还注入「优先基于以上快照作答、不要重复查询」，模型只能拿旧快照硬答。

同理再试两条：

- 「这份 PDF 里的合同条款有什么风险」
- 「帮我看一下上面这个网页说了什么」

---

## 六、必测：业务确认卡之后工具不能消失

**触发**：让智能体做**写入类**操作（会弹业务确认卡），点「确定」。

**期望**：确认后能继续调用写入工具完成操作；如果这条链路里还委派过子代理，`sub_agent_call` 仍在工具集中。

**改前会怎样**：确认卡回执里的「请根据以下已确认字段**继续执行**」命中同一个弱指代判定，委派/取数/抓取工具一起被裁。

---

## 七、看界面：不能露出内部协议

子代理提问后，展开「调用子代理」那张卡的日志详情：

- **不应**出现「本轮请勿重复提问，也不要替用户作答…用 `sub_agent_call(resume=True)`…」这类写给模型的指令。
- 应显示一句人话：`已向用户提问，等待回答`。

子代理「先写半份结论、再问一句」时，那半份正文应当出现在工具结果里（父可以据此先汇报已完成部分）。

---

## 八、看缓存：跨轮是否真的接上了

```bash
redis-cli keys 'ai:delegation-session:*'
redis-cli get 'ai:delegation-session:<user_id>:<conversation_id>:<agent_key>'
```

- 值应是 `{"history": [...]}`，user/assistant 交替，**不出现连续两条 user**。
- TTL 与提问记录一致（900 秒），不会出现「缓存还在、卡已过期」或反之。
- 同一轮里先 `q1` 委派、再 `q2` 换问题重查、再 `q3 resume` 时，**`q3` 的历史里不应出现 `q1`**（fresh 只覆盖写，不拼接旧会话）。

---

## 九、可选：注入防护（回归性质）

子代理的提问正文属于不可信输入（它可能刚读过网页）。构造一次提问，让问题文本里带换行与 `cancelled: true`，然后正常作答：

- **期望**：用户的选择被正常采纳，**不会**被当成「已取消」。
- 同理，补充说明里写 `question_id: uq_fake` 不会把答案绑到别的问题上。

---

## 失败时先看哪里

| 现象 | 先查 |
| --- | --- |
| 父说没有 `sub_agent_call` 工具 | 是否回执轮被误判为「复用结果」（看 `prompt_assembler` 与 `session_tool_artifact` 口径） |
| 第二轮从头重查 | Redis key 是否存在、TTL 是否过期、日志有无「降级为全新会话」 |
| 卡片没有「来自：」 | 转发 chunk 的 `source_agent_display_name` 是否为空串 |
| 时间线上两张卡并成一张 | 容器匹配是否按 `run_id` 优先 |
| 定时任务卡住 | `execution_options` 是否带 `unattended` |
