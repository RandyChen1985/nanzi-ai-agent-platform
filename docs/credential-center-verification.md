# 凭据中心：上线与验证

当前依据：[统一规格](superpowers/specs/2026-11-14-credential-injection.md) · [统一开发计划](superpowers/plans/2026-11-14-credential-injection.md) · [交互原型](../prototypes/2026-11-14-credential-injection.html)。历史方案来源、审计与已撤销规则见统一规格附录。

## 结构化凭据发布与验收

### 迁移和配置

1. 在隔离测试环境备份存量密文、绑定、授权及对应旧密钥，确认前序迁移已经应用。MySQL 使用 `db-prod/V218-add-structured-credentials.sql`，PostgreSQL 使用 `db-prod-pg/V118-add-structured-credentials.sql`，只执行对应数据库的一份文件。该文件包含类型、版本、实例、工具配置、使用授权、任务等待、两个系统参数及两种 MCP 结果策略；历史行保留 `legacy` 格式，无需解密或自动合并。
2. 两份脚本分别替代归档开发分支原 MySQL V216–V219、PostgreSQL V116–V119 的凭据迁移，当前连续编号为 V218/V118，紧接主分支 V217/V117。未执行、部分执行、全部执行过旧凭据迁移（包括旧合并文件 V220/V120）的环境，均可显式执行下方新文件：缺失结构补齐，已有配置、密文和已发布类型不覆盖。`--last` 按文件或版本断点选择；旧断点高于 V218/V118 时不会选中新文件，必须显式指定路径，不能继续依赖 `--last`。不自动改写 `.last_applied_sql`。主分支 V216/V217、V116/V117 是另外的功能迁移，不能因执行过旧开发分支的同编号凭据迁移而跳过。先将 API、调度器和执行节点升级到同一兼容版本，再保存页面配置。
3. 管理员在「系统配置 → 参数配置 → 凭证策略」展开密钥生成帮助，按下节在本地生成密钥并填写 `credential_payload_keyring_json`，再设置 `structured_credentials_enabled`。保存后平台从主库读取对应设置。首次保存前沿用原来的部署密钥环与活跃编号。密钥环 JSON 以明文保存在主库，主库备份包含这些值。
4. 从个人 IMAP 测试工具开始，依次验证创建、固定和按次授权、助手恢复、调度恢复、API 固定字段。启用的类型可选，保存结构化值需要有效的密钥环。系统凭据统一检查凭据中心的共享授权及类型、场景、域名等条件，无需再次配置逐工具凭据授权。使用合成值和模拟上游。

以下命令供部署人员在确认目标库后手动执行；本次代码整理没有执行迁移：

```bash
# MySQL（与下面 PostgreSQL 命令二选一）
./db-prod/apply-sql.sh db-prod/V218-add-structured-credentials.sql
# PostgreSQL
./db-prod-pg/apply-sql.sh db-prod-pg/V118-add-structured-credentials.sql
```

前置基线为 MySQL V217 / PostgreSQL V117 及以前的适用主分支迁移。合并 SQL 是增量升级文件，不是空库基线；新环境仍由各自导入入口按序执行全套迁移。真实双库首次执行、部分升级和重复执行需在可销毁测试库验收，静态校验不能代替这一步。

### 本地生成密钥与保存配置

在管理员自己的可信本地终端执行以下 Python 命令。它安全随机生成 **32 个原始字节**，再编码为 URL-safe Base64；输出为 44 个字符，保留末尾 `=`。这里的 32 指字节数，不是编码后的字符数。页面只提供复制，不执行命令或生成密钥。

```bash
python -c "import base64,secrets; print(base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())"
```

首次配置时，将本地输出替换下例的占位内容，然后粘贴完整 JSON 到密钥环输入框：

```json
{"active_key_id":"cred-v1","keys":{"cred-v1":"<替换为本地生成的密钥>"}}
```

轮换时重新生成另一把密钥，使用尚未使用过的编号。例如：

```json
{"active_key_id":"cred-v2","keys":{"cred-v2":"<替换为另行生成的新密钥>"}}
```

JSON 顶层只包含 `active_key_id` 和对象 `keys`；活跃编号必须是 `keys` 中的一项。所有编号均为 1–48 个英文字母、数字、下划线或连字符（`[A-Za-z0-9_-]`）。占位文本不能作为密钥使用。轮换保存自动保留服务端现有的可解码旧读密钥，不需读取旧值重新粘贴；同一编号不能替换成另一把密钥。切换活跃编号仅影响之后的新建或实例轮换，不会自动重加密全部旧实例。

密钥环输入留空表示页面不提交该字段，保留现有配置；留空不会生成或删除密钥。没有有效既有密钥环时，留空并开启总开关会被拒绝。直接调用接口时，省略字段或 `null` 才表示不更新，显式 `""` 无效。保存成功后只写输入清空，页面显示校验状态和活跃编号，不返回密钥值。复制命令或示例不会自动填写输入，剪贴板不可用时可手动选择帮助中的文本复制。

### 验收矩阵

| 场景 | 预期结果 |
| --- | --- |
| 密钥生成帮助与留空 | 帮助可展开并复制本地命令、首次及轮换占位 JSON；不生成或自动填入密钥。有效既有配置下留空保留；未配置或无效时留空不能启用；格式无效或活跃编号不在 keys 时拒绝保存。 |
| 类型禁用与创建并发 | 禁用生效后的创建被服务端拒绝。已有实例继续按其状态、归属、有效期和使用授权检查。 |
| 关闭结构化新建开关 | 结构化类型显示“已禁用（不可新建）”且详情/版本/Schema/预览可读，个人与管理创建选项保留但禁选。旧页面提交和直接调用创建 API 均拒绝；单值凭据、变量不受影响。 |
| 关闭后维护与运行 | 已有凭据可轮换、编辑和重新绑定，固定/动态 MCP、API、脚本环境变量、定时任务继续按原权限和实例状态运行；密钥无效仍报配置错误。聊天/定时补录可选择已有凭据，禁止新建；类型定义仍可编辑和发布。 |
| 重新开启与类型状态 | 关闭不修改类型自身启用标记；重开后原先启用的类型恢复可创建，管理员原先禁用的类型保持禁用。 |
| 类型发布、轮换和停用 | 新版本保留启用状态，旧实例保持原类型版本。轮换保留固定引用。停用后，新调用被拒绝。 |
| 由模型推导账号 | 模型可结合当前消息、历史、邮件、网页和工具结果中的账号线索，先查询当前已挂载工具对应类型的凭据候选，再填写 credential_account。后端只在当前执行用户本人或已共享且符合工具权限的候选中精确匹配；唯一匹配自动执行，未确定或歧义进入原生选择。 |
| 固定凭据 | 模型没有 credential_account，也不需要查询候选。对已挂载固定工具调用候选接口，应返回 CREDENTIAL_CANDIDATES_NOT_REQUIRED 并提示直接调用；只有未挂载工具返回 CREDENTIAL_TOOL_NOT_AVAILABLE。固定/规则切换后的工具装载应及时更新参数投影。 |
| 授权卡新建 | 全局允许结构化新建且类型启用时可按当前工具的类型版本新建个人凭据。表单预填经核验的账号，使用范围限定当前服务域名与 MCP 场景。用户点击“保存并继续”，保存成功后恢复当前调用。关闭新建时仍可选择已有凭据，但旧表单提交新建必须拒绝。 |
| MCP 调用与 API 工具 | 字段绑定后从模型工具参数剔除。连接认证只用于出站认证，组映射只用于对应工具参数。API 结构化字段用于固定请求头或请求体。工具、配置、目标、用户或权限失效时拒绝执行。 |
| JSONPath 结果、进度与错误 | 默认凭据调用只交付状态。配置模型可见结果字段后，模拟上游返回业务 JSON，核对选中节点的字段和值原样进入工具结果，包括名称为 token/password 的字段及与合成凭据相同的值。完整注入请求不写入模型参数、进度或出站审计，错误和取消后注入上下文复位。 |
| 助手和任务恢复 | 跨用户拒绝；授权到恢复之间发生停用、撤权或配置变更时重新校验。并发继续只消费一次。任务选择可确认供后续运行复用，只存引用，每次读取当前值；任务修改或取消后旧卡不能补录/恢复。 |
| 脚本环境变量 | 单值凭据与结构化标量字段可按固定映射注入独立 Docker/K8s 执行实例；平台和个人开关均开启，凭据允许 script_env。模型参数、命令、共享目录和任务定义不含注入值。stdout/stderr 与产物检查凭据回显；不支持的执行策略拒绝执行，不降级到宿主机。 |
| 统计与关联工具 | 统计包含有权限的单值及结构化凭据；infer 候选由专用查询按工具返回。详情的工具按固定绑定、类型匹配、成功使用取并集并去重，不能把固定绑定数为 0 解释为没有使用。 |

### 灰度、轮换与回退

- 只向测试账号配置经核验的工具。观察拒绝原因、审计完整性、授权超时和出站次数。
- 完成对应的数据库迁移并升级所有执行节点后，需要总结邮件时，在「MCP 工具集 → 对应工具 → 参数设置」按实际响应逐行配置 RFC 9535 JSONPath。例如 `$.messages[*].subject` 取邮件主题；二维数组可用 `$.messages[*][1]` 取第二列；`$` 选择完整业务根值。支持对象、数组、标量、负下标、联合、切片、递归、过滤和标准函数。基于解包后的业务 JSON 查询；局部数组结果按原下标用 `null` 占位。留空、非法或无匹配时仅返回受限状态；合法路径按原结构返回实际选中内容，不按字段名或凭据值二次过滤。空数组本身可由 `$.messages` 选中，`$.messages[*]` 在空数组上无匹配。
- 使用服务 Header、连接令牌或逐参数凭据的 MCP 工具，在「参数设置 → 逐参数设置」将模型可见的结果字段与参数来源一起保存。此入口也支持无输入参数的工具，所需列已包含在 V218/V118 合并迁移中。同一条凭据的工具继续使用组凭据里的配置。
- 工具测试台显示对话调用名和结果不可见原因。模型只收到执行状态或选中的业务数据。检查本次是否读取到所需邮件时，按已保存的路径试跑并确认 `result_visibility` 为 `projected`。
- JSONPath 选中的内容原样进入模型上下文，并可用于对话历史、执行追踪或定时任务结果。修改配置只影响后续调用；同一服务若改变输出格式，需按新格式重新核对配置。
- 「由模型推导账号」的 `credential_account` 来自凭据中心，工具说明给出绑定类型名称、键与版本。可用 `list_mcp_credential_candidates` 按当前挂载工具查询必要元数据，再将用户口语账号对应到保存的规范账号；不再要求本轮原文逐字包含账号。模型不能读取凭据字段，后端仍验证归属/共享、类型版本与工具权限。
- 轮换时为新密钥使用新编号并指定为活跃编号。保存会保留原有读密钥，新建和实例轮换使用活跃编号，旧密文继续使用原编号。
- 关闭 `structured_credentials_enabled` 仅禁止新建结构化凭据，已有凭据的调用、定时任务、轮换及绑定继续可用；类型定义仍可管理。实例停用、过期、撤权和密钥错误仍限制使用。全局开关不修改类型自身状态，单个类型的新建权限继续由类型状态控制；关闭后不要移除已有密文所需的读密钥。回退到只识别部署变量的版本前，需为该版本恢复可解密现有数据的密钥环，并核对旧版本关闭开关的语义。
- 升级前核对待确认的工具调用。旧快照可能因工具参数结构、profile 或调用名变化而失效，受影响的调用重新发起。普通会话的选择仅对当次调用生效；定时任务可在确认时选择复用，平台只保存当前任务和执行主体绑定的引用。
- 现有应用审计、聊天历史或备份中可能留有升级前的数据。保留期限和历史数据处置单独核对。用户应在凭据表单录入值，聊天输入中的普通文本按聊天数据处理。

## 一、先执行数据库变更（旧版凭据中心）

以下内容用于回溯旧版凭据中心的初始化和回归。

三件事，顺序不能换。

### 1. V209 已执行过的话，要单独去外键

凭据中心的六张表**没有外键**（要能单独导出再导入，外键会强制父表先存在，导入顺序一错就整批失败）。如果之前的 V209 已经建好表，那批表上是带外键的，重跑 `CREATE TABLE IF NOT EXISTS` 不会改已有表：

```sql
-- MySQL
ALTER TABLE sys_secret_grants    DROP FOREIGN KEY fk_grant_secret;
ALTER TABLE sys_secret_bindings  DROP FOREIGN KEY fk_binding_secret;

-- PostgreSQL
ALTER TABLE sys_secret_grants    DROP CONSTRAINT fk_grant_secret;
ALTER TABLE sys_secret_bindings  DROP CONSTRAINT fk_binding_secret;
```

确认干净（两个库都应为 0 行）：

```sql
SELECT table_name, constraint_name
FROM information_schema.table_constraints
WHERE constraint_type = 'FOREIGN KEY'
  AND table_name LIKE 'sys_secret%';
```

### 2. 没执行过的，按顺序跑

```
db-prod/V209-add-credential-center.sql   -- 六张表 + 菜单种子 + 变更审计 + credential_params
```

PostgreSQL 对应 `V109`。

> 早期版本的菜单种子单独放在 `V210-add-credential-center-menu.sql`，现已合并进 V209 的第二段。仓库里不再有这个文件——如果你在旧文档或笔记里看到它，按 V209 执行即可（`CREATE TABLE IF NOT EXISTS` 与带 `START/END` 标记的菜单段都是可重入的）。

### 3. 菜单种子已改动

`app/services/menu_seed.py` 里新增了 `menu:system:credentials` 与 `element:system:credentials_manage`。如果你们的部署流程依赖菜单种子自动同步，重启即可；如果是手工导入 `ai_agent_menus`，跑 V209（菜单段在文件中部，带 `START/END` 标记，可单独截取执行）。

## 二、影响面：哪些既有功能被动了

改动不只「新增功能」，有四条既有链路被碰过。**回归优先看这四条。**

| 链路 | 改了什么 | 风险 |
|---|---|---|
| **记录边界** | 凭据输入和注入请求保留隔离；只有实际经 MCP JSONPath 投影标记的结果按选中内容保存，其他既有出口仍按原规则处理 | 不得把 MCP 的结果许可应用到工具入参或脚本输出 |
| **API 工具调用** | `generic_api._perform_request` 的 header 段多了一次绑定的解析 | 多一次 DB 查询；`${CREDENTIAL:}` 占位符处理顺序 |
| **MCP 出站调用** | `mcp_client` 在 `build_mcp_headers` 之后叠加绑定 | **绑定优先**，会覆盖 `fixed_token` |
| **脚本工具执行** | 有 env 绑定时进入独立执行器，后台内存经 stdin 协议交付本次环境变量，依赖安装阶段不接收凭据 | 不支持的策略明确拒绝；无绑定脚本保持原执行路径 |

其余为纯新增：个人中心 tab、系统管理页面、菜单节点、凭据表。

## 三、回归：确认没弄坏既有功能

重启服务后挨个走。**这些项任何一条不对劲都比新功能不通更严重**，因为它们影响存量用户。

### 1. 脱敏还在工作

随便跑一轮对话，让智能体调用一次带密钥的工具（或用一个配了密钥的数据源），然后看审计：

- 注入请求和配置值不得被输入链路写入 `query` / `summary`；主动选中的 MCP 返回内容按下一条结果规则记录
- 工具入参和注入请求不得记录凭据；MCP 经 JSONPath 选中的返回值按原样保存，不能把此类结果重新按字段名或相同凭据值过滤
- 出现 `${secret:config.xxx}` 这种标记是**正常的**——那就是脱敏后的形态

```sql
-- 抽查最近的历史记录，看有没有漏网的密钥形态
SELECT id, LEFT(query, 200) FROM ai_agent_chat_history ORDER BY created_at DESC LIMIT 5;
```

### 2. 四种工具照常能跑

| 工具类型 | 怎么做 | 应有的结果 |
|---|---|---|
| API 工具 | 找一个**没绑定凭据**的已有工具，试跑一次 | 和改动前一样成功；带 `${CREDENTIAL:}` 占位符的仍报「凭据还没填」 |
| MCP 工具 | 找一个配了 `fixed_token` 的服务，调用一次 | 成功，用的还是那个共享 Token |
| 脚本工具 | 跑一个无凭据绑定的已有脚本 | 成功；stdout 与改动前一致 |
| 定时任务 | 手动触发一次已有任务 | 成功；日志里执行用户是任务创建者 |

脚本工具分别验证无绑定与有绑定路径。有绑定时检查隔离提供者、双开关、场景和目标摘要；无绑定时仍使用原执行器，不创建凭据专用实例。

### 3. 后台日志没有新噪音

```bash
grep -c "SecretInject" <your log file>
```

预期是 **0**，或只在真的绑过凭据时出现。如果每次调用都刷一条 WARNING，说明绑定表查询在失败——那是迁移没执行完的信号。

（表不存在时会触发 60 秒熔断，不会刷屏，但第一次的 WARNING 会明确写「读取绑定失败」。）

### 4. 界面没塌

- 个人中心 10 个 tab 都能点开，「我的凭据」在「我的 MCP」和「我的任务」之间
- 工具编辑页 → 高级请求配置 → Headers 的「键值对」模式能增删行、能保存
- MCP 服务编辑页的认证区块正常，未绑定时不显示「已绑定」
- 系统管理侧栏出现「凭据中心」（管理员账号）

## 四、新功能：确认真的能用

### 建一条凭据

个人中心 → 我的凭据 → 新建。

- 类型选「凭证」，场景勾上「API 工具」，域名白名单填目标服务的域名（**留空等于只允许平台内部目标**，发往外部会被拒）
- 提交后列表出现，值显示为掩码，没有「查看」按钮——这是设计，不是 bug

### 绑到一个 API 工具

工具管理 → 编辑一个已有工具 → 高级请求配置 → Headers。

1. 点某个 header 行右侧的钥匙图标
2. 选刚建的凭据 → 保存绑定
3. 那一行的值应变成 `${CREDENTIAL:你的标识}`，图标变绿

新建工具时钥匙是灰的——绑定的消费者是工具 id，工具没入库就没有可绑的对象。

### 证明注入真的生效

在隔离测试工具中使用合成凭据和模拟服务：服务端核对收到的字段是否符合映射，只返回验证状态，不返回凭据。也可用错误合成值验证认证失败分支；401/403 本身不能独立证明映射正确。

| 现象 | 说明 |
|---|---|
| 模拟服务校验映射后返回成功 | 注入字段与预期合成值一致 |
| 使用错误合成值后返回 401 / 403 | 认证失败路径正常；结合模拟服务断言核对实际映射 |
| 报「凭据还没填」 | ❌ 绑定没写进去，或场景/域名被拦（看使用记录） |

完成后清理测试记录。不要为验证而修改实际服务使用的生产凭据。

### 看使用记录

个人中心 → 我的凭据 → 使用记录。每条记录有场景、结果、目标域名。

`result` 的取值和含义：

| result | 含义 | 该查什么 |
|---|---|---|
| `success` | 取到了值 | — |
| `denied_by_binding` | 这个槽位没有绑定 | 绑定没保存成功，或绑到了别的工具/槽位 |
| `denied_by_grant` | 系统级凭据没授权给你 | 找管理员授权，或检查 `dept_code` 是否匹配 |
| `denied_by_scenario` | 凭据没开这个场景 | 编辑凭据，勾上对应场景 |
| `denied_by_host` | 目标域名不在白名单 | 编辑凭据补白名单；**空列表只允许内部目标** |
| `denied_by_script_policy` | 脚本 env 被平台策略关着 | 系统配置开 `secret_policy_allow_script_env` + 个人偏好两层都开 |

### MCP 服务的绑定

MCP 服务 → 编辑 → 认证区下方「用凭据中心的凭据」。

绑上之后**优先于上面的固定 Token**；使用模拟服务验证优先级与执行用户权限，不修改实际生产 Token。

### 脚本工具的环境变量

脚本工具 → 编辑 → 第四步「依赖与超时」→ 环境变量 → 「+ 绑定环境变量」。

弹窗里填**变量名**（要和脚本里 `os.environ["..."]` 完全一致），选择允许「脚本环境变量」场景的凭据。单值直接绑定；结构化凭据需选择已发布类型中的标量字段，例如 `password1 → MAIL_PASSWORD`、`port1 → MAIL_PORT`。平台策略和执行用户偏好须同时开启；共享凭据仍须有使用授权。

验证方法：脚本里写

```python
import json
import os

print(json.dumps({"credential_present": bool(os.environ.get("MAIL_PASSWORD"))}))
```

使用合成凭据，在已配置 Docker/K8s 沙箱的会话中调用已保存脚本，预期 `credential_present` 为 `true`。字段错配、目标摘要变化、无权限、开关关闭应拒绝整次注入，不允许仅填部分环境变量。数字和布尔值按确定格式转为环境字符串；对象/数组不能直接映射到一个变量。

值不写入命令行、共享 `.env` 或全局 `os.environ`，只交给本次独立执行实例。stdout/stderr 在统一返回前检查回显；用合成值故意回显时预期被替换或隐藏，不能期待原样输出。可导出的文本产物也经过路径与内容检查。完成、超时和取消均清理实例。此脚本输出策略与 MCP 的 JSONPath 原样返回分别处理。

### 变量类凭据读明文

列表里只有「变量」类型的行有「查看值」按钮。点开能看到明文并复制——「凭证」类型没有这个按钮，接口也会 403，设计上就不存在这个能力。

每次读取都会记一条使用记录，弹窗里也写明了。

### 这条凭据用在哪

绑定管理显示显式绑定；详情中的“使用工具”另按固定绑定、类型匹配及成功使用历史取并集。同一工具只计一次，并展示各来源标签；列表固定绑定数量不等于使用工具并集数量。

- **全局**：管理员做的绑定，对所有能用该消费者的人生效
- **我绑的**：只影响你自己，并会覆盖全局

删掉消费者（工具 / MCP 服务 / 脚本）时绑定会一起清掉，不会留孤儿。

### 系统级凭据与授权

管理员在「系统管理 → 凭据中心」建一条系统级凭据，然后：

1. 授权给用户 A
2. A 登录 → 个人中心 → 我的凭据 → 系统共享 → 能看到
3. 用户 B 登录 → 看不到（列表里连名称都没有）
4. 撤销授权 → A 也看不到了

结构化凭据也使用上述同一授权。类型及版本匹配的 MCP 测试台、模型候选和动态关联中应出现该共享凭据；固定绑定、聊天/定时恢复和实际注入均需再次检查授权。已有个人绑定在撤权后可以保留，但不允许继续注入。API/脚本/MCP 认证字段同样可以由被授权用户绑定到自己的槽位，脚本仍受平台和个人开关控制。

在 MCP 参数设置的“同一条凭据”中选好类型/版本，再切换为“固定凭据”，下方应立即显示“我的固定凭据”，无需预先保存。列表包含本人及已授权系统凭据，后者标注“系统共享”。选择后点“保存设置”，配置和个人引用一起保存；重新打开应回填，模型调用无需传 `credential_account`。加载失败可点“重新加载”，旧绑定已失效时需明确选择其他凭据或留空解除个人绑定。类型/版本变化后应重新筛选，不能沿用不兼容的引用；保存失败时原配置和绑定均保持不变。

名称和账号不是一回事：例如名称“adb的邮箱凭证”、账号 `mcp.mail.user-secret`，应先用候选工具的 `keyword="adb"` 查询，再使用返回的完整账号调用。直接填写 `credential_account="adb"` 不会按名称模糊匹配。

旧 `/credential-profile/grants` 接口不再决定使用权：历史查询及清理保留并标明不生效，PUT 新增返回 410，统一去凭据中心授权/撤销；旧记录不会转换为全局共享授权。本次无需执行新 SQL 迁移。

「未授权连名字都不出现」是刻意的：凭据名本身是情报（`sap.prod.admin_token` 这种名字一看就知道有什么）。

## 五、出问题时看哪里

| 症状 | 先看 |
|---|---|
| 凭据列表一直转圈 / 报错 | 迁移有没有跑完；`sys_secrets` 表在不在 |
| 绑定保存成功但调用没用上 | 使用记录的 `result`；日志 `[SecretInject]` 前缀 |
| 每次调用都刷 `SecretInject` WARNING | 绑定表查询失败，多半是迁移没落全（会熔断 60 秒） |
| 界面报 404 而不是 403 | 正常。未授权的凭据连「存在」都不该暴露 |
| 管理员的「凭据中心」不出现 | 权限码 `menu:system:credentials` 有没有写进 `ai_agent_menus` |
| 凭据脚本无法执行 | Docker/K8s 提供者、平台和个人开关、script_env 场景、变量名、结构化字段及目标摘要 |

## 六、运维约定

以下约定在当前实现中继续生效：

- **脚本 env 还要单独开闸**：界面上能绑了，但注入要求平台策略 `secret_policy_allow_script_env` 与用户偏好（我的凭据 → 策略）**同时**打开，两层默认都是关。只绑不开，脚本拿不到变量。
- **存量 MCP token 导入**：决定不做——`fixed_token` 是服务级共享的，搬进凭据中心效果一样且变得更难维护。需要按用户区分时，让用户自己绑即可，绑定会自动盖过 `fixed_token`。
