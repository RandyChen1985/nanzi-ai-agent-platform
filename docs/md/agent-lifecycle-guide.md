# 智能体全生命周期开发流程

从零建一个智能体，到它成为全公司可用的生产基线，中间要经过**新建 → 配置 → 发布 → 审核 → 上线 → 迭代 → 下架**这几步。

这份文档按你实际会遇到的顺序讲，每一步都说明**谁在做、做完是什么状态、下一步该点哪里**。

---

## 一、先搞清楚三个概念

动手之前，先把这几个词分清，后面会反复用到：

| 概念 | 含义 | 谁决定 |
|---|---|---|
| **智能体** | 一个"人"，有名字、头像、类型、引擎 | 创建者 |
| **版本** | 这个"人"某一次的能力配置（提示词、模型、工具、技能） | 每次都新建一版，不覆盖历史 |
| **系统级** | 这个智能体是**公司生产基线**，全公司（经授权）可用，改动要审核 | 管理员审批 |

两个关键区别：

- **版本发布**：换掉"当前生效的是哪一版配置"，你自己就能做，**不需要审核**
- **设为系统级**：让这个智能体变成公司资产，**需要管理员审核**

这两件事互不替代。一个智能体可以先有线上版本，很久以后才申请成为系统级。

### 版本有哪几种状态

| 状态 | 含义 | 能改吗 | 能删吗 |
|---|---|---|---|
| `DRAFT` 草稿 | 还在开发 | ✅ 随便改 | ✅ |
| `PUBLISHED` 线上 | 正在生效的配置 | ✅ 可以改内容，但**改完要重新发布**才生效 | ❌ |
| `ARCHIVED` 归档 | 被新版顶替的历史版本 | ❌ 只读 | ✅ |

> 同一时刻**只有一个** `PUBLISHED` 版本。发布新版本时，旧的自动转成 `ARCHIVED`。

## 二、完整流程一张图

```
 【普通用户】                              【管理员】
                                              
 ① 新建智能体                                
    └→ 生成草稿 V1（套用模板）                
                                              
 ② 配置 & 调试                               
    ├─ 改提示词 / 模型 / 工具 / 技能          
    ├─ 调试台试跑（可指定任意版本）            
    └─ 版本对比                                
                                              
 ③ 发布版本  ←─────── 这一步自己做，无需审批    
    └→ 状态变成 PUBLISHED（线上）             
                                              
 ④ 想让它成为公司基线？                        
    ├─ 点「申请发布为系统级」──── 站内信 ────→ ⑤ 审核队列
    │   （填写申请理由，可选）                  ├─ 通过 → 智能体立刻变系统级
    │                                           └─ 驳回（必填理由）→ 退回，可再来
    └─ 申请期间自己不能改（管理员可以）          
                                              
 ⑥ 上线后的迭代                               
    ├─ 直接改草稿（系统级也允许）              
    └─ 改完点「申请上线」──── 站内信 ────────→ 管理员审批 → 发布该版本
                                              
 ⑦ 下架（取消系统级）                          
    ├─ 管理员操作，需填原因                    
    ├─ 弹窗显示：已分配给 N 人（附名单）        
    ├─ 勾选通知 → 这 N 人收到站内信            
    └→ is_system = false，授权保留（重新上架自动恢复）
                                              
 ⑧ 人员变动                                    
    └─ 管理员「变更权属人」→ 记入发布历史 + 通知新权属人
```

## 三、第 1 步：新建智能体

**入口**：智能体中心 → 左上角「新建智能体」

向导分 6 步，可以随时存草稿退出，下次接着做。

### 需要填什么

| 步骤 | 内容 | 说明 |
|---|---|---|
| 1. 智能体信息 | 物理标识符、显示名称、描述、头像、类型 | **物理标识符全局唯一**，创建后不要再改 |
| 2. 模型策略 | 模型、温度、编排模型 | 决定"思考方式" |
| 3. 工具能力 | 勾选能用的工具 | 决定"能做什么" |
| 4. 系统提示词 | 角色设定、行为约束 | 决定"是什么人" |
| 5. 欢迎语 | 开场白、引导卡片 | 可选 |
| 6. 确认保存 | 检查后创建 | 生成草稿 V1 |

### 关于"套用模板"

新建时后端会按你选的**类型**套一个模板：

| 类型 | 模板来源 |
|---|---|
| 通用助手 | 主助手（main） |
| ChatBI | ChatBI 助手的配置 |
| 知识库助手 | 知识库问答助手的配置 |

模板会把提示词、模型、工具**整份带过来**，省去你从空开始配。

> **注意**：模板里的工具如果引用了**模板作者私有的 MCP 服务**，而你没有那个服务的权限，系统会**自动帮你剔掉**，并在创建成功的提示里告诉你「已跳过 N 个你无权使用的工具」。
>
> 这是有意的：那些工具对你永久不可见，留着只会让智能体一保存就报「无权访问该 MCP 服务」，而你在界面上既看不到、也取消不了。

### 建完之后

智能体出现在列表里，状态是**已启用**，有一个 `DRAFT` 版本的 V1。**此时还不能给别人用**——需要先发布一个线上版本。

---

## 四、第 2 步：配置与调试

**入口**：卡片上的「配置与发布」

### 你会看到什么

左侧是版本列表，右侧是配置编辑区，分 6 个步骤（和新建时一致）。顶部有**配置完成度 4/5** 这样的提示，告诉你还差什么。

### 三个常用动作

**1. 改配置**

选中一个 `DRAFT` 版本直接改。改完**保存**只是存草稿，不影响线上。

> 已发布的版本（`PUBLISHED`）也能改内容，但改完不会自动生效——必须重新发布。发布按钮对系统级智能体的非管理员是**灰的**，只能保存草稿（见下文第 6 步）。

**2. 调试**

不用发布就能试跑。调试台（`/dashboard/agent-debug`）可以：

- 选智能体
- 选**具体的调试版本**（默认跟随线上版本，也可以选某个还没发布的草稿）
- 直接对话看效果

版本列表里每行也有「去调试」按钮，一键带着这一版跳过去。

> 这一条对系统级智能体特别有用：线上版本动不了（要审核），但你可以把新草稿拿来试。

**3. 版本对比**

选中两个版本 → 「对比」，你能看到提示词、模型、工具、技能的逐项差异。跳过没变的部分，只标出真正改了什么。

### 配置体检

打开版本编辑器时，系统会检查**当前配置能不能真的跑起来**：

| 检查项 | 发现问题时 |
|---|---|
| 模型是否可用 | 黄色提示「相关调用会失败」 |
| 工具引用的 MCP 服务 | 列出失效的工具名 + 原因 |

工具失效有几种原因，处理方式不同：

| 原因 | 含义 | 怎么办 |
|---|---|---|
| 无权访问该 MCP 服务 | 这是别人的私有服务 | **一键移除**（你拿不到权限） |
| MCP 服务已禁用 | 管理员临时关掉了 | 等服务恢复，或先移除 |
| MCP 服务已删除 | 服务没了 | 移除 |
| 工具已下线 | 单个工具被禁用 | 移除，或等恢复 |

**「一键移除」**按钮会自动清掉所有失效引用，你重新发布即可。

## 五、第 3 步：发布版本

**入口**：版本列表里选中某个版本 → 「发布上线」

**这一步不需要任何人审批。** 点确认后：

- 该版本变 `PUBLISHED`，立刻生效
- 原来的线上版本自动变 `ARCHIVED`
- 进发布历史（记下时间、操作人、版本号）

### 发布前系统会拦的情况

| 情况 | 提示 | 怎么办 |
|---|---|---|
| 你不是所有者也不是管理员 | 无权限修改此智能体 | 找所有者或管理员 |
| 系统级智能体 + 你不是管理员 | 发布按钮是灰的 | 走「申请上线」 |
| 该智能体有待审申请 | 审核中不能发布新配置 | 撤回申请先改，或等结果 |
| **配置未就绪** | 提示缺少什么 | 见下表 |
| 版本不属于这个智能体 | 数据异常 | 重新进页面 |

「配置未就绪」具体指：

| 缺少项 | 什么情况 |
|---|---|
| `primary_capability` | 主能力与类型不匹配（比如选了知识库助手但没勾知识库能力） |
| `data_query_tool` | ChatBI 类型但没配数据查询工具 |
| `knowledge_base_binding` | 知识库助手没绑定任何知识库（且系统没有默认库） |
| `knowledge_base_tool` | 知识库助手没勾知识库检索工具 |

> 系统会在发布前拦这些，是因为它们会造成「发布成功、一用就报错」。

## 六、第 4 步：发布为系统级（关键环节）

**系统级 = 公司生产基线。** 它可以被授权给任何人，全公司共用；代价是**改动必须审核**。

### 谁都不能在新建/编辑时勾"系统级"

表单里没有这个开关，接口也会拒绝。系统级只能通过下面两条路获得——**每一次都要记录日志、发通知**：

| 你的身份 | 操作 |
|---|---|
| 管理员 | 卡片菜单 →「发布为系统级」，直接生效 |
| 普通用户 | 卡片菜单 →「申请发布为系统级」，等管理员审批 |

### 普通用户的完整路径

1. 点「申请发布为系统级」，填写申请理由（可选）
2. 卡片出现**审核中**标记（`审核中 · 期间不能发布新配置`）。此时你**可以继续改草稿、建版本、用草稿调试**，只是发布被拦住
3. 管理员在顶部「发布审核」入口看到待审数量角标
4. 管理员打开申请，看到你提交时的配置快照（只读），选择：
   - **通过** → 立刻变系统级，你收到站内信
   - **驳回**（必填理由）→ 退回，你能重新编辑，也会收到站内信
5. 期间你可以**撤回**申请，撤回后立刻解冻

### 成为系统级之后会怎样

| 你能做的 | 你不能做的 |
|---|---|
| 改草稿、建新版本、调试 | ❌ 发布版本（要申请） |
| 复制一份自己继续开发 | ❌ 改名称/描述/头像/启停/删除 |

**元数据全部只读**，能力配置可以改草稿。要改线上内容，走「申请上线」（见下一步）。

### 一个重要澄清：系统级 ≠ 全员可用

系统级只是"公司资产"，**不会自动分配给所有人**。管理员还需要在**用户/角色管理**里给具体的人授权。

没被授权的人：看不到这个智能体、也没法用。这是有意设计的——生产基线不等于人人能碰。

---

## 七、第 5 步：上线后的迭代

成为系统级之后，日常迭代是这样的：

```
你发现提示词要改
  └→ 打开「配置与发布」，改草稿（或新建 V4）
      └→ 调好，点「申请上线」
          └→ 管理员审批
              ├─ 通过 → 这一版发布上线，旧版归档，你收到站内信
              └─ 驳回 → 版本仍是草稿，你继续改
```

**为什么要申请而不是直接发布**：系统级是生产基线，谁在什么时候换掉了线上配置，必须有人负责。申请单里记着「申请的是哪一版」，审核时管理员看到的也是那一版，不会出现"申请的是 A 版、审核时被改成 B 版"。

### 待审期间：冻的是"发布"，不是"开发"

| 动作 | 待审期间 |
|---|---|
| 改草稿、新建版本、用草稿调试 | ✅ 照常 |
| 发布版本（改线上配置） | ❌ 被拦住 |
| 改名称/描述/头像、启停、删除 | ❌ 锁死 |
| 撤回申请 | ✅ 随时 |

理由是审核的**对象**是"提交那一刻的这份配置"——申请单里存了快照，审核人看的就是它。你在草稿里继续改，不改线上、也不影响审核内容，没理由把开发停下来。

想立刻让改动上线：先撤回申请，改完重新提交；或者「复制智能体」另开一条自己发布。

管理员不受限制（他是审核方，可能需要帮申请人修配置）。

同一时刻**一个智能体只能有一个待审申请**。

## 八、第 6 步：下架（取消系统级）

**入口**：管理员 → 卡片菜单 →「下架（取消系统级）」

### 下架弹窗会告诉你什么

- **已经分配给多少人**，附具体名单
- 影响的是哪些人

### 下架时会发生什么

| 项目 | 结果 |
|---|---|
| `is_system` | 变为 `false` |
| 已分配的授权 | **保留**（重新上架时自动恢复） |
| 被授权的用户 | **立刻看不到它**（列表按 `is_system` 过滤） |
| 站内信 | 默认勾选发送，可以取消（取消时会明确告诉你"用户不会知情"） |
| 发布历史 | 记一条 `UNPUBLISH`，含影响人数与是否通知 |

> **重新上架**会自动恢复之前的授权，不用重新分配一遍。

### 主助手不能下架

主助手是系统固定入口，下架它等于把整个平台的默认对话入口干掉，所以直接禁止。

---

## 九、第 7 步：人员变动（变更权属人）

有人离职或转岗，他名下的智能体就没人能编辑了。管理员可以转交。

**入口**：管理员 → 卡片菜单 →「变更权属人」

### 怎么用

1. 搜索要接手的人（支持用户名/姓名，边打边搜）
2. 选择（当前权属人会打标，避免选错）
3. 填写变更原因（可选，会记入发布历史）
4. 确认

### 转交后

| 项目 | 结果 |
|---|---|
| 权属人 | 变更，新权属人可编辑、建版本 |
| 系统级智能体 | **额外补授权**（否则新权属人"看得到、用不了"） |
| 站内信 | 新权属人收到「智能体已转交给你」 |
| 发布历史 | 记一条 `TRANSFER_OWNER`：从 A 变更为 B，附原因 |

### 转交时的工具体检

如果智能体引用了**原所有者私有的 MCP 服务**，换人之后新权属人用不了那些工具。转交时系统会按新权属人的视角体检一遍，并提示：

> 权属人已变更，但新权属人有 N 个工具无权使用，请在版本配置中移除后重新发布

**系统不会自动改你的配置**——转交是身份变更，不该顺带改内容。带着这份清单去编辑器里点「一键移除」即可。

### 哪些情况不能转交

| 情况 | 原因 |
|---|---|
| 主助手 | 系统固定入口，没有"归谁"的概念 |
| 有待审申请 | 申请单记的是当时的申请人，换人对不上 |
| 目标账号已停用 | 转给停用账号只是换个方式变孤儿 |
| 转给同一个人 | 没意义 |

### 怎么发现哪些智能体需要转交

管理员会在智能体中心顶部看到提示：

> **N 个智能体的权属人已停用** · 已无人能编辑，建议转交给仍在岗的同事 · [只看这些]

点「只看这些」直接筛选。也可以在筛选面板里选「权属人 → 权属人已停用」。

## 十、发布历史：什么时候能查什么

**入口**：卡片菜单 / 详情 →「发布历史」（管理员和创建者可见）

它是一条**合并时间线**，把申请单和操作事件放在一起：

| 类型 | 显示 | 触发时机 |
|---|---|---|
| 申请 | 提交发布申请 / 申请已通过 / 申请被驳回 / 申请人撤回 | 审核流程每一步 |
| `PUBLISH` | 发布为系统级 | 管理员直接发布，或审核通过 |
| `UNPUBLISH` | 下架（取消系统级） | 管理员下架 |
| `BASELINE_PUBLISH` | 发布新基线版本 | **任何智能体**发布新版本（不只系统级） |
| `META_UPDATE` | 修改元数据 | 改了名称/描述等 |
| `TOGGLE_ENABLED` | 启用状态变更 | 启用/停用 |
| `TRANSFER_OWNER` | 变更权属人 | 转交 |

每条能展开看**当时的配置快照**（提示词、模型、工具、技能），所以事后能回答"当时线上到底是什么配置"。

## 十一、常见问题

### 为什么我改不了这个智能体的配置？

按可能性排查：

1. **它是系统级、且你不是管理员** → 能力配置可以改草稿，但**元数据只读**、**不能发布**
2. **它有待审申请** → 草稿能改，但发布与元数据被锁住，撤回或等审核结果
3. **它不是你创建的** → 只有创建者和管理员能编辑
4. **权属人已停用** → 找管理员变更权属人

### 为什么工具显示「无权访问该 MCP 服务」？

那个工具属于**别人的私有 MCP 服务**，你拿不到权限。在版本编辑器里点「一键移除」清掉，然后重新发布。

这类引用通常来自两个地方，现在都已处理：
- 复制别人的智能体（复制时自动剔除，并告知跳过几个）
- 新建时套用模板（套模板时自动剔除，并告知跳过几个）

已经存在的智能体需要手动清一次。

### 为什么我看不到某个智能体？

非管理员只能看到两类：

1. 自己创建的
2. **系统级 + 被授权给自己**（或自己所在的角色）

「系统级」不等于「全员可用」，授权是单独的一步。

### 系统级智能体的发布按钮为什么是灰的？

因为它是生产基线。你需要点「申请上线」，由管理员审批。

### 复制一份和申请编辑有什么区别？

| | 复制 | 申请 |
|---|---|---|
| 结果 | 一个新的、独立的智能体 | 改原来那个 |
| 影响线上 | 不影响 | 影响（审批通过后） |
| 适合 | 你想大改、或只想给自己用 | 想改进公司基线 |

复制出的副本归你所有，可以自由编辑发布，和原来那个没有任何关联（不会合并）。

### 下架之后，之前分配的人还能用吗？

不能。下架后 `is_system=false`，他们立刻从列表里消失。但**授权记录保留**，重新上架会自动恢复。

如果下架时勾了通知，他们还会收到一条站内信。

## 十二、状态速查表

| 状态 | 谁能改配置 | 谁能改元数据 | 谁能发布版本 | 谁能删 |
|---|---|---|---|---|
| 普通（非系统级），你是所有者 | ✅ | ✅ | ✅ | ✅ |
| 普通，你不是所有者 | ❌ | ❌ | ❌ | ❌ |
| 系统级，你是所有者 | ✅（只能改草稿） | ❌ | ❌（需申请） | ❌ |

|---|---|---|---|---|

## 附：一条最短路径

如果你想最快看到效果：

1. **新建智能体** → 选类型、填名字 → 保存（得到草稿 V1）
2. **配置与发布** → 改系统提示词 → 保存
3. **调试** → 试几句话，效果满意
4. **发布上线** → 立刻生效，自己能在对话里用了
5. 想给别人用 → 找管理员**授权**；想成为公司基线 → 点**申请发布为系统级**

后面每一步都不影响前一步的成果——它们是**在已有基础上加一层**，不是推倒重来。
