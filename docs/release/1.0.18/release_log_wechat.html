🚀 核心特性 (Key Features)

01 · 接入 Langfuse 链路追踪：AI 思考过程与 Token 消耗一目了然

告别大模型调用的“黑盒”时代，全面接入业内知名的开源可观测平台 Langfuse：

  • 成本账本清清楚楚：无论是多轮复杂对话，还是内部自动写 SQL、意图分析、总结摘要，每一笔大模型调用的响应速度与 Token 消耗全部精准统计。
  • 开箱即用与安全脱敏：在管理后台填入密钥即可直接测试连通，无需重启服务；自带敏感内容脱敏开关，只记性能与用量、不泄露隐私，省心又安全。

🐛 缺陷修复 (Bug Fixes)

🧠 AI 运行时 / 链路追踪

· Langfuse 默认过滤器丢弃根 span：默认上报过滤器仅认自家插桩，重写 should_export_span 精确放行平台命名空间。

· Langfuse 重建 client 阻塞事件循环：关闭旧 client 改为后台异步任务处理，配置无实质变动时跳过无谓重建。

· 直调 span 篡改外层 Trace 标识：解耦 identity_attributes()，直调 span 仅绑定会话与用户，保留外层 Trace 名称完整性。

· 采样温度设为 0.0 被当作未设置：修正以真假值判定的逻辑，数值型解析器正确放行 0.0 绝对严谨温度。

· 沙箱执行步骤日志被自身子步骤遮挡：优化执行时间线日志流收集结构，确保父命令与容器终端输出分层呈现。

🔐 账号认证 / 邮件通知 / 安全风控

· 忘记密码接口存在邮箱枚举攻击面：统一各分支（不存在/待审核/限流/成功）返回一致成功消息，异步发信消除耗时侧信道。

· 重置密码核销失败却提前作废 Token：调整为前置只读校验账号状态与密码复杂度，保存时刻原子 GETDEL 一次性核销。

· 改密后既有泄露会话依旧有效：重置密码或修改密码成功后立即全量吊销旧会话凭据，强制重新鉴权登录。

· 邮件测试接口存在开放代发风险：连通性测试邮件强制限定发给当前登录用户自身邮箱，严防凭据冒用。

· 自定义 SMTP 加密方式被硬编码为 SSL：改为根据端口自适应（465 对应 SSL，其他对应 STARTTLS）并支持显式配置。

· 收件人含有全角标点导致发信失败：增加全角标点归一化清洗与格式校验，支持输入法混合逗号分号。

💻 前端交互 / 性能 / 跨平台

· 全屏弹层遮罩受局部容器限制：统一改用 Teleport to="body"，确保遮罩覆盖率 100%。

· Token 统计加载慢与图例遮挡：指标请求改为并行聚合，压缩卡片高度；优化 ECharts 图例居中布局，消除与 X 轴刻度重叠。

· WSL/Linux 环境运行脚本提示 \r 错误：引入 .gitattributes 并全量转为 LF，彻底清除脚本中的 CR 换行符。

· 历史失败测试基线大清理：清理过期测试用例，修复 Mock 漂移与跨用例上下文泄漏，大幅收敛测试清单。

📖 平滑升级指南 (Upgrade Guide)

遵循以下标准步骤即可平滑无缝升级至 v1.0.18.0。请务必注意：本版本新增 4 组数据库迁移必须执行、需安装 langfuse 依赖、改密成功后旧会话自动吊销属于预期内安全加固。

方式一：源码拉取升级（开发与虚机部署）

# 1. 同步拉取主分支最新代码

git fetch origin && git checkout main && git pull origin main

# 2. 执行数据库结构平滑迁移 (MySQL / PG)

bash db-prod/apply-sql.sh # PG: bash db-prod-pg/apply-sql.sh

# 3. 更新依赖组件（安装 langfuse==4.15.6）

poetry install --no-root

# 4. 刷新工作区行尾（Windows 用户推荐）并启动本地服务

git checkout-index --force --all && ./dev.sh

📌 检查项：拉取后若在 Windows/WSL 运行脚本报 \r 错，执行 git checkout-index --force --all 即可完成本地工作区 LF 行尾刷新。

方式二：Docker 容器化升级（生产环境推荐）

# 1. 执行数据库增量升级 (宿主或临时容器)

bash db-prod/apply-sql.sh # PG: bash db-prod-pg/apply-sql.sh

# 2. 导入官方 Release 镜像归档（x86_64 / ARM64 按架构选择）

docker load -i nanzi-ai-agent_1.0.18.0_linux-amd64_*.tar

docker load -i nanzi-ai-agent_1.0.18.0_linux-arm64_*.tar

# （或在本地自主构建：cd docker && ./build_linux_x86.sh 1.0.18.0）

# 3. 重启容器服务

cd docker && ./start-nanzi-ai-agent.sh

方式三：沙箱构建与跨平台运维 CLI（若启用沙箱策略）

# Docker 沙箱：环境预检与镜像构建

bash sandbox/docker/build-docker-sandbox-image.sh

# K8s 沙箱：集群就绪与 RBAC 权限健康检查

bash k8s_deploy/nanzi-k8s.sh health

# K8s 沙箱：构建沙箱网关镜像（默认内置清华源加速）

bash k8s_deploy/build-k8s-sandbox-image.sh --pip-index https://pypi.tuna.tsinghua.edu.cn/simple
