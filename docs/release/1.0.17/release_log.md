# 🎉 NanZi AI Agent Platform v1.0.17.0 Release Notes

**GitHub Repository**: [RandyChen1985/nanzi-ai-agent-platform](https://github.com/RandyChen1985/nanzi-ai-agent-platform)

v1.0.17.0 版本是一次以 **AgentScope 2.0.9 精确版本锁定与运行时行为收敛、执行时间线全链路可观测（Bash 命令原文 / 工具调用元信息 / 意图摘要）、向量索引维度守卫与重构进度抽屉、Doris 数据源适配与字段维度下钻元数据、智能体一键复制与三层继承专属头像** 为核心驱动，并全面推进 **大模型请求读取超时可配置、工具结果上限放宽至 64Ki、Redis 浏览器业务分组、沙箱与 K8s 升级运维、系统配置与系统诊断页信息架构重构、全站表单控件与 Toast 视觉基础设施统一** 的重量级可观测性与工程治理版本。

AI 运行时首次做到**版本可控**：`agentscope` 由无上限的 `>=2.0.6` 锁定为 `==2.0.9`，结束「镜像重建时间不同即装到不同版本、本地与线上静默漂移、故障无法复现」的历史。执行时间线升级为 **Bash 命令原文 + 模型写的意图摘要 + 调用元信息**；工具结果上限由平台 4000 字符与框架 2000 token 双闸门统一放宽到 **64Ki**，MCP 结果不再被提前截断。

数据侧交付 Doris 数据源适配器、字段维度角色与下钻层级组，以及物理表分区与索引字段元数据，让 ChatBI 生成的 SQL 可裁剪、可命中索引，并让 AI 能识别可分组字段与下钻链。

平台侧补齐智能体一键复制、物理标识符重名预检、专属头像三层继承、用户批量启停与角色双列穿梭框；同时完成系统配置页与系统诊断页的信息架构重构、K8s 沙箱镜像源与升级向导治理。

本次变更范围自 `832351c44a09c7723576252dea132aa6357c03e2`（含）至 `3f2063d82c0449ebd75a9094c9d4ad9cf169d779`（含），共 **89 个提交**（其中非 Merge 提交 74 个），涉及 **311 个文件**、**35,653 行新增代码**与 **2,703 行删除**。

> ⚠️ **升级注意**：本版本**无强制重新登录、无权限码变更**（延续 1.0.16 凭据体系不变），但有两点必须执行：其一，`agentscope` 已从 `>=2.0.6` 锁定为 `==2.0.9`，**Docker 沙箱镜像必须重建**（镜像内容哈希已变化，旧的预构建镜像不会被运行时复用，且旧镜像会让 Bash 工具直接 500）；其二，若你曾手工在系统配置中写入过 `agentscope_tool_result_limit`，需自行将其调整为 `65536`（默认值已改，仓库内无迁移种子）。详见下方 Upgrade Guide。

## 🚀 Key Features

### 1. 🔗 AgentScope 精确版本锁定与运行时行为收敛 (AgentScope Version Pinning & Runtime Hardening)
*   **依赖从「无上限」改为精确锁定**：`>=2.0.6` → `==2.0.9`，结束「镜像重建时间不同即装到不同版本、本地与线上静默漂移、故障无法复现」。
*   **大模型请求读取超时可配置**：默认 180 秒——原先 SDK 默认 600 秒与看门狗持平，上游卡住时业务层重试实际上没有触发窗口；范围 30-300 秒，可在系统配置内调整。
*   **两处防御性收敛**：上下文图片上限显式固化为 5（防上游改默认值静默改变平台行为）；结构化输出失败与基础设施错误分类，为差异化重试留出接口。

### 2. 🧭 执行时间线全链路可观测 (Execution Timeline Observability)
*   **展示 Bash 命令原文与调用元信息**：命令此前在三处被丢弃、只能翻调试抽屉；现用独立字段承载，并接上模型 / 温度 / 工具状态等元信息，刷新与历史回放不再丢失。
*   **Bash 行显示模型写的意图摘要**：如 `Bash · 前端契约全量回归`；仅对 Bash 生效以避开自有工具同名字段的语义冲突，模型未填时不伪造。
*   **工具结果上限统一放宽到 64Ki**：平台 4000 字符 + 框架 2000 token 双闸门叠加，4000 字符以外的内容在任何地方都不再存在，模型「去 sessions 读完整结果」只会读到别轮内容；现两层对齐 64Ki。

### 3. 🧠 向量索引维度守卫与重构进度抽屉 (Vector Index Guard & Rebuild Progress)
*   **维度变更不再静默失效**：索引校验由「存在性」升级为「存在且维度一致」，不一致自动触发重建；重建保留已有文档数据，不因重建丢记忆，记忆工作台给出「维度不匹配」警示与修复引导。
*   **重构有了实时进度抽屉**：系统配置与记忆工作台的向量重构统一改为右侧抽屉，实时展示状态、阶段、进度、耗时、逐条日志与失败明细；关闭抽屉不取消后台任务。
*   **任务日志通道与互斥锁**：新增通用 `TaskLogService`；修复「重启后 30 分钟内重构被误挡」「任务状态与过期时间分两次提交、进程被杀后留下永不过期的 Redis 键」等缺陷。

### 4. 🏢 Doris 数据源与字段维度下钻元数据 (Doris Adapter & Dimension Metadata)
*   **新增 Doris 数据源**：兼容 MySQL 协议，复用既有驱动与适配逻辑，连接测试、表列表、DDL 获取、采样与 SQL 执行全链路打通。
*   **让 AI 下钻不再「靠猜」**：字段新增维度角色与层级组 + 序号，标记出「哪些字段可以分组」「哪几个字段构成从粗到细的下钻链」；同时记录物理表分区与索引字段，使生成的 SQL 可裁剪、可命中索引。
*   **修掉 3 处列保存缺陷**：改字段类型保存不上（不报错、刷新即回退）；**不带字段列表的保存会删光整张表的字段元数据**（数据丢失隐患）；新维度字段无取值与长度边界，超长值表现为整张表保存 500。
*   **补齐 PG 迁移缺口并保护人工标注**：维度三列原先只提供了 MySQL 脚本，PG 主库一部署即 `UndefinedColumn`；另修复「走一次智能导入就抹掉全部人工标注的维度角色」。

### 5. 🤖 智能体中心：一键复制、重名预检与专属头像 (Agent Center & Avatar Inheritance)
*   **一键复制智能体**：单事务复制「元数据 + 最新已发布版本」，副本直接可用、排序紧邻源、字段深拷贝；复用 `element:agent:create` 权限、不新增权限点，系统智能体也能当模板。
*   **标识符重名边输边提醒**：新增预检接口并与创建路径共用同一查询，杜绝「预检说可用、创建却失败」；失焦 + 输入期防抖双时机校验，撞名时禁用确认按钮，改名撞唯一索引由 500 变为可读提示。
*   **专属头像三层继承**：消息自带 → 智能体专属 → 全局官方形象 → 内置默认，并防止两层兜底互相触发死循环；完整头像控件补进新建·编辑弹窗（原先只放在一个仅新建时才存在的步骤里）。
*   **AI 聊天头像「旧页面倒灌」四层治理**：显式编辑闸门、乐观并发 409 护栏、拔除本地缓存、动态时间戳文件名消除浏览器强缓存；另修复部分预设因地址超长（2197 > 后端 2048 上限）报 422。

### 6. 👥 用户与权限治理 (User & Role Governance)
*   **用户批量启用 / 禁用**：多选 + 二次确认，自动跳过当前登录账号并如实分项回报；提交后按快照逐个失效会话缓存，确保禁用立即踢下线。
*   **角色「分配用户」重构为标准双列穿梭框**：修掉「徽标人数 ≠ 列表条数」（候选池超过 1000 被静默截断，实测默认角色 6 名成员只渲染出 2 名）；接口支持分页 / 搜索 / 排除已是成员，并锁定「全量成员 ID 不受分页影响」的契约。
*   **补齐 default 角色引导**：新建用户时自动勾选，缺少该角色时给出提示与一键初始化。
*   **修复知识库类型智能体无法被委派**：就绪判定从一个根本没有这两列的对象上取字段，取值恒为空，导致任何该类型智能体无论怎样配置都判未就绪——表现为「直接选中能用、一委派就说尚未就绪」。

### 7. 🖥️ 平台运维与全站前端体验统一 (Platform Ops & Frontend Experience)
*   **系统配置页与系统诊断页重构**：诊断页由三列分栏改为上下结构、操作卡片置顶并排、控制台占满整行；配置页改为「分组图标只管形状、颜色只表达状态」，并修掉「切换分组时滚动位置不动、看到的是新分组的中间部分」与「分组超过一屏时底部永远滚不到」。SSH 沙箱同步补齐 `sshpass` 环境探测，私钥字段改为独立文本域（脱敏遮罩、格式校验、公钥拦截）。
*   **Redis 浏览器按业务分组**：由最多 5000 条键平铺改为 **12 个业务分组**，组头显示业务名、数量与类型汇总，支持一键全部展开，未识别的键落到「其它 Key」兜底。
*   **沙箱与 K8s 升级运维**：沙箱镜像构建新增 `--pip-index`（默认清华源，解决国内构建机超时或依赖装不齐；仅对 K8s 生效——Docker 镜像 tag 是内容哈希，脚本侧拼参数会造成预构建产物与运行时不匹配）；升级向导候选版本改为按**版本号数值比较**，原实现取字典序末位、实测运行 1.0.16.0 时**默认推荐了 1.0.15.0（一次降级）**，现对低于运行版本的选择增加二次确认。
*   **全站前端基础设施统一**：预置样式把边框宽度与内边距一并归零，而大量老代码只写了边框**颜色**，审计出 **137 个元素有边框颜色无边框宽度、44 个元素缺内边距**；现全局兜底（所用选择器优先级最低，工具类仍可逐个覆盖），搜索框原生清空按钮的右侧留白一并兜底。**Toast** 升级为毛玻璃质感、悬停暂停倒计时、每屏最多 4 条，全平台 **990 处既有调用无需改动**；登录页新增放大镜探索效果与低版本浏览器升级引导。
*   **对话体验与历史治理**：会话历史新增来源 / 智能体 / 状态 / 时间范围筛选，并修复分组模式下关键词与状态只匹配最新一轮、更早轮次的命中会让整个会话被漏掉的缺陷；修复「AI 主动提问」轮在历史里整体消失、提问卡无法重建；新增 `/embed/personal` 第三方嵌入个人中心（复用主站组件，自带凭据门禁——未授权给明确拒绝页，绝不渲染成「还没设密码的普通用户」空壳）。
*   **技能工作台与测试债务**：修复快速切换技能时慢响应覆盖当前内容所致的「显示 A 的内容却保存进 B」；补齐卡片视图键盘打开、新建与上传常显入口（此前只有右键菜单）与 7 个弹层的 dialog 语义；修正契约测试 **52 个长期失败用例**（测试过期 45、辅助脚本从未入库 6、规范断层 1、环境依赖 1），断言条数整体净增。

## 🐛 Bug Fixes

### AI 运行时 / 工具链 / 提示词
*   **沙箱内 Bash 工具 HTTP 500（`No module named 'docstring_parser'`）**：上游把沙箱镜像内 AgentScope 改为 `--no-deps` 安装，而平台在容器内运行内置工具需要 `agentscope.tool` 的完整依赖；已用 Docker / K8s 共用的 `GATEWAY_EXTRA_PIP` 清单补齐 6 个包。
*   **MCP 工具结果被平台侧提前截断**：平台 4000 字符 + 框架 2000 token 双闸门叠加，导致 4000 字符以外内容在任何地方都不再存在，模型「去 sessions 读回完整结果」只会读到别的调用留下的文件；已两层对齐 64Ki。
*   **工具结果上限配置被静默覆盖**：平台把框架默认的 `agentscope_tool_result_limit` 由 50000 覆盖为 2000，闸门过低使中等规模 MCP 结果也被拆分；默认值与 `_int` 兜底已改为 65536。
*   **结构化输出失败无法与基础设施错误区分**：两类失败此前都归入 `"error"`，调用方无从判断该重试还是该换提示词 / 换模型；已新增精确分类（含「父类其它子类不得被误判」的护栏）。
*   **大模型请求超时与看门狗预算持平**：SDK 默认 `read=600s` 与 producer 看门狗 600s 基本持平，上游挂起时业务层重试**实际上没有触发窗口**；已显式设置四类超时并把 `read` 默认压到 180s（可配置 30-300s）。
*   **上下文图片上限依赖上游默认值**：未显式设置，上游日后调整默认值时平台行为会被静默改变；已固化为 5。
*   **元数据解析提示词从未生效**：目标智能体在两个库的种子中均被禁用且此后无迁移重新启用，`get_active_agent_config()` 稳定返回 `None` 落入只有 3 行的兜底分支，详尽版的 8 条要求一条都没在跑；已把兜底确立为正式提示词并补齐要求。
*   **ChatBI 查数底线 3 处指令互相冲突**：分区裁剪会凭空生成过滤条件、`dimension_role=none` 的绝对禁止字面执行等于「没有任何字段可以分组」、静默收窄范围与「禁止停轮」冲突；且行为规则被写进进入向量索引的正文，导致每次调整策略都要全量重建向量索引；已全部收敛到代码层。
*   **行为规则误入向量索引正文的测试断言**：原断言恰好固化了「行为规则应进入 chunk」的错误设计，已改为只断言字段语义进入 chunk。
*   **任务记录 Hash 残留永久无 TTL**：`create_task()` 分两次 `await` 提交 `hset` 与 `expire`，进程在两者之间被杀（`--reload` 很常见）会留下 `TTL=-1` 的残留键，永远不会被清理；已改为 `pipeline()` 原子提交。
*   **向量索引维度变更后静默空转**：索引校验只看存在性，维度不匹配时既不报错也不重建，检索静默失效；已升级为「存在且维度一致」，并让 `FT.DROPINDEX` 默认保留文档数据。
*   **`ToolPermission` 入参区块与「复制工具输出」按钮几何重叠（点击劫持）**：入参区块及其复制按钮位于展开区右上角，而外层按钮以同一 `relative` 容器定位并带 `z-10`——点「复制命令」实际复制的是工具输出，仅有入参时还会渲染一个静默失败的空按钮与空 `pre`；已将输出区块与复制按钮拆为独立容器且仅在有输出时渲染，并加结构契约锁定该布局。

### 元数据 / 数据治理
*   **字段类型改了保存不上（静默失效）**：列更新分支漏写 `type`，而编辑弹窗的字段类型是可改的下拉；改类型保存不报错、刷新即回退。
*   **空字段列表删光全表字段（数据丢失隐患）**：`not_in([])` 被渲染为恒真条件，任何不带 `columns` 的 PUT 都会物理删除该表全部字段元数据；已加非空守卫与 WARNING。
*   **PostgreSQL 主库部署即报错**：`meta_columns` 的维度三列只提供了 MySQL 脚本，而 ORM 已带这三列，PG 主库一部署就 `UndefinedColumn`。
*   **重新导入静默清空人工标注的维度角色（数据损失）**：`model_dump()` 会把 `ColumnSchema` 默认值一并注入，使「保留既有值」的回退逻辑全部失效，走一次智能导入就会抹掉全部人工标注；已改为 `exclude_unset=True`。
*   **清空「序号」输入框导致整张表保存 422**：`v-model.number` 删空时给出空串而非数字，而字段是 `Optional[int]`；已在提交前归一为 `null`。
*   **新维度字段无取值边界**：超长值绕到数据库层才报错，表现为整张表保存 500；已收敛为枚举 + `max_length=100` 并在前端补 `maxlength`。
*   **智能导入数据源回归**：改为「裸数据库类型优先」导致既有契约测试失败，且适配器按数据源名精确匹配、传裸类型会抛 `ValueError` 使关系探测降级；已恢复数据源名优先。
*   **智能导入向导无重名检测**：填入已存在的数据集 ID 时无任何提示、保存按钮照常可点，只能在提交后才失败；已加输入框红色警告与保存按钮联动禁用。

### 知识库
*   **文档列表被静默截断**：未传 `page_size`，后端默认 100 且仅在大于 100 时才自动翻页，文档超过 100 个即被截断且文档数被写成 100。
*   **上传中途切换知识库会把文件传错库**：`uploadDocument` 在循环内重复读取 `selectedDatasetId`，且上传期间左侧树仍可点击。
*   **失败被伪装成成功 / 空数据 / 无人授权**：触发解析失败被计入上传成功数；权限读取失败显示为「未分配额外的用户或角色访问权限」（并静默吞掉删除确认框的授权风险警告）；文档列表与分块加载失败分别显示为「暂无文档」「暂无切片数据」且无重试入口。
*   **双击创建两个同名知识库**：创建知识库无提交锁；取消授权与删除文件夹同样缺 in-flight 锁。
*   **文档列表与分块请求竞态**：并发请求相互覆盖、loading 被先返回的请求提前关闭；快速切换文档会串台、翻页失败时页码前进而内容不变；组件卸载后在途轮询重新挂上定时器。
*   **按钮权限判定不一致**：文件夹重命名 / 删除、文档移动缺 `element:knowledge:edit`，「重新解析」缺 `element:knowledge:parse_document`，点击只得 403。
*   **召回测试页 XSS 风险**：`v-html` 直接渲染分块原文且 `highlightContent` 不做任何 HTML 转义，文档内容里的脚本或事件属性会在页面上执行；已按白名单清洗。
*   **召回测试页错误归因错误**：参数校验把 Python `repr` 放在 `detail`，用户看到的是 `[{'type': 'greater_than_equal', ...}]`；错误框标题硬编码为「RAGFlow 暂时不可用」，403 / 400 都被当成 RAGFlow 故障。
*   **召回测试「失败伪装成 0 命中」**：对照模式失败时仍渲染「A组/B组暂无召回数据」；单模式下「检索完成但 0 命中」与「尚未检索」提示相同。
*   **召回测试无法取消检索**：单次检索最坏约 40s 且按钮被锁死，用户只能刷新整页；组件卸载后还会在别的页面弹出「检索完成」。
*   **召回测试移动端不可用**：侧栏固定 380px 且全页无断点，360px 视口下结果面板被压到 0 宽，外层又是 `overflow-x-hidden`。
*   **运营看板必须先刷两次才看到最新数据**：Redis→DB 归并在后台任务中执行，本次响应读到的是归并前的旧值。
*   **运营看板检索量被重复累加 / 引用率被系统性压低**：执行器自动预取本身就是调用检索工具，runner 侧再记一次；引用量埋点又被放在事实一致性网关门控之后（只有回答通过网关才记引用），导致「有检索、零引用」甚至引用率恒为 0。
*   **运营看板引用编号错位**：工具每次调用都从 1 重新编号，一轮内多次检索会让模型看到重复 `[ID:n]`，引用被错配到错误文档；已改为整轮唯一编号。
*   **运营看板向普通用户暴露全平台数据**：`/metrics/summary` 原先只校验登录，未做管理员权限判定。
*   **文档详情 `v-else-if` 编译错误**：新增按钮容器后 `v-else-if` 不再与 `v-if` 相邻。
*   **门户抽屉与流程横幅 11 种无效色阶**：Tailwind 3 未定义的色阶类经编译产物核实不生成任何 CSS，导致浅色模式 Tooltip 失去背景、竖分隔线消失、暗色模式多处缺底色与边框；`h-4.5` 渲染偏差、`bg-green-955` 笔误、`shadow-2xs` / `backdrop-blur-xs` 系 v4 类名。

### 智能体 / 门户 / 权限
*   **知识库类型智能体无法被委派**：委派就绪判定从「发布版本对象」上取 `capabilities` / `engine_config`，而该表根本没有这两列，`getattr` 兜底恒为 `{}` 使 `dataset_ids` 永远为空——任何 LOCAL + KNOWLEDGE_BASE 智能体无论怎样配置都判未就绪；且判定比运行时更严（运行时未绑定时会回退系统级默认数据集）。
*   **复制智能体弹窗无标识符预检**：手写裸 `input` 未接入名称预检设施，填入已存在的标识符时既无内联提示、「确认复制」也照常可点，只能提交后拿到后端 400。
*   **预检仅失焦触发会漏检**：用户填完名字直接点按钮不会触发 `blur`，看起来像「没检测」；已补输入期 400ms 防抖预检。
*   **改智能体名撞唯一索引抛 500**：`update_agent` 改名前未做唯一性校验，原先会抛 `IntegrityError`。
*   **部分预设 AI 头像点击报 422**：内置 SVG data URI 长达 2197 字符，超过后端 avatar 字段 `max_length=2048`。
*   **AI 头像「旧页面倒灌」覆盖企业形象**：本地缓存与服务端偏好中的陈旧头像会覆盖全员权威形象；已用显式编辑闸门 + 乐观并发 409 护栏 + 拔除本地缓存 + 动态时间戳文件名（消除 HTTP 强缓存）四层治理。
*   **找不到智能体头像设置入口**：完整控件原先只放在版本抽屉的「智能体信息」步骤，而该步骤仅在新建时存在。
*   **待绑定头像被 TTL 回收**：`pending_` 前缀文件未被转正即被清理；三处写入点已接入 `adopt_pending_avatar`。
*   **角色成员徽标人数与列表条数对不上**：用户列表一次性拉取 `size=1000`，超过 1000 时候选池被静默截断，已选成员详情又从被截断的候选池反查（实测默认角色 6 名成员只渲染出 2 名）。
*   **搜索图标渲染为 0×0 / 蓝色竖线消失**：`h-4.5`、`border-l-3` 等无效 Tailwind 类不产生 CSS。
*   **用户批量禁用可能把自己也禁用**：批量接口现自动跳过当前登录账号并回报 `skipped_self`，不中断整批。
*   **复制智能体后副本沉到列表末尾**：`sort_order` 改为取源 +1 让副本紧邻源。

### 沙箱 / K8s 运维
*   **K8s 升级向导默认推荐一次降级**：候选识别把「任意非当前 Tag」都当作新版本，最终取字典序末位；实测运行 1.0.16.0 时默认值被推荐为 1.0.15.0。
*   **带端口仓库的镜像 Tag 解析错误**：`awk -F: '{print $2}'` 对 `registry.example.com:5000/...:1.0.16.0` 会切出 `5000/nanzi/nanzi-ai-agent`，导致「当前运行中」判定与版本比较全部失效。
*   **升级向导基准取错**：原先只以 `kustomization.yaml` 为基准，二次执行（平台仍在运行）时会拿本地文件版本与节点镜像比较；已改为优先以集群实际运行镜像为基准。
*   **升级与安装两处探测逻辑重复**：改一处必漏一处；已合并为单一入口 `probe_nanzi_images`。
*   **沙箱构建缺 pip 源**：Docker 与 K8s 沙箱都没配置 pip 源，国内构建机直连 PyPI 经常超时或依赖装不齐；现有 `--proxy` 只覆盖「安装 uv」那一步 `curl`。
*   **`--pip-index` 值直接展开进 Dockerfile**：会带来命令注入面；已加白名单校验并单独拦截换行。
*   **SSH 沙箱缺少环境提示**：密码认证依赖 `sshpass`，但未安装时用户只看到 502 报错；已补动态探测与双重解决指引。
*   **私钥被脱敏掩码覆盖**：服务端回显的脱敏占位符可能被当作新值写回；已增加掩码防覆盖机制，并自动解析转义换行符与单行私钥解决 OpenSSH `invalid format`。

### 前端交互 / 视觉 / 测试基础设施
*   **输入框「看起来不像输入框」**：Tailwind preflight 归零边框宽度与内边距，而大量老代码只写了边框颜色；审计出 137 个元素有边框颜色无边框宽度、44 个元素缺内边距。
*   **系统配置页两套底色 / 输入框高度不一致**：同页品牌个性化字段是白底、参数配置与日志字段是灰底；渲染实测 20px vs 38px。
*   **`readonly:bg-gray-100` 静默失效**：Tailwind 正确写法是 `read-only:`，原写法编译产出 0 条规则等于没写。
*   **搜索框原生清空按钮与文字拥挤**：64 个 `type="search"` 中 52 处右侧留白仅 8～12px，而按钮约需 28px。
*   **召回测试等页面快捷键与焦点约定不统一**：已补 `Ctrl+Enter`、`role="alert"`、`aria-live` 与焦点环。
*   **网页预览 / 时间线细节**：`EmbedChat` 深色模式一片白雾（`:global()` 破坏 scoped 作用域，9 条全局规则全部编译错误并误伤根容器）、表格偶数行白底浅字、ECharts 深色下是一块白板；时间线标题里两个口径不同的耗时并排显示。
*   **宿主初始化遮罩永久糊住挂件**：超时分支只标记状态而从不关闭 `loading`。
*   **嵌入会话切走页面后无法续显（卡死丢内容）**：执行任务时切到平台其它页面再切回会卡死、已输出的思考丢失且不再实时推进；现新增会话事件日志 `nanzi:conv_stream:{uid}:{cid}` 与增量拉取端点 `GET /conversation/{id}/stream-events`，前端按日志整体重建（不叠加、不吞掉切走期间的新产出）并增量续显，过程日志只作可视化旁路、终态仍以历史落库为准。
*   **输出完成后首次点快捷按钮被静默吞掉**：发送守卫在「运行中」标记未清时直接 `return`、零用户反馈，而该标记只靠流式终态事件释放、丢失后仅靠 1.5 秒轮询收敛；现点击即核验后端真相，确实仍忙则排队并在锁释放瞬间自动补发（附超时放弃、有草稿不代发等保护）。
*   **`tests/frontend` 52 个用例长期失败**：其中 6 个调用的测试辅助脚本从未进入版本库（`git log --all` 为空），另有 1 个因缺少 Pillow 以收集错误形式中断整套测试；已按成因分类修复并让断言条数净增。
*   **`test_system_config_group_collapse_contract` 断言范围过宽**：原扫描整个文件，会被诊断页后续新增的 Redis 分组按钮误伤；已收窄到「参数配置」tab 作用域。

## 🗄️ Database Migrations (表结构与配置变更清单)

本次版本包含 **3 组双数据库（MySQL / PostgreSQL）同步迁移脚本**：

| 版本号 (MySQL / PG) | 变更说明 | 涉及数据表 / 配置项 |
| :--- | :--- | :--- |
| `V158` / `V59` | 记录物理表分区字段与索引字段，供 ChatBI 生成可裁剪、可命中索引的 SQL（**仅新增列，不改动既有数据**） | `meta_tables.partition_fields`、`meta_tables.index_fields` |
| `V159` / `V60` | 为元数据字段增加维度角色与层级组标记，供 ChatBI 下钻分析识别可分组字段与下钻路径（**仅新增列，带默认值 `none`**） | `meta_columns.dimension_role`、`meta_columns.hierarchy_group`、`meta_columns.hierarchy_order` |
| `V160` / `V61` | 新增大模型 HTTP 请求读取超时配置（默认 180 秒，范围 30-300）。采用「已存在则更新」写法（MySQL `ON DUPLICATE KEY UPDATE` / PostgreSQL `ON CONFLICT DO UPDATE`）保证可重跑：重跑会纠正分组与描述，但两侧**均不改动 `value`**，避免覆盖运维已调整过的值 | `system_configs` 新增 `llm_request_read_timeout`（分类 `agent`，即「智能体设置」） |

> ⚠️ **PostgreSQL 用户请注意**：`V159` / `V60` 中的 `V60` 是为补齐 PR #197 遗漏的 `meta_columns` 维度三列而新增的——若你曾单独执行过只含 `meta_tables` 的旧 PG 脚本，ORM 已带这三列而表结构没有，**部署后访问元数据会直接 `UndefinedColumn`**，请务必执行 `V60`。

**新增环境变量（`env.example`）**：

本次版本**未新增任何环境变量**，`env.example` 无变更。新增的 `llm_request_read_timeout` 是存放于 `system_configs` 的系统配置项（可在「系统配置 → 智能体设置」分组内以滑块调整），不是环境变量。

**依赖变更（`requirements.txt`）**：

| 变更项 | 变更前 | 变更后 | 说明 |
| :--- | :--- | :--- | :--- |
| `agentscope[service,storage,workspace]` | `>=2.0.6` | `==2.0.9` | 从无上限改为精确锁定，杜绝镜像重建时间不同即装到不同版本；升级前建议先阅读 `docs/md/agentscope_2.0.9_upgrade_guide.md` |

> **升级提示**：启动前请确保执行平台数据库迁移脚本。MySQL 环境执行 `bash db-prod/apply-sql.sh`，PostgreSQL 环境执行 `bash db-prod-pg/apply-sql.sh`（或免 Python 依赖的 `bash db-prod-pg/apply-sql-native.sh`），脚本具备完整的幂等性检查、断点续跑与优雅日志格式化。

## 📖 Upgrade Guide (平滑升级指引)

### ⚠️ 升级前必读

1. **本版本无强制重新登录、无权限码变更**：1.0.16 建立的门户会话令牌化体系（`portal_session` Cookie、`sess_` 不透明令牌）与 API 权限码在本版本中**保持不变**，已登录用户无需重新登录，角色权限也无需重新分配。
2. **Docker 沙箱镜像必须重建（必须执行）**：`requirements.txt` 中 `agentscope` 已锁定为 `==2.0.9`，且沙箱运行时依赖清单由 `K8S_GATEWAY_EXTRA_PIP` 泛化为 Docker / K8s 共用的 `GATEWAY_EXTRA_PIP`（新增 6 个包），两者都参与 Docker 沙箱镜像 tag 的 SHA256 计算，镜像标识已由 `agentscope-workspace:5acc8c3675ac` 变为 `de8514863995`。**若不重建，运行时不会复用旧的预构建镜像（会退化为每次现场构建），而若复用了 2.0.9 下未补齐依赖的旧镜像，Bash 工具会直接返回 `HTTP 500: No module named 'docstring_parser'`。**
3. **手工写入过 `agentscope_tool_result_limit` 的用户需自行调整**：该配置项的默认值与兜底值已由 `2000` 改为 `65536`（单位：token）。仓库内既无该键的迁移种子、也无前端配置页，因此**默认值即为生效值**；但若你曾手工在 `system_configs` 中写入过该键，需自行将其改为 `65536` 后重启服务，否则平台仍会先于框架提前截断工具结果。
4. **会话历史筛选语义变更（对外可见的行为变更）**：分组模式（`group_by_conversation=true`）下，`keyword` 与 `status` 由「仅匹配每个会话的最新一轮」改为「**匹配会话内任意轮次**」。这是缺陷修复而非配置项，不传这两个参数时行为与改动前完全一致。
5. **K8s 升级向导候选版本规则变更**：镜像候选 Tag 改为按**版本号数值比较**，只推荐严格高于当前运行版本的最高版本，纯别名 Tag（如 `latest`）不再参与比较；显式选择低于运行版本的 Tag 会触发二次确认（默认 N）。若你此前的升级脚本依赖旧的「字典序末位」行为，请留意。
6. **依赖升级**：`poetry install --no-root` 会按新的精确版本安装 AgentScope 2.0.9。若本地 `.venv` 仍是 2.0.6/2.0.7，请先重新安装依赖再启动。

1. **拉取最新代码并同步主分支**：
   ```bash
   git fetch origin
   git checkout main
   git pull origin main
   ```

2. **数据库结构平滑升级**：
   ```bash
   # MySQL 用户执行：
   bash db-prod/apply-sql.sh

   # PostgreSQL 用户执行（Python 环境）：
   bash db-prod-pg/apply-sql.sh

   # PostgreSQL 用户执行（免 Python，使用系统 psql）：
   ```
