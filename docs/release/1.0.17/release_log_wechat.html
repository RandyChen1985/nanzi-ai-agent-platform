数据侧交付 Doris 数据源适配器、字段维度角色与下钻层级组，以及物理表分区与索引字段元数据，让 ChatBI 生成的 SQL 可裁剪、可命中索引，并让 AI 能识别可分组字段与下钻链。

平台侧补齐智能体一键复制、物理标识符重名预检、专属头像三层继承、用户批量启停与角色双列穿梭框；同时完成系统配置页与系统诊断页的信息架构重构、K8s 沙箱镜像源与升级向导治理。

⚠️ 升级注意 (Upgrade Notes)

· 本版本无强制重新登录、无权限码变更：1.0.16 建立的门户会话令牌化体系（portal_session Cookie、sess_ 不透明令牌）与 API 权限码保持不变，已登录用户无需重新登录，角色权限也无需重新分配。

· Docker 沙箱镜像必须重建（必须执行）：AgentScope 已锁定 ==2.0.9，且沙箱运行时依赖清单由 K8s 专属泛化为 Docker / K8s 共用的 GATEWAY_EXTRA_PIP（新增 6 个包），两者都参与镜像 tag 的 SHA256 计算，镜像标识已变化。若不重建，Bash 工具会直接返回 HTTP 500: No module named 'docstring_parser'。

· 手工写入过 agentscope_tool_result_limit 需自行调整：默认值与兜底值已由 2000 改为 65536（单位 token）。仓库内既无该键的迁移种子、也无前端配置页，默认值即生效值；若你曾手工写入过该键，请改为 65536 后重启服务。

🚀 核心更新亮点 (Key Features)

1. 🔗 AI 运行时精确锁定与执行时间线全链路可观测

· AI 框架版本不再「悄悄换掉」：以前依赖写的是「不低于某版本」且没有锁文件，镜像哪天重建就装哪天的最新版，本地与线上静默漂移、线上出故障无法复现；现已精确锁定 AgentScope 2.0.9。

· 终于能看到 bash 到底执行了什么命令：命令全程都在数据里、却在三处被丢掉；现在时间线卡片直接展示命令原文、模型写的意图摘要（如「Bash · 前端契约全量回归」）与调用元信息，刷新与历史回放都还在。

· 工具结果不再被两把闸门连截两次：模型明明收到 20 条记录只看得到 7 条，反复说「要去 sessions 读完整结果」却读到别轮内容——根因是平台先截到 4000 字符、框架再按 2000 token 拆分，两道叠加后超出的内容在任何地方都不再存在；现两层统一放宽到 64Ki。模型请求超时也从「与看门狗同时到点、重试来不及执行」改为默认 180 秒且可配置。

简单说：以前「AI 用什么版本」取决于哪天重建的镜像，「AI 看到了什么」取决于两道截断闸门，出了问题只能靠猜；现在版本钉死、过程全程可回溯、结果不再被中途砍掉。

2. 🧠 向量索引维度守卫与重构进度抽屉

· 改了向量维度后检索不再「静默失效」：以前索引检查只看「有没有」，维度对不上时既不报错也不重建；现在校验升级为「存在且维度一致」，不一致自动重建，重建保留已有文档数据、不会因为重建索引而丢记忆，记忆工作台会给出黄色警示与修复引导。

· 重构不再只能去后台看日志：系统配置与记忆工作台的向量重构统一改为右侧进度抽屉，实时展示状态、当前阶段、已完成/总数、进度条、耗时、逐条日志与失败明细，关闭抽屉不会取消后台任务；单条失败不中断整批，重复触发直接返回 409 并说明是谁在占用。

· 修掉「重构被误挡 30 分钟」与「Redis 里残留永久垃圾键」：启动锁与手动锁共用同一个键，导致每次重启后 30 分钟内手动重构都被误挡（现改为短锁 + 续期）；任务状态与过期时间分两次提交，进程若在中间被杀就会留下一个永不过期的 Redis 键（现场实测抓到过），现已改为原子提交。

3. 🏢 Doris 数据源与字段维度下钻元数据

· 新增 Doris 数据源支持：Doris 兼容 MySQL 协议，直接复用既有驱动与适配逻辑，连接测试、表列表、DDL 获取、采样与 SQL 执行全链路打通，前端同步新增选项与图标。

· 让 AI 下钻不再「靠猜」：字段新增维度角色与层级组 + 序号，标记出「哪些字段可以分组」「哪几个字段构成从粗到细的下钻链」；同时记录物理表的分区字段与索引字段，让生成的 SQL 可裁剪、可命中索引。

· 修掉 3 处列保存缺陷：改字段类型保存不上（不报错、刷新即回退）；不带字段列表的保存会把整张表的字段元数据删光（属数据丢失隐患，已加非空守卫）；新的维度字段没有长度与取值校验，超长值会绕到数据库层才报错、表现为整张表保存 500。

· 重新导入不再抹掉人工标注：走一次「智能导入」会把人工标注的维度角色全部清空（默认值被一并注入，使「保留既有值」的逻辑失效）；同时补齐了 PostgreSQL 侧遗漏的维度迁移——否则 PG 主库一部署就会报列不存在。

4. 🤖 智能体一键复制、专属头像与用户权限治理

· 一键复制智能体（含最新已发布版本）：单事务复制元数据与最新已发布版本，副本直接可用、排序紧邻源而不是沉到末尾、字段一律深拷贝；系统智能体也能当模板（复制不改源），无需新增权限点。

· 标识符重名「边输边提醒」：预检接口与创建路径共用同一查询，杜绝「预检说可用、创建却失败」；失焦 + 输入期双时机校验（仅靠失焦会漏：填完名字直接点按钮不触发失焦），撞名时禁用确认按钮，改名撞唯一索引也由 500 变成可读提示。

· 智能体专属头像：三层继承：消息自带 → 智能体专属 → 全局官方形象 → 内置默认，并防止两层兜底互相触发死循环；完整头像控件补进用户真正能打开的新建·编辑弹窗（原先只放在一个仅新建时才存在的步骤里，等于找不到入口）。AI 聊天头像「旧页面倒灌」也做了四层治理。

· 用户批量启用 / 禁用（禁用即踢下线）：表格与移动端卡片支持多选、浮出批量操作条并二次确认；自动跳过当前登录账号、未知 ID 单独计数；提交后按快照逐个失效会话缓存，确保禁用立即生效。

· 角色「分配用户」重构为标准双列穿梭框 + 修掉「能用的智能体不能被委派」：前者修掉「徽标人数 ≠ 列表条数」（候选池被静默截断，实测默认角色 6 名成员只渲染出 2 名），并锁定「全量成员 ID 不受分页影响」的契约；后者根因是就绪判定从一个根本没有对应字段的对象上取值、恒为空，导致「直接选中能用、一委派就说尚未就绪」。

🐛 缺陷修复 (Bug Fixes)

🧠 AI 运行时 / 工具链 / 提示词

· 沙箱内 Bash 工具 HTTP 500：上游把沙箱镜像内 AI 框架改为「不装依赖」安装，而平台在容器内运行内置工具需要完整依赖；已用 Docker / K8s 共用清单补齐 6 个包。

· MCP 工具结果被平台侧提前截断：平台 4000 字符 + 框架 2000 token 双闸门叠加，4000 字符以外内容在任何地方都不复存在；已两层对齐 64Ki，并修掉「框架默认值被平台静默覆盖为 2000」。

· 结构化输出失败无法与基础设施错误区分：两类失败以前都归入同一个错误值，调用方无从判断该重试还是该换提示词 / 换模型；已新增精确分类与误判护栏。

· 模型请求超时与看门狗同时到点：上游卡住时业务层重试实际上没有触发窗口；已将读取超时默认压到 180 秒并做成可配置。

· 元数据解析提示词从未生效：目标智能体在种子数据中被禁用且此后未重新启用，一直落在只有 3 行的兜底分支，详尽版 8 条要求一条都没跑；已把兜底确立为正式提示词。

· ChatBI 查数底线 3 处指令互相冲突：会凭空生成过滤条件、字面执行等于「没有任何字段可以分组」、静默收窄范围与「禁止停轮」冲突；且行为规则被写进向量索引正文，导致每次调整策略都要全量重建索引。已全部收敛到代码层，并把「行为规则只留代码」固化为契约。

· Redis 里残留永不过期的任务键：任务状态与过期时间分两次提交，进程在中间被杀就留下一个永不过期的键（现场实测抓到 TTL=-1 的残留）；已改为原子提交。

· 向量索引维度变更后静默空转：校验只看存在性，维度不匹配时既不报错也不重建，检索静默失效；已升级为「存在且维度一致」，并让删除索引默认保留文档数据。

· 时间线「复制命令」实际复制的是工具输出（点击劫持）：入参区块与复制按钮和外层按钮几何重叠，仅有入参时还会渲染一个静默失败的空按钮；已拆为独立容器并加结构契约锁定。

🏢 元数据 / 数据治理

· 字段类型改了保存不上（静默失效）：更新分支漏写类型字段，而编辑弹窗里字段类型是可改的下拉；保存不报错、刷新即回退。

· 不带字段列表的保存会删光整张表字段（数据丢失隐患）：过滤条件被渲染成恒真，任何不带字段列表的保存都会物理删除该表全部字段元数据；已加非空守卫与告警。

· PostgreSQL 主库部署即报错：字段维度三列只提供了 MySQL 脚本，而 ORM 已带这三列，PG 主库一部署就报列不存在。

· 重新导入静默清空人工标注的维度角色（数据损失）：默认值被一并注入使「保留既有值」全部失效，走一次智能导入就会抹掉全部人工标注；已改为只提交用户真正设置过的字段。

· 清空「序号」输入框导致整张表保存失败：数字输入框删空时给出空串而非数字，与可选整数类型冲突；已在提交前归一。

· 新维度字段无取值边界：超长值绕到数据库层才报错，表现为整张表保存 500；已收敛为枚举 + 长度上限并在前端补校验。

· 智能导入数据源回归：改为「裸数据库类型优先」导致既有契约测试失败，且适配器按数据源名精确匹配、传裸类型会抛异常使关系探测降级；已恢复数据源名优先。

· 智能导入向导无重名检测：填入已存在的数据集 ID 时无任何提示、保存按钮照常可点，只能在提交后才失败；已加红色警告与保存按钮联动禁用。

📚 知识库

· 文档列表被静默截断：未传分页参数，后端默认 100 条，超过即被截断且文档数被写成 100。

· 上传中途切换知识库会把文件传错库：上传循环内重复读取当前选中的知识库，且上传期间左侧树仍可点击。

· 失败被伪装成成功 / 空数据 / 无人授权：解析触发失败被计入上传成功数；权限读取失败显示为「未分配权限」，还静默吞掉删除确认框里的授权风险警告；列表与分块加载失败显示为「暂无数据」且无重试入口。

· 双击创建两个同名知识库 / 请求竞态：创建无提交锁；文档列表与分块请求并发互相覆盖、快速切换串台、翻页失败但页码前进；组件卸载后在途轮询重新挂上定时器。

· 按钮权限判定不一致：文件夹重命名 / 删除、文档移动、重新解析等按钮缺少与同区块一致的权限判定，点击只得 403。

· 召回测试页存在脚本注入风险：分块原文渲染时完全不做 HTML 转义，文档里的脚本或事件属性会在页面上执行；已按白名单清洗。

· 召回测试页错误归因错误 / 失败伪装成 0 命中：参数校验的内部表示直接展示给用户，403 与 400 都被归因为「RAGFlow 不可用」；对照模式失败时仍渲染「暂无召回数据」，单模式下「0 命中」与「尚未检索」提示相同。

· 召回测试无法取消检索：单次最坏约 40 秒且按钮锁死，用户只能刷新整页；组件卸载后还会在别的页面弹出「检索完成」。另修复移动端结果面板被压到 0 宽、无法横滚。

· 运营看板必须先刷两次才看到最新数据：归并在后台任务中执行，本次响应读到的是归并前的旧值。

· 检索量被重复累加、引用率被系统性压低：执行器自动预取本身就是调用检索工具，runner 侧再记一次；引用量埋点又被放在事实一致性网关之后，导致「有检索、零引用」甚至引用率恒为 0。

· 引用编号错位：工具每次调用都从 1 重新编号，一轮内多次检索会让模型看到重复编号，引用被错配到错误文档；已改为整轮唯一编号。

· 运营看板向普通用户暴露全平台数据：指标汇总接口原先只校验登录，未做管理员权限判定。

· 文档详情编译错误：新增按钮容器后条件分支不再相邻，前端直接编译报错。

· 门户抽屉与流程横幅 11 种无效样式类：经编译产物核实这些类不生成任何 CSS，导致浅色模式提示框失去背景、竖分隔线消失、暗色模式多处缺底色与边框，另有尺寸类渲染偏差与笔误色阶。

🤖 智能体 / 门户 / 权限

· 知识库类型智能体无法被委派：就绪判定从「发布版本对象」上取两个字段，而该表根本没有这两列，取值恒为空，任何该类型智能体无论怎样配置都判未就绪——表现为「直接选中能用、一委派就说尚未就绪」；且判定比运行时更严。

· 复制智能体弹窗无标识符预检：手写裸输入框未接入已有名称预检设施，撞名既无内联提示、确认按钮也照常可点，只能提交后拿到 400。另修「仅失焦触发会漏检」（填完名字直接点按钮不触发失焦）。

· 改智能体名撞唯一索引抛 500：改名前未做唯一性校验，原先直接抛数据库异常。

· 部分预设 AI 头像点击报 422：内联图地址长达 2197 字符，超过后端 2048 上限；已改为 public 静态短路径并提前拦截超长地址。

· AI 头像「旧页面倒灌」覆盖企业形象：本地缓存与服务端偏好中的陈旧头像会覆盖全员权威形象；已用显式编辑闸门 + 乐观并发冲突护栏 + 拔除本地缓存 + 动态时间戳文件名（消除浏览器强缓存）四层治理。

· 找不到智能体头像设置入口：完整控件原先只放在一个「仅新建时才存在」的步骤里。

· 待绑定头像被过期清理回收：上传的临时文件未被转正即被清理；三处写入点已接入转正逻辑。

· 角色成员徽标人数与列表条数对不上：用户列表一次性拉取上限 1000，超过时候选池被静默截断，已选成员详情又从被截断的候选池反查（实测默认角色 6 名成员只渲染出 2 名）。

· 搜索图标渲染为 0×0、蓝色竖线消失：无效样式类不产生任何 CSS。

· 用户批量禁用可能把自己也禁用：批量接口现自动跳过当前登录账号并如实回报，不中断整批。

· 复制智能体后副本沉到列表末尾：排序号改为取源 +1，让副本紧邻源。

☸️ 沙箱 / K8s 运维

· K8s 升级向导默认推荐一次降级：候选识别把「任意非当前 Tag」都当作新版本并最终取字典序末位；实测运行 1.0.16.0 时默认值被推荐为 1.0.15.0。现改为按版本号数值比较，只推荐严格更高的最高版本，并对旧版本二次确认。

· 带端口仓库的镜像地址解析错误：按冒号切分会把 registry:5000/...:1.0.16.0 切错，导致「当前运行中」判定与版本比较全部失效；已改为按最后一个冒号切分并兼容 digest。

· 升级向导基准取错：原先以本地配置文件为基准，二次执行时会拿本地文件版本与节点镜像比较；已改为优先以集群实际运行镜像为基准。

· 升级与安装两处探测逻辑重复：改一处必漏一处；已合并为单一入口与共用比较函数（刻意不用 sort -V 以兼容 BusyBox）。

· 沙箱构建缺 pip 源：Docker 与 K8s 沙箱都没配置镜像源，国内构建机直连官方源经常超时或依赖装不齐；现有代理参数只覆盖「安装包管理器」那一步，管不到装依赖。

· 镜像源参数会直接展开进构建文件：存在命令注入面；已加白名单校验并单独拦截换行（按行匹配不会命中空白字符类）。

· SSH 沙箱缺少环境提示：密码认证依赖 sshpass，未安装时用户只看到 502 报错；已补动态探测与双重解决指引，并在测试连接前前置拦截。

· 私钥被脱敏掩码覆盖：服务端回显的脱敏占位符可能被当作新值写回覆盖真实私钥；已加掩码防覆盖机制，并自动解析转义换行符与单行私钥解决 OpenSSH 格式错误。

💻 前端交互 / 视觉 / 测试基础设施

· 输入框「看起来不像输入框」：预置样式归零边框宽度与内边距，而大量老代码只写了边框颜色；审计出 137 个元素有边框颜色无边框宽度、44 个元素缺内边距。

· 系统配置页两套底色、输入框高度不一致：同页品牌个性化字段是白底、参数配置与日志字段是灰底；渲染实测 20px vs 38px。

· 只读态底色类名写错导致静默失效：编译产出 0 条规则等于没写，已更名并覆盖全部只读值字段。

· 搜索框原生清空按钮与文字拥挤：64 个搜索框中 52 处右侧留白仅 8～12px，而按钮约需 28px。

· 宿主初始化遮罩永久糊住挂件：超时分支只标记状态而从不关闭遮罩。

· 嵌入会话切走页面后无法续显（卡死丢内容）：执行任务时切到平台其它页面再切回会卡死、已输出的思考丢失且不再实时推进；现新增会话事件日志与增量拉取端点，切回后按日志整体重建并增量续显，过程日志只作可视化旁路、终态仍以历史落库为准。

· 输出完成后首次点快捷按钮被静默吞掉：发送守卫在「运行中」标记未清时直接返回、零用户反馈，而该标记只靠流式终态事件释放、丢失后只能等 1.5 秒轮询；现点击即核验后端真相，确实仍忙则排队并自动补发。

· 技能工作台「显示 A 的内容却保存进 B」：快速切换技能时慢响应覆盖当前内容并污染作用域标记；另修复未保存内容被静默覆盖、批量上传单个失败中断整批、同一文件重复点击误弹「切换将丢失修改」并真的重载。

· 技能工作台键盘 / 触屏不可达：卡片视图仅支持点击（键盘用户无法进入详情）、新建与上传只有右键菜单入口；已补 dialog 语义、键盘打开与常显入口，并修正 25 处无效样式类。

· 记忆工作台提示框被裁剪：卡片设置了裁剪，而提示框是向下弹出的绝对定位层——裁剪发生在绘制阶段，层级再高也无法逃逸，导致提示框只显示一行且右侧文字被截断。

· 契约测试 52 个用例长期失败：其中 6 个调用的测试辅助脚本从未进入版本库（查遍全部历史为空），一直无法执行；另有 1 个因缺少可选依赖以收集错误形式中断整套测试。已按成因分四类修复（测试过期 45 个、脚本缺失 6 个、规范断层 1 个、环境依赖 1 个），断言条数整体净增，无 assert True / skip / xfail / 注释断言。

· 一处契约断言范围过宽：原扫描整个文件，会被诊断页后续新增的分组按钮误伤；已收窄到「参数配置」作用域。

📖 平滑升级指南 (Upgrade Guide)

遵循以下标准步骤即可平滑无缝升级至 v1.0.17.0。本版本无强制重新登录、无权限码变更，但请务必确认三点：AgentScope 已锁定精确版本需重装依赖、Docker 沙箱镜像必须重建、若曾手工写入过 agentscope_tool_result_limit 需改为 65536。

方式一：源码拉取升级（开发与虚机部署）

# 1. 同步拉取主分支最新代码

git fetch origin && git checkout main && git pull origin main

# 2. 执行数据库结构平滑迁移 (MySQL / PG)

bash db-prod/apply-sql.sh # PG: bash db-prod-pg/apply-sql.sh

# 3. 重装后端依赖（AgentScope 已锁定 ==2.0.9，必须重装）

poetry install --no-root

# 4. 前端构建与启动本地服务

./dev.sh

📌 检查项：本版本 env.example 无变更，无需新增环境变量；若你曾手工在 system_configs 中写入 agentscope_tool_result_limit，请改为 65536 后重启服务。

方式二：Docker 容器化升级（生产环境推荐）

# 1. 执行数据库增量升级 (宿主或临时容器)

bash db-prod/apply-sql.sh # PG: bash db-prod-pg/apply-sql.sh

# 2. 导入官方 Release 镜像归档（x86_64 / ARM64 按架构选择）

docker load -i nanzi-ai-agent_1.0.17.0_linux-amd64_*.tar

docker load -i nanzi-ai-agent_1.0.17.0_linux-arm64_*.tar

# （或在本地自主构建：cd docker && ./build_linux_x86.sh 1.0.17.0）

# 3. 重启容器服务

cd docker && ./start-nanzi-ai-agent.sh

方式三：沙箱构建与运维 CLI（若启用 Docker / K8s 沙箱策略）

# Docker 沙箱：本版本必须重建（依赖清单已变化，旧镜像会让 Bash 工具 500）

bash sandbox/docker/build-docker-sandbox-image.sh

# K8s 沙箱：集群就绪与 RBAC 权限体检

bash k8s_deploy/nanzi-k8s.sh health

# K8s 沙箱：构建沙箱网关镜像（--pip-index 新增，默认已内置清华源）

bash k8s_deploy/build-k8s-sandbox-image.sh --pip-index https://pypi.tuna.tsinghua.edu.cn/simple

# K8s 沙箱：双层探测本地与节点运行时中已就绪的镜像清单

bash k8s_deploy/build-k8s-sandbox-image.sh --list

☸️ 镜像源优先级：--pip-index > 环境变量 PYPI_INDEX_URL > 内置默认清华源；http:// 内网源会自动放行。注意该选项仅对 K8s 沙箱生效——Docker 沙箱镜像标签是内容哈希，脚本侧临时拼参数会造成预构建产物与运行时不匹配。另：K8s 升级向导的候选版本已改为按版本号数值比较，只会推荐严格高于当前运行版本的最高版本，选择旧版本会触发回退二次确认。
