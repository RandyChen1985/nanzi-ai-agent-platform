⚠️ 升级核心须知 (Upgrade Notes)

🚨 必须先做（顺序不能错）

  • 1. 9 组迁移跑完，再启动新代码：MySQL V209 ~ V217、PostgreSQL V109 ~ V117，两套一一对应、不可跳号，覆盖凭据中心五张表与菜单、产物父会话归属、凭据规则匹配、业务分组三列、超时上限、多群通知。新代码会读新增的列与配置，迁移没跑完会直接报错。执行 bash db-prod/apply-sql.sh（MySQL）或 bash db-prod-pg/apply-sql.sh（PostgreSQL），脚本自带进度、断点续跑与结构校验。
  • 2. V211 必须排在 V212 前面：前一个新建一个更严格的槽位唯一索引（多带了「取值方式」），后一个才删掉旧索引。顺序反了会留下「旧索引已删、新索引未建」的空档，此时若有绑定写入，可能插进两条重复的槽位行。跳过后补跑也来得及，但请保持顺序。

⚠️ 升级后行为会变

  • 3. 凭据从「填在配置里」变成「引用一条凭据」：此前 Token、API Key 直接填在 MCP 服务、API 工具请求头、脚本环境变量里，谁打开配置页谁都能看见明文；现在只显示「来自凭据」和凭据名字。已经手填的真实值不会被自动搬走，仍按原样生效；想纳入管理就新建一条凭据再绑上去，绑定优先于手填值。定时任务也不再需要单独勾「允许无人值守使用」——判定完全按它内部那个工具走，历史上勾过的老数据仍能通过校验。
  • 4. 智能体、MCP、技能、数据集、工具都多了一个「业务分组」：它是单值归属，只服务页签与筛选，和已有的「标签」「所属用户组」「归属范围」是三件不同的事。存量数据全部落成「未分组」，不需要回填，不设置也不影响任何既有功能。技能的分组写在技能说明文件里，复制、分享、发布时会跟着一起走。
  • 5. 工具级超时不再是「只能比上层小」：上层（版本级、全局级）从「天花板」变成「默认值」，工具级配多少就生效多少，最多可到 86400 秒。如果某个工具此前因为上层限制被迫配了小值，现在可以直接调大；整轮看门狗上限也从 3600 秒同步放开，否则配了长预算也跑不完。
  • 6. 子代理思考不再进入主会话正文：改为按日志回流、默认折叠。另外委派结果上限从 8000 字符提到 64Ki，此前超长结果会被硬切（明细表断列、结论被砍半），升级后这类结果会完整返回，主智能体的上下文占用也会相应变大。

🔧 视环境处理

  • 7. 通知渠道的「一个渠道一个群」限制解除了：现在可以配多个群并指定默认群。存量配置会自动补一个群名并标记为默认，升级后行为与升级前一致，不需要手工处理；只有定时任务想发到指定群时才需要额外配置。
  • 8. 环境变量模板重排为 9 段，实例可命名：模板按部署顺序重新组织并补齐代码里真实生效但模板缺失的项，同时移除了不生效的旧变量（RAGFlow、模型、外部 SQL 等一律走系统配置页维护，写在环境变量里从来没有生效过）。多实例部署建议给每台机器填实例名，否则「实例」页只能看到主机名。

🚀 核心特性 (Key Features)

01 · 凭据中心：密钥只进不出，谁能用哪条说得清

Token 和 API Key 不再写在配置里，而是引用一条凭据；谁能用、用在哪、什么时候改过，全都有记录。

  • 引用而不是填值：个人的与平台共用的分开管，页面上只显示凭据名字与「来自凭据」，明文只在真正发请求那一瞬间存在。
  • 一次配好，三处自动带上：MCP 服务的认证头与工具入参、API 工具的请求头与地址参数、脚本的环境变量都能引用；而且新建工具时就能先选，不必先存一遍空配置再回来配。
  • 值的来源有三种：固定一条、按规则自动匹配、交给模型在可见候选里挑。规则可以按「谁在用」或「这次调用的入参」精确匹配，匹配不上时可选严格失败、回退同层固定凭据，或者让模型挑。
  • 模型永远看不到密钥：凡声明「值来自凭据」的参数，都会从模型能看到、能填写的参数表里删掉——看不到就不可能编一个出来；远端工具的参数定义保持原样，下次同步不会被覆盖。
  • 用得清、查得到：每个凭据有用量统计与变更记录（谁、什么时候、把什么改成了什么）；写进提示词或日志的值会自动脱敏；凭据失效时给出的是「去哪补、补什么」而不是「未配置」；误停一条共用凭据也能自己启用回来，不必重建。

02 · 业务分组：五类资产用同一套整理方式

智能体、MCP、技能、数据集、工具都能按业务域归组，页签、徽标、筛选一次学全站通用。

  • 同一套交互：新建和编辑时可填，列表页顶部按分组出页签，卡片上有徽标，点徽标即按该分组过滤。
  • 页签顺序与出口固定：「未分组」永远殿后，分组多到放不下时给「更多分组」入口；页签上的数字是「按当前筛选命中的条数」，不会出现各页签相加比总数还多。
  • 分组和标签是两件事：分组是「归谁管」，单值、只服务导航；标签是「有什么属性」，可以多个，还会参与智能体挑选数据集。混用会让同一份数据挂在好几个页签下，也看不到「未分组」。
  • 技能的分组写在技能说明文件里：技能可以被直接编辑、导入压缩包、分享给同事、提交发布，这些动作都在搬运文件；分组写在文件里就天然跟着走，不会搬一次丢一次，也因此不需要任何数据库改动。
  • 侧栏可以收起来了：「我的技能」「我的 MCP」的二级菜单默认收起，把横向空间让给内容；顶部分享入口换成收件箱与纸飞机，一眼分清收到的和发出的。

03 · 工具级运行时参数：慢工具自己定预算

单个工具可以有自己的超时与温度，不用为了一个慢工具把整个版本一起放大。

  • 超时三级覆盖：工具级、版本级、全局级，上层只是默认值。给一个跑十几分钟的报表工具配长超时，其余工具不受影响。
  • 配多少生效多少：不再把超过上层的配置静默截断成上层的值——此前界面填 600 秒、实际按 180 秒跑，用户只觉着「怎么老是超时」。超上层时琥珀色提示但不拦保存，摘要里标出「超上层」。
  • 整轮预算有天花板提示：单工具上限放开后，整轮执行仍有兜底时限，二者不一致时页面会说明，不会出现「工具配了 30 分钟、整轮 60 分钟被杀」的莫名失败。
  • 温度只对用得上的工具开放：目前只有「看图」这类会自己再调一次模型的工具需要它，其余显示「不适用」并说明原因，不再给一个改了也没效果的输入框。
  • 不再提供没有实际作用的选项：工具级的「执行模型」下拉已移除（每个智能体只有一个模型，这个值从来没有下发的地方）。齿轮按「和默认值不同」点亮并带角标，卡片上直接显示「超时 600 秒 · 描述已覆盖」。

04 · 多智能体协作：子代理会提问，思考能分层

委派出去的专家缺条件时会把问题抛回来，你答完它接着上次的进度继续。

  • 子代理可以反问你：选哪个库、哪段时间不再靠猜，问题会直达主会话；你回答后由同一个子代理接着做，不用从头再来。
  • 等待时间不算超时：这条链路是「中断—恢复」而不是「卡住等」，思考几分钟也不消耗委派预算；中途换一个完全不同的问题会开新会话，不会把两件不相干的事拼在一起。
  • 思考过程可以分层看：详细、标准、精简、关闭四档。精简档把多轮思考合并成一行「N 轮 · 合计 X 秒 · 合计字数」，工具调用仍一条条可见，需要细节时再展开看原文。
  • 子代理的思考不再混进正文：它以可折叠的日志形式回流，既看得见它在想什么，又不占主回答的位置，也不会挤掉真正的结论。
  • 专家团成员就地增删：在「专家团设置」里直接改成员，保存时自动生成新版本并发布，其余配置原样保留；名单的三种状态与实际可委派范围严格一致。

05 · 运维可见性：多实例一屏看清，告警能分群

跑了几台、哪台在跑调度、版本一致吗——一个页面回答完，异常状态直接点名。

  • 系统诊断多了「实例」页：一次看清每台机器的版本、是否在跑定时调度、各自的数据库与缓存版本，趋势保留 24 小时。
  • 异常状态直接点名：出现「两台都是主」「一台主都没有」「主节点掉线」时，页面顶部直接告警，不需要逐台核对。
  • 每台机器有自己的名字：节点标识优先取你填的实例名，重启回来仍认得；取了别名的机器不会因为短暂掉线就丢失身份。
  • 通知能分群了：钉钉、飞书、企业微信每个渠道都可以配多个群并指定默认群，定时任务可按渠道指定发到哪个群；指定的群不存在时，对话场景宁可不发也不发错群，定时任务降级发默认群并记录原因。
  • 环境变量模板能照着填了：按部署顺序重排成 9 段并补齐缺失的可调项，同时删掉那些写了也不生效的旧变量——此前照着模板配一堆、实际全靠系统配置页。

06 · 界面与终端：一屏放下，一点就中

窄屏不再是「能用就行」：页签能滑、筛选收成一行、详情能返回。

  • 审计日志能滚动了：此前窄屏下筛选条件摊成五行、加上统计卡片比一屏还高，下面的列表被压成零高度，看起来像「页面坏了」。现在筛选收成一行「搜索 + 筛选 + 刷新」，条件收进展开区。

  • 用户模式的菜单不再被截断：菜单区和会话列表改为按内容分配高度，展开「更多」时整组可见、会话列表整体下移，不会再出现「看起来只有这么多」而漏看最后几项。
  • 弹层不再先缩再撑：「我的资源」这类分页签的弹层改为固定尺寸，切换页签时不会先缩成一条再被撑大。

🐛 问题修复 (Bug Fixes)

⏰ 调度、定时任务与 Cron

· 定时任务要再勾一次才承认凭据：此前无人值守调用必须额外勾「允许定时任务使用」，用户刚在对话里验证过能用、到定时任务里却不生效，界面上也看不出差别。现在定时任务只是「谁在跑」，判定完全按它内部那个工具走，与手动调用一致。

· 告警和日报只能挤进同一个群：一个渠道只能配一个群是数据库唯一键钉死的。现在可以配多个群并指定默认群；指定的群被删或停用时，对话里宁可不发，定时任务降级发默认群并写明原因。

· 迁移脚本被一段注释卡住：脚本按分号切语句却不识别注释，SQL 注释里举例写的一段符号被当成语句分隔，后半段被当 SQL 发给数据库并报错。现在按注释内的分号与引号正确处理，重复执行也不再受历史注释影响。

💬 会话、时间线与交互

· 「绑了凭据却没生效」：MCP 认证头的绑定此前遍历的是服务配置里的头、还跳过「值非空」的项，连绑定表都没查——配过静态值的头绑了也永远不生效，使用记录里一条都没有；而绑定后值输入框被隐藏，用户也没法自己清掉旧值，等于死锁。现在以绑定表为准。

· 会话跨用户串号、时间差 8 小时：真机验收发现的三个问题，都是「界面显示配好了、实际不是那么回事」。已逐条修正，时间统一按本地时区呈现。

· 选了别的模型，执行卡片仍显示版本配置的模型：实际请求一直是对的，是记录与展示各自去读了版本配置、没走会话里真正的覆盖值。现在模型口径收敛成一处：工具级、已记录的真实模型、会话覆盖、版本配置、全局默认依次取。

· 「变更记录」弹框一片空白：系统级凭据的变更记录读不到内容，管理员看不到谁改过。现在能正常列出，并看清「谁、什么时候、做了什么」。

· 参数设置弹窗把已配好的规则显示成「固定凭据 · 未选」：首次打开时状态没有回填，看着像配置丢了。现在打开即所见，试算与真实调用共用同一段判断，不会再出现「试算能命中、真调用没命中」。

· 子代理的思考会挤掉结论：委派流把思考内容也完整带回，遇到长度上限时先被截掉的反而是结论。现在思考与结果分开处理。

· 并行委派的容器对不上号：历史回放时几个并行子代理会被并成一张卡片，编号与位置错位。现在按批次精确归位。

🔐 平台、权限与登录

· 页签行消失后卡死：在「未分组」里把最后一条归组后，页签行连同开关一起消失，而筛选还停在原分组，于是列表空白且没有退回「全部」的入口，只能刷新。现在页签行消失时自动回到「全部」。

· 分组名可以是空白：数据集的分组名少了另外几处都有的规整处理，填几个空格会落成一个看不见的空分组，超长则直接报错。现在统一去空白、超长截断。

· 管理员在用户模式下改配置要绕两步：「更多」里补上了系统设置入口（仅管理员可见，且要同时满足角色与权限才显示）。

· 实例相关接口的权限口径不一致：部分接口只校验了角色、没校验权限项，现已对齐。

· 更新日志在开发环境看不到：此前被环境判断直接隐藏，现回退到 Releases 列表页，关于面板里也补了直链。

🛠️ 工具、沙箱与嵌入

· RAGFlow 1.0 下「参与检索」保存报错、删切片返回 405：上游同时改了四处接口约定——文档更新方法变了、启停从布尔改成整数、列表不再回传启停状态、删除切片的路由根本不存在（任何发行版都没有）。现在按上游源码逐条对齐，老版本走兼容分支。

· 建库时一个字段被拒就整个失败：上游对字段的接受程度与版本有关，此前一个字段被拒会让整个建库流程失败。现在按被拒字段分级降级，能建的先建起来并明确说明少了什么。

· 委派结果在 8000 字符处被硬切：明细表断列、多段落结论被砍掉一半，调用方只能重新委派一次。现在与普通工具结果同一口径，超出部分交给下游的截断与压缩处理。

· 凭据中心工具栏在手机上把中文按钮压成竖排：窄屏下按钮被 flex 压扁，文字一个字一行。已修正，同类问题在多个页面一并排查。

· 历史消息的渲染与对话不一致：历史记录页用的是另一套渲染，代码块、图片、表格显示与对话里不同。现在统一。
