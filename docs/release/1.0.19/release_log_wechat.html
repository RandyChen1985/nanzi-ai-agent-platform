⚠️ 升级核心须知 (Upgrade Notes)

  • 数据库迁移必跑：新增 8 组数据库迁移（MySQL V165 ~ V172 / PostgreSQL V66 ~ V73），涉及 API 工具业务分组、版本模型锁、权限表字段扩列、智能体级权限作用域、沙箱孤儿对账配置、微信小程序绑定表、微端角色与开关、会话生产看门狗超时配置。
  • 沙箱孤儿对账说明：新增 sandbox_orphan_reconcile 开关（默认开启），适用于单副本环境自动回收超 30 分钟无主遗留容器/Pod；多副本集群部署必须关闭，以防副本间误判互删。
  • 微信小程序端点接入：如需开启小程序微端，请在系统配置中开启 miniprogram_enabled，并在后台「角色管理」为 miniprogram_user 角色勾选允许访问的智能体。
  • 权限缓存平滑更新：修改禁用资源权限后将自动增量失效本地权限缓存，无须像旧版本一样强制注销用户会话。

🚀 核心特性 (Key Features)

01 · 智能体级细粒度资源限定与防御加固

告别“一刀切”的粗放授权，构建严密的维度排除矩阵：

  • 智能体级排除机制：在既有全局禁用的基础上，支持「用户/角色 × 特定智能体」的作用域组合。管理员可精准限定某个角色仅在指定智能体内禁用特定工具（系统工具、API 工具、MCP 工具）或公共技能，未配置则全局兜底生效。
  • 「禁用资源」管理端全面升级：整合系统工具、API 工具、MCP 工具及公共技能四页签结构；分组卡片引入黑名单高亮（有黑名单项即红色提示），一眼定位被拉黑分组；弹窗增加候选来源版本解析与分条高亮说明。
  • 底层命令与技能安全加固：统一沙箱 MCP shell 与交互终端命令禁用的单一策略源，彻底封堵只读绕过旁路；权限表资源字段扩宽至 255 字符，根除 422 报错；被禁公共技能在技能入口直观置灰只读并标明原因。
  • 模型切换权限管控：版本配置新增「允许在输入框手动切换模型」开关，关闭后彻底隐藏切换入口；支持角色/用户级「模型白名单」；模型下拉框支持快速实时搜索。

02 · 微信小程序微端生态与移动端体验进阶

端到端打通移动场景与微信生态，体验如原生 App 般丝滑：

  • 小程序无感静默开户：提供开箱即用的小程序微端集成方案，基于微信 wx.login 实现静默鉴权与自动开户；新增身份绑定表保证唯一性并支持 unionid 跨应用关联。
  • 微端角色安全隔离：预置 miniprogram_user 角色种子与功能开关，智能体可见性基于白名单安全隔离，未勾选默认不可见。
  • 移动端头部收纳与紧凑弹层：移动端顶部菜单重构为紧凑弹层，无缝融入个人中心；个人中心返回浮标支持触摸拖动手势定位与边缘方向感知收起。
  • 统一底部操作抽屉：移动端聊天界面重排操作栏，外露「数据调用统计」与「上传附件」快捷入口，四组功能分组呈现，点击动作后自动平滑收起。

03 · 沙箱架构韧性、技能生命周期与孤儿自动对账

深入容器运行底座，全面攻克容器残留与技能模板一致性：

  • 沙箱孤儿后台自动对账：新增系统配置 sandbox_orphan_reconcile，后台定时扫描 Docker 容器与 K8s Pod 标签，自动回收脱离注册表且超 30 分钟的遗留沙箱，根治 sleep infinity 容器泄漏。
  • 技能沙箱 .seed 模板隔离：会话技能快照统一收敛至平台维护的 .seed 隐藏目录，彻底消除硬编码死路径；公共技能变更后基于指纹自动重建模板；个人技能源目录只读挂载防篡改。
  • K8s 与 Docker 环境同构对齐：对齐 K8s 沙箱技能挂载路径与口径，补齐技能集合令牌透传与心跳守护；沙箱空闲回收时长与后端回收器统一同源，UI 浮标不再硬编码。
  • 解压防爆包与覆写安全护栏：技能压缩包解压强制校验总大小与文件数上限；打通个人技能创建覆写、审核预览与导出改名全流程。

04 · 高并发多会话防串台、运行态看板与死锁自愈

  • 多会话隔离防串台：聊天端全面实现多角色会话自隔离，用户切换登录不再串台，审计改走独立端点；调试页会话指针严格绑定会话归属人。
  • 「进行中的会话」看板与强制复位：EmbedChat 顶部新增进行中会话面板与数量徽标，实时识别进行中与疑似僵死任务，支持一键切换与强制终止；历史会话点击当前会话不再重复重载，消灭在途内容冻结。
  • 看门狗硬超时系统配置化：新增 agent_chat_producer_hard_timeout_seconds 配置（默认 600 秒），消除整轮超时与单工具超时的隐式冲突。
  • 会话交互体验进化：历史面板引入全新引导式空状态组件；空会话直接新建免弹确认框；新建会话自动中止在途生成并释放会话锁；上下文浮标在生成中保持可点击。

05 · API 工具向导模式、分组治理与 Schema 净化

  • 添加工具「向导模式」：支持直接粘贴 cURL 命令行，系统自动解析 URL、方法、Header 及参数生成标准 Schema，支持在线填参“先试跑”，联调成功一键入库。
  • API 工具业务分组治理：数据库新增 group_name 字段，智能体编排「工具能力」步骤支持分组视图、批量展开/折叠与分组治理入口，告别所有自定义工具堆积在「其他扩展」的混乱。
  • 参数可视化编辑与坏 Schema 净化：参数定义支持可视化表格编辑；Schema 净化器自动补齐根层 required 字段，修复坏 Schema 废掉整个大模型请求的问题。
  • MCP 编辑态凭据复用与 SSE 状态防护：编辑 MCP 工具连接测试时自动复用已保存凭据（地址变更才重输）；SSE 握手成功前不提前发布会话。

🐛 重点缺陷修复 (Bug Fixes)

🧠 AI 编排 / 权限 / 运行时

· MCP 工具调用名口径不一致：统一全链路 MCP 工具调用名称解析，修复「未在本智能体注册」误拦截。

· 工具坏 Schema 废掉整轮请求：增加 Schema 自动净化器，自动补齐根层 required 并聚合警告日志。

· 模型调用失败无原始错误记录：补全非 2xx 与流式中断时的原始错误留痕，便于精准排查供应商故障。

· 跨用例 Redis 事件循环泄漏：修复 runtime 与 executors 合跑时跨 event loop 导致的连接污染。

· RAG 引用详情刷新丢失：知识库引用详情写入 Redis 旁路存储，刷新后仍可展开。

· 委派场景引用信息丢失：修复委派场景下引用详情被过滤白名单误丢的问题，双路径补全 citation 转发。

⚡ 会话并发 / 隔离 / 稳定性

· 跨用户登录会话串台：聊天端全面实现多角色会话自隔离，管理员审计走独立端点，杜绝会话混用。

· 多会话切换导致死锁与冻结：重构会话切换与响应信封判定状态机，点击当前历史会话不再重复重载，修复在途内容冻结。

· 新会话输入框被旧生成锁定：新建会话时主动停掉在途流式任务并释放会话锁，免去确认弹窗即刻进入输入态。

· 看门狗与单工具超时隐式冲突：将 producer 硬超时看门狗外化为系统配置，并消除二次范围判定的边界缺陷。

📦 沙箱环境 / 技能系统

· 沙箱孤儿僵死容器累积：实现容器/Pod 标签后台对账回收，自动清理脱离注册表的孤儿沙箱。

· 沙箱技能硬编码路径失效：重构为平台维护的 .seed 快照目录，公共技能变更后基于指纹自动重建模板。

· K8s 沙箱配置与 Docker 脱节：拉平 K8s 技能集合令牌传递、挂载路径与执行期心跳守护。

· 技能解压风险防御：解压流程强制校验总文件大小上限与文件数上限，防御恶意解压炸弹。

💻 前端交互 / 弹层 / 图表

· 全站 27 处弹层遮罩受局部容器限制：收敛 6 处 overlay 与 21 处原生弹窗，统一 Teleport 挂载到 body 铺满视口。

· ECharts 窄容器底部图例遮挡 X 轴：默认启用滚动图例，校准 legend.top="bottom" 布局判定。

· 雪花 ID 精度在前端丢失：用户扩展数据字段中的长整型与雪花 ID 统一序列化为字符串处理。

· 内嵌网页预览被名单误拦截：内嵌可行性改为由服务端实测 HTTP 响应头判定，放行正常页面。

📖 平滑升级指南 (Upgrade Guide)

遵循以下标准步骤即可平滑无缝升级至 v1.0.19.0。请务必注意：本版本新增 8 组数据库迁移必须执行。

方式一：源码拉取升级（开发与虚机部署）

# 1. 同步拉取主分支最新代码

git fetch origin && git checkout main && git pull origin main

# 2. 执行数据库结构平滑迁移 (MySQL / PG)

bash db-prod/apply-sql.sh # PG: bash db-prod-pg/apply-sql.sh

# 3. 更新依赖环境并启动本地服务

poetry install --no-root && ./dev.sh

方式二：Docker 容器化升级（生产环境推荐）

# 1. 执行数据库增量升级 (宿主或临时容器)

bash db-prod/apply-sql.sh # PG: bash db-prod-pg/apply-sql.sh

# 2. 导入官方 Release 镜像归档（x86_64 / ARM64 按架构选择）

docker load -i nanzi-ai-agent_1.0.19.0_linux-amd64_*.tar

docker load -i nanzi-ai-agent_1.0.19.0_linux-arm64_*.tar

# 3. 重启容器服务

cd docker && ./start-nanzi-ai-agent.sh

方式三：沙箱构建与运维 CLI（若启用沙箱）

# Docker 沙箱：环境预检与镜像构建

bash sandbox/docker/build-docker-sandbox-image.sh

# K8s 沙箱：集群就绪与 RBAC 权限健康检查

bash k8s_deploy/nanzi-k8s.sh health
