NanZi 开源智能体平台正式发布 v1.0.16.0 版本！这是一次以身份凭据体系重构、会话可吊销与审计脱敏、嵌入凭据实例级隔离、数据集质量治理与元数据漂移 AI 语义治理、K8s 沙箱零配置共享工作区为核心驱动，并全面推进登录防暴破锁定、安全响应头、上下文 token 口径统一与 Prompt Cache 指标归一化的重量级安全与治理版本。

平台完成了自建库以来最彻底的一次身份凭据体系重构：登录后浏览器只持有不可猜测、可即时吊销的不透明会话令牌 sess_<random>，真实 API Key 不再出现在任何一种响应体、localStorage 或前端注入代码中；同时为 API Key 引入 nzi_ 可辨识前缀，让凭据在日志与抓包中一眼可辨。

在数据治理领域，推出数据集质量治理分（类型一致性 30 + 结构覆盖 25 + 备注完备度 25 + 表完整性 20）与元数据漂移 AI 语义治理闭环；在沙箱与运维侧，Kubernetes 沙箱实现零配置自动探测并共享平台数据卷，双库迁移脚本升级为带交互式确认、断点续跑与原生客户端模式的工程化工具链。

⚠️ 破坏性变更提示 (Breaking Changes)

· 门户会话 Cookie 更名，需重新登录一次：Cookie 由 admin_token 正式更名为 portal_session，遵循「只认新名、不加兼容分支」的既定迁移风格——升级后所有已登录用户需重新登录一次。

· 代客签发嵌入凭证权限码变更，需管理员重新授权：「代他人签发嵌入凭证」由借用「获取用户画像」API 权限，改为独立的 API 权限码 POST:/api/v1/embed/tickets，此前依赖旧权限的角色需管理员在后台【角色管理 → 智能体中心】重新分配。

🚀 核心更新亮点 (Key Features)

1. 🔐 门户会话令牌化与凭据全域收敛：浏览器彻底告别长期 API Key

· 不透明会话令牌 sess_<random> 全链路落地：登录成功后由服务端签发可吊销的随机令牌，写入既有 auth:api_key:{sha256(token)} 键空间，令牌落 Redis 哈希（含 user_id / role / status / session_type / verified_at）并设 24 小时 TTL，活跃请求自动滑动续期。

· PORTAL_SESSION_TOKEN_ENABLED 开关（默认开启）：置 false 即恢复旧行为（Cookie 直存真实 Key），仅在 Redis 不可用等异常场景需要；登录下发点统一收敛为 _issue_portal_session_cookie 并以契约测试锁定调用点数量，Redis 不可用时 Fail-Open 回退原凭据。

· 登录响应体不再回传真实 API Key：/auth/login、/auth/sso/login、/auth/login/2fa 三处移除 api_key 字段，凭据只经 HttpOnly Cookie 下发；保留三处按业务必需的显式取 Key 通道并以 6 项源码级契约测试锁定边界。

· API Key 引入 nzi_ 可辨识前缀：随机体仍为 43 字符 / 256 bit，不减熵（总长 43→47）；verify_api_key 不解析格式、只做 SHA256 查库，历史无前缀 Key 继续有效。

· 前端凭据去本地化：移除全局与 19 个文件共 27 处页面内凭据注入，停止写入 localStorage.api_key，新增 userSession.ts 收敛会话清理路径；嵌入场景改由已鉴权用户签发 emb_ses_ 短期令牌，长期 Key 用后即弃。

· 对外文档全量同步：ChatBI HTTP API、嵌入集成指南、FAQ 等活文档统一对齐「Cookie 不承载真实 API Key、登录不回传凭据、外部集成仍走 X-API-Key / Authorization」的凭据形态说明。

· 会话生命周期治理：会话令牌支持按用户成批吊销（auth:user_sessions 索引与 60 秒回源复核双保险），审计日志凭据全链路脱敏，嵌入凭据按实例隔离消除身份串号，票据改为「只读校验通过后再原子核销」。

· 认证韧性加固：登录防暴破 5 次 / 15 分钟锁定、nosniff / CSP / 30 天 HSTS 安全响应头、反向代理自适应 Cookie Secure，代客签发归位专用 API 权限码 POST:/api/v1/embed/tickets。

简单说：以前登录后浏览器里躺着一把「永久钥匙」，现在只发一张 24 小时有效、随时能作废的「门禁卡」——哪怕门禁卡丢了，管理员在后台一按就能成批吊销，真实密钥再也不会出现在前端、日志和抓包里。

2. 🏢 数据集质量治理分体系与元数据漂移 AI 语义治理

· 给每个数据集打「体检分」（0-100）：从字段类型、结构覆盖、备注齐全度、表完整性四维算分，扣分原因可见；列表与卡片展示分数、支持排序，并显示评分时间。

· 不再「读不到就给满分」：以前结构读不出来时问题数为 0，反被判 100 分「优秀」；现在标注「分数基于不完整比对」并挂 ⚠ 提示。

· 新增字段自动补中文名与描述：有注释用注释，没有让 AI 结合真实数据推断，可人工改后一键收录；还能揪出「字段没写备注」并批量补齐。

· 字段类型统一 6 大类，治理动作更「防呆」：类型收敛为字符串 / 整数 / 小数 / 时间 / 布尔 / JSON；不能用「新增字段」处理「整张表已丢失」，批量处置某条出错不连累其他条。

3. ☸️ 沙箱零配置共享工作区与构建运维一体化

· 沙箱里终于能看到完整工作区：以前 K8s 沙箱只看得到一个 sandbox 子目录，看不到会话记录、文档和历史文件；现在改为挂载整个用户工作区，和 Docker 沙箱行为一致。

· 共享工作区改成「零配置」：以前要手工指定命名空间和共享卷，配错不报错、只表现为沙箱里空空的；现在默认自动探测平台数据卷并共享，留空即用，填 none 才强制隔离。存在配错风险时直接告警，不再无声失效。

· 运维脚本不再把平台和沙箱混在一起：沙箱与平台同命名空间后，两边资源会互相混显；现在按标签分开统计，并能直接看到沙箱复用了哪个平台数据卷，排障更快。

· 沙箱构建工具链开箱即用：Docker 与 K8s 构建脚本统一收进 sandbox/ 目录、命名与用法对齐；构建前自动检查环境（没装 CLI、服务没起、权限不足分别给指引），预置镜像内置 git、ping、netstat、dig 等排障工具，构建终端改为彩色分区排版。

· 构建与部署更稳：补丁失败会直接中断构建，避免产出残缺镜像；平台启动时自动创建 docs / skills / branding 三个公共只读目录，避免空存储首次挂载时报「目录不存在」，工作区浏览器也禁止误删这些系统目录。

4. 🗄️ 双数据库迁移脚本工具化：升级更省心、可随时重跑

· 升级脚本会「说话」了：MySQL 与 PostgreSQL 的迁移脚本统一支持查看帮助、指定范围升级、从上次中断处继续；运行时彩色分区打印进度与统计，执行前必须输入 YES 确认防手滑，环境缺依赖时会直接提示怎么装。

· PostgreSQL 多了一条免依赖路径：新增免 Python 的直接执行脚本，用系统自带的 psql 就能升级，适合精简容器与受限环境。

· 可以反复重跑，不怕升级到一半出错：修复了 PostgreSQL 脚本的两处历史问题——一个布尔开关被写成了数字、两处字段添加缺少「已存在就跳过」判断，导致重复执行直接报错；现在随时重跑都安全，并补齐了双库自动化单测。

5. ✨ 对话质量、调试工具与前端体验全面精修

· 中文对话不再被过早压缩：以前中文的 token 估算偏高约一倍，实测纯中文会话在 64k 模型上只用到 35% 就被判超窗、被迫做压缩总结；现在口径与实际对齐，并修掉了「编辑重发后旧的压缩摘要被拼回新对话」「长期不用后计数器重来导致消息被丢」等问题。

· 调试时能看清每一步怎么跑的：新增「执行详情」抽屉，把执行步骤（含完整的工具入参出参）、组装后的完整 Prompt、运行时上下文收在一处；Prompt 支持一键复制、折叠与 token 估算，不用再翻日志。调试页还能直接启停沙箱、打开终端，页面偶发空白的问题一并修掉。

· 界面操作更顺手：内嵌对话顶栏统一改用自定义提示气泡（不再用滞后的原生提示），会话历史侧边栏支持当前会话高亮、搜索防抖、Markdown 导出、按日期分组折叠；模型选择、@ 提及、快捷指令都支持键盘上下选择并自动滚动跟随；AI 回复底部按钮尺寸统一；网页预览在新窗口打开后会自动关闭面板。

· 模型调用统计更准，AI 更少答非所问：补齐了不同厂商（OpenAI / Anthropic / 聚合网关）缓存用量的解析差异，调用明细里能看清「缓存读取」与「未缓存输入」各占多少；同时修掉几处误判——问「你是什么模型」不再被截断，提到 gift、charter 这类日常词不再误触发图片识别，闲聊也不再被强推去检索平台文档，历史表格也不会再被截断丢数据。

· 通知与平台细节更省心：渠道连通性测试消息现在会带上触发人与时间（按平台时区），一眼能认出是谁测的、对不对得上刚点的操作，并且不会把密钥带进消息里；平台还补齐了 FAQ 入口、部署实践技术文与安装文档说明。

🐛 缺陷修复 (Bug Fixes)

🔐 认证 / 会话 / 凭据安全

· 会话令牌无法吊销（高危）：会话令牌以单向哈希存储、无法由用户反查，禁用 / 删号 / 改角色 / 重置密钥后旧会话仍长期可用；现已补上用户维度的会话索引、成批吊销与 60 秒回源复核兜底。

· 审计日志明文落库（高危）：审计脱敏名单漏了会话令牌字段，令牌随响应体明文入库且详情接口原样回显；现已补键名与内容双重脱敏。

· 跨站 iframe 刷新失效（高危回归）：嵌入会话 Cookie 采用 lax 策略，在跨站第三方 iframe 中不会被发送，原先「一旦服务端下发了 Cookie 就清掉地址栏凭据」的做法使刷新后既无地址栏凭据、Cookie 也不发；现改用本标签页的短期令牌作为刷新依据。

· 登出未清理嵌入会话：门户登出后请求会回落到嵌入身份造成身份串号；现在两个 Cookie 都读、都删，并按会话类型走服务端吊销。

· 登录响应体泄露长期密钥 / 内嵌页永久卡加载 / 调试台闪红：三处登录接口不再回传真实密钥；无凭据初始化时非严格模式照常回落同源 Cookie 校验；并区分「等待宿主下发凭据」与「凭据失效」，消除一帧红色遮罩。

· 票据被来源校验白白消耗 / 嵌入令牌并发兑换误报：改为「只读校验通过后再原子核销」，域名白名单没配对方不再白白消耗票据；前端增加并发去重。

· 多实例身份串号 / 用户信息接口名称不符：嵌入凭据的本地存储按实例维度隔离且不回退旧键；「获取用户画像」更正为「获取用户信息」（仅显示名变化，权限不变）。

🏢 元数据 / 巡检 / 数据治理

· 巡检降级误判满分：物理结构读取失败时各类问题数都是 0，反而被判成 100 分「优秀」；现在会标记不可读的表数量与降级状态，并在前端以 ⚠ 提示。

· 质量分入口不一致 / 全库巡检单数据集异常拖垮整轮：单数据集与全库两条路径统一结算；全库巡检对每个数据集独立隔离，异常只计入失败数、不再回滚整轮结果。

· 跨类型误处置 / 批量处置语义矛盾：引入「处置动作与问题类型」的白名单校验；批量处置按条隔离，不再出现「计数已算成功但整批回滚」。

· 采样 SQL 注入面与误杀：4 处采样中 3 处为字符串拼接直通请求体，而唯一的安全校验又过严、会静默跳过中文列名采样；现已统一走安全引用。

· 告警去重吞没 / 物理类型误判：去重条件补上问题类型，避免「类型不匹配」告警吞没「备注缺失」告警；字段类型统一归一化为 6 大类并改用更稳的匹配方式。

· AI 推荐语义弹窗被遮挡 / 数据表卡片按钮藏得过深：弹窗改为挂载到页面根节点并置顶显示；操作按钮移除「悬停才现身」的样式，改为默认常显。

🧠 上下文管理 / 提示词 / AI 工具

· 中文上下文被高估约 2 倍：token 估算口径改为按字节折算，与运行时口径对齐，避免中文会话在 64k 模型上仅用到 35% 就被压缩。

· 手动压缩快照未失效 / 计数器静默后重置：补上快照失效点与版本校验；计数器随状态重置一并续期，不再丢弃新消息。

· 输出预留恒为 0 / 压缩卡片重复与计数翻倍 / 摘要请求自身超窗：统一上下文元数据口径；压缩事件补阶段标记，中间态不再重复发卡；摘要请求加上限并优先保留最近内容。

· 空回复 / 半截话难以排查 / 断轮清理口径不一致：输出上限补 128 的下限并留下显式告警；两套断轮清理逻辑统一为一套。

· 摘录自我抄写：生成压缩摘录时跳过携带压缩标记的系统消息，并修复其识别逻辑取不到值导致漏检的问题。

· 图片识别词边界误伤 / 模型身份询问被误判截断 / 上一轮表格数据丢失：日常词汇不再误触发图片识别；移除当前模型的前置拦截；最近一轮回复的表格保护到 100 行，折叠提示改为外部引用块。

· 执行观测测试偶发失败 / 会话历史路由错位：修正测试基础设施标记误用导致的连接池事件循环错配；会话历史接口的路由装饰器从误挂位置移回，修复 400 错误。

📖 平滑升级指南 (Upgrade Guide)

遵循以下标准步骤即可平滑无缝升级至 v1.0.16.0。升级前请务必确认两条破坏性变更（重新登录一次、重新授权嵌入签发权限码），并确保 Redis 已开启持久化。

方式一：源码拉取升级（开发与虚机部署）

# 1. 同步拉取主分支最新代码

git fetch origin && git checkout main && git pull origin main

# 2. 执行数据库结构平滑迁移 (MySQL / PG)

bash db-prod/apply-sql.sh # PG: bash db-prod-pg/apply-sql.sh

# 3. 前端构建与启动本地服务（本版本 requirements.txt 无新增依赖）

poetry install --no-root && ./dev.sh

📌 环境变量检查：确认 .env 中的 PORTAL_SESSION_TOKEN_ENABLED（建议保持 true）与 ALLOWED_ORIGINS（跨域部署需填实际域名）。

方式二：Docker 容器化升级（生产环境推荐）

# 1. 执行数据库增量升级 (宿主或临时容器)

bash db-prod/apply-sql.sh # PG: bash db-prod-pg/apply-sql.sh

# 2. 导入官方 Release 镜像归档（x86_64 / ARM64 按架构选择）

docker load -i nanzi-ai-agent_1.0.16.0_linux-amd64_*.tar

docker load -i nanzi-ai-agent_1.0.16.0_linux-arm64_*.tar

# （或在本地自主构建：cd docker && ./build_linux_x86.sh 1.0.16.0）

# 3. 重启容器服务

cd docker && ./start-nanzi-ai-agent.sh

方式三：沙箱构建与运维 CLI（若启用 Docker / K8s 沙箱策略）

# Docker 沙箱：环境预检 + 预置镜像构建（含排障工具链）

bash sandbox/docker/build-docker-sandbox-image.sh

# K8s 沙箱：集群就绪与 RBAC 权限体检

bash k8s_deploy/nanzi-k8s.sh health

# K8s 沙箱：构建并核验沙箱网关镜像（--list 双层探测本地与节点运行时）

bash k8s_deploy/build-k8s-sandbox-image.sh --list

☸️ 共享工作区配置建议：sandbox_k8s_existing_pvc 留空即自动探测并共享平台数据卷（推荐零配置）；需要强隔离时填 none，沙箱将使用每工作区独立创建的空 PVC。若沙箱 Pod 随迁移进入平台命名空间，需在该命名空间重新应用 k8s_deploy/sandbox-rbac.example.yaml 授予 Pod / PVC 管理权限。
