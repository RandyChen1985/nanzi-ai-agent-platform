🚀 核心更新亮点 (Key Features)

1. 🏗️ AI 编排责任链管道化重构与工程解耦

  • 6 阶责任链流水线：彻底摒弃单体大函数的流转方式，重构为 PreflightStep → ContextStep → RouteStep → AssembleStep → ExecutionStep → FinalizeStep，职责高度内聚，强类型上下文安全传递。
  • 分布式锁看门狗自动续约：引入后台守护协程，会话执行期间自动给 Redis 锁延期，任务结束即刻释放，根除复杂耗时大任务的锁超时失效与 409 异常。
  • 长推理心跳与终态收敛：深度思考和工具等待期间自动推送 heartbeat，防止 Nginx / 网关切断 SSE 长连接；严格保障流式终态状态机必定收敛，告别前端无限 Loading。
  • 候选正文毫秒直出与首句工作区并发预热：在未确定调工具前首段候选正文毫秒推向前端（TTFT 极大降低）；触发工具时协议级 retraction 平滑转为过程引导；装配阶段异步并行初始化工作区与 Docker 沙箱，冷启动等待归零；修复思考卡片防过早折叠。
  • 多工具并发异步调度：模型单轮次发出的无依赖工具调用由串行累加升级为异步并行执行（asyncio.gather），多源查数与检索耗时锐减 60%+。
  • 事实证据分级门禁：三级置信度判定。工具查询失败或无数据时强约束模型事实防御，禁止胡编乱造，支持全链路多级追溯与元查询。

简单说：原本混在一起的一千多行调度逻辑，现在被拆分成了 6 节清晰标准的车厢流水线。而且有了后台看门狗自动延期锁、首字毫秒直出和多工具并行执行，提问几乎感觉不到等待，长时间思考也不会锁死！

2. 🌐 全功能平台 MCP 服务台与双向生态闭环

  • 平台全面变身标准 MCP Server (入站开放)：Cursor、Claude Desktop、VSCode 或外部自研应用可一键直连 NanZi，调用平台全量 Agent、ChatBI 数据查询、元数据与知识库工具。对外工具名统一规范为下划线风格。
  • 企业级 OAuth 授权与 Scope 版本化：支持生成 Client ID / Secret、自定义 Token 有效期（7天/30天/永久等）；引入 scope_version，权限调整后旧 Token 立即失效，防越权；支持全员共享 Client 协作。
  • 调用第三方 MCP 的用户身份上下文透传 (UserContext Assertion 核心特性)：
    • 破解企业级权限盲区：智能体调用外部企业自研 MCP 服务时，如果仅传固定全局 Token，目标系统无法识别到底是哪位员工在对话，无法实施行级数据权限、部门隔离或操作审计；若放进入参则极易被模型篡改伪造。
    • 双轨分离认证协议：将 Authorization: Bearer（验证平台来源）与 X-Nanzi-User-Assertion（携带经过签名的真实员工上下文）解耦分离，支持独立开关、互不干扰。
    • Ed25519 非对称签名防伪：平台在后端为每个 MCP 独立生成非对称私钥与专属 Audience，私钥高强度加密存储且绝不暴露前端；业务 MCP 仅需读取公钥验证签名。
    • 丰富结构化 Payload：签名载荷包含标准主体 sub、user_context（真实用户 ID、用户名、姓名、部门代码、组织路径）、过滤敏感词后的扩展属性、发起调用的智能体信息，以及防重放攻击的 jti 与 60 秒极短有效期。
    • 公钥发现端点与一键代码生成：对外提供标准 JWKS 端点（/.well-known/nanzi/mcp/{mcp_server_id}/jwks.json）；管理页面提供 Python / Java 一键生成对接中间件示例代码，业务方无需手写验签。
    • 内置 Echo 诊断测试服务：平台提供一键创建 Echo 测试 MCP 实例，实时回显 Bearer Token 与 UserContext 的脱敏验签状态（user_assertion_received=true、user_assertion_valid=true），全链路排查更省心。
  • 出站外调全链路独立审计 (Outbound Audit)：新增独立审计表与服务台「审计日志」Tab，全量监控智能体调用外部 MCP 工具的入参出参、时延（毫秒）与 Trace ID。

简单说：以前智能体调用你们公司的内部系统（MCP 工具），内部系统只知道是 NanZi 发来的，不知道具体是张三还是李四在操作，没法做数据鉴权；现在 NanZi 会用非对称加密把张三的身份和部门签名后一起传过去，内部系统既能精确鉴权，又完全不用担心用户被伪造！

3. 🌡️ 模型级 Temperature 采样温度独立配置

  • 按模型差异化采样 (0.0 ~ 2.0)：在底层 ai_models 表新增 temperature 字段，支持在模型管理页面中为不同模型设置专属温度。
  • 智能体与模型测试优先继承：新建智能体及进行模型接口测试时，优先自动读取并应用该模型的配置温度；未设置时平滑回退至系统全局默认值。
  • 场景精准调优：严谨的 SQL/代码生成类模型可锁定低温度（如 0.1~0.2）追求高确定性，创意思考类模型可适当调高（如 0.7~0.8）激发发散性。
  • 前端指引与类型安全：前端提供温度参考说明与滑块提示，并加固类型索引安全访问。

简单说：不同的模型擅长的场景不同。现在你可以给写代码的模型设置一个低温度保证答案严谨不乱发挥，给写文案的模型设置一个适中温度激发创造力，灵活度大大提升。

4. 🛡️ 平台综合体验、元数据调度与安全防线全面加固

  • EmbedChat 浮标与轻量化：嵌入式聊天组件反幻觉开关默认关闭提供极速响应；输入框内直接集成悬浮状态指示与浮标交互，大幅优化窄屏与移动端排版；正文防刷屏熔断调整为 15 周期。
  • 元数据推荐大表分批生成：支持大表实体关系发现分批生成与诊断日志，修复长响应 JSON 截断，取消死板数量上限；优先数据库物理探测匹配外键与同名索引，大幅节约 AI 调用 Token；新增元数据同步实时日志流与进度条。
  • Cron 表达式容错自愈：底层增加非法 Cron 容错，彻底解决任务调度列表 500 崩溃问题；统一前后端可视化生成器与双向校验规则。
  • 单次超时基线统一：统一全局单次工具调用超时基准为 60s（agent_max_toolcall_timeout），防止无效任务卡死。
  • 文件防重名覆盖与下载签名：统一安全文件名生成机制，彻底修复同名并发上传覆盖冲突；加固生成文件下载链接的时效性签名校验。
  • 前端排版打磨与在线统计修复：统一图标库与类型安全，优化消息底部操作栏，修复移动端 Excel 导出按钮重复显示及在线用户重复计数缺陷。
  • 自动化测试全矩阵覆盖：新增 30+ 组核心自动化测试，同步更新 tests/CHECKLIST.md。

简单说：无论是在网页中嵌入智能体、管理大规模企业数据字典、编排定时任务，还是上传下载业务文件，平台的稳定性和细节体验都得到了系统性的打磨。

🛠️ 极速升级指引 (Upgrade Guide)

方式一：源码拉取升级（开发与虚机部署） 

# 1. 拉取最新代码
git fetch origin && git checkout main && git pull origin main

# 2. 执行数据库增量升级 (自动幂等执行新版本迁移)
./db-prod/apply-sql-native.sh   # PG 执行: ./db-prod-pg/apply-sql.sh

# 3. 启动/重启平台（自动准备依赖环境）
./dev.sh

方式二：Docker 容器化升级（生产环境推荐） 

# 1. 执行数据库增量升级
./db-prod/apply-sql-native.sh

# 2. 导入官方 Release 镜像归档（以 x86_64 为例）
docker load -i nanzi-ai-agent_1.0.14.0_linux-amd64_*.tar

# 3. 重启容器服务
cd docker && ./start-nanzi-ai-agent.sh
