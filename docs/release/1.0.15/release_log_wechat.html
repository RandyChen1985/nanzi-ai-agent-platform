🚀 核心更新亮点 (Key Features)

1. ☸️ Kubernetes 原生 Pod 安全沙箱策略与企业级自动化运维体系

  • Kubernetes 原生安全 Pod 运行时：智能体执行 Bash 命令行任务时，在 Kubernetes 专用命名空间内动态拉起独立 Pod，实现进程、网络、存储及计算资源的强物理边界隔离。
  • 平台 ServiceAccount 绑定最小 RBAC 权限：Kustomize 原生纳管与自动化部署，严格限制 Pod 操作权限，完美适配企业多租户隔离与资源配额（Quota）管控。
  • 对等 kubectl exec 的「进入 Pod」Web 终端：输入框浮标内集成双协议 Web 终端，直连 Kubernetes CoreV1 API 的 WebSocket SPDY 子协议，开发者可一键进入 Pod 内部排查依赖与命令执行。
  • 全流程运维脚本与镜像构建体系：新增 k8s_deploy/nanzi-k8s.sh health 一键体检、重启二次确认与强制杀死命令；k8s_deploy/install.sh 交互意图选择支持 q 安全退出并修复 ANSI 彩色乱码；系统配置页提供预置沙箱镜像一键构建引导弹窗（containerd 与 K3s 双环境一键切换）。

简单说：平台不仅能在宿主机 Docker 跑沙箱，现在还可以直接接入公司的 Kubernetes 集群！智能体每次跑命令都会在 K8s 里面拉起独立 Pod，自带安全 RBAC 和 Web 网页终端，运维还有一键体检脚本，生产部署稳如磐石。

2. ⚡ 沙箱架构革新：按需惰性拉起（Lazy Sandbox）与后台自动预热加载体系

  • 按需惰性沙箱代理机制（Lazy Sandbox）：彻底颠覆打开会话无条件创建沙箱容器的高消耗模式。普通闲聊、知识库检索、查数或使用宿主文件工具（Read/Glob/Grep）时，沙箱绝不拉起，零容器开销；仅在真正调用 Bash 命令行工具时毫秒级按需拉起。
  • 会话打开静默自动预热加载与空闲回收（Auto-Warm & Idle Reclaim）：系统配置新增 sandbox_auto_warm（自动预热开关）与 sandbox_idle_time（空闲回收周期，V153 / V54，Docker 与 K8s 通用）。会话打开或新建后，后台自动发起一次静默预热加载；用户构思打字时容器 / Pod 已经在后台悄然就绪，后续调用 Bash 时直接秒级热态命中，零冷启动等待；超时无人使用时自动销毁回收，兼顾极速体感与算力节约。
  • Bash 卡片节点动态挂载与进度推流：沙箱拉起进度（pending / success / error）通过独立 ID workspace:sandbox:<bash_id> 精准挂载至当前 Bash 卡片下方，避免进度漂移；拉起时推送 Info Toast，就绪后推送 Success Toast 并即时刷新状态。

简单说：不想让服务器白白开着一堆空容器，但又不想等命令执行时冷启动？NanZi 既支持“不调用 Bash 就绝不拉起沙箱”的惰性节约模式，又支持“进会话后台静默预热加载”——你在打字时沙箱就在后台悄悄准备好了，发出去直接秒执行，长时间不用还会自动回收！

3. 🧠 提示词缓存与防编造升级：首字秒级直出、成本狂降 80%~90%、杜绝凭空瞎编

  • ⚡ 首字毫秒级直出，告别漫长转圈等待： 以往多轮对话或复杂智能体任务中，大模型每次都要重复阅读成千上万字的通用规则与工具说明，等待时间较长。新版引入前缀缓存（Prompt Cache）技术，将固定的基础规则提前预热复用，首字响应时间（TTFT）缩短 70% 以上，提问秒响应！
  • 💰 Token 成本暴降 80%~90%，企业调用越聊越省： 全面接入主流大模型（DeepSeek、Claude、GPT-4o 等）的上下文缓存计费优惠。命中缓存的前缀内容计费直降至常规费用的 10%~20%，无论是长任务执行还是企业多人高频使用，累计消耗成本断崖式下降。
  • 🎯 真实结果优先铁律，彻底杜绝张嘴瞎编： 强化系统防编造准则。当询问网址连通性、HTTP 状态码、响应耗时或服务器状态等客观指标时，AI 必须真正调用工具获取真实结果后才能作答；严禁凭空编造“假装成功”的虚假数据，查不到就如实说明，回答真实可信。

简单说：就像去餐厅点餐，大厨把常用的底汤高汤提前熬好备用，不仅上菜快如闪电、账单直接打两折，而且立下了新规矩：绝不缺斤少两、绝不胡说八道，查到的才是真的！

4. 🏢 元数据管理智能体检与自动同步：删表一键下线、改动红绿留痕、查数自动纠错

  • 🔍 数据库定时自动“体检”，删表精准识别与一键下线： 业务数据库常有调整，一旦某张表在后台被删除，AI 查数就会频频报错。新版支持系统后台自动定时体检，精准捕捉“已被删除的失效表”，管理员只需在界面上一键安全下线，同时自动清理关联历史告警，再也不留任何冗余隐患。
  • 🔄 字段类型变动一键智能同步，告别手工重新配置： 数据库字段改了格式或增减了列？系统自动扫描出所有不一致的地方，支持点击【一键同步全部差异】，平台元数据与底层向量知识库自动联动刷新，省去大量人工对表改配置的繁琐工作。
  • 📋 改动全链路红绿对比留痕，操作审计一目了然： 谁在什么时间下线了哪张表、改动了哪个字段、因为什么原因修改，系统均自动生成清晰的红绿色对比记录（就像合同改动标注一样直观），权责清晰，满足企业级审计与安全合规要求。
  • 🛡️ 智能查数更聪明，遇字段过时自动剔除重查： 在 ChatBI 智能取数分析时，若恰好遇到数据库刚刚下线或改名的过时字段，AI 不再直接弹出红色报错让用户不知所措，而是自动识别并剔除失效字段，无感自动重试查出正确结果。

简单说：后台数据库变动了，平台以前“蒙在鼓里”导致查数报错；现在不仅能天天自动体检发现失效表并一键下线，改了字段点一下就能自动同步，查数据遇到废弃字段还能自动纠错把正确答案查出来！

📖 平滑升级指南 (Upgrade Guide)

遵循以下标准步骤即可平滑无缝升级至 v1.0.15.0：

方式一：源码拉取升级（开发与虚机部署）

# 1. 同步拉取主分支最新代码

git checkout main && git pull origin main

# 2. 执行数据库结构平滑迁移 (MySQL / PG)

bash db-prod/apply-sql.sh # PG 执行: bash db-prod-pg/apply-sql.sh

# 3. 启动开发与编译环境

./dev.sh

方式二：Docker 容器化升级（生产环境推荐）

# 1. 执行数据库增量升级 (宿主或临时容器)

bash db-prod/apply-sql.sh # PG: bash db-prod-pg/apply-sql.sh

# 2. 导入官方 Release 镜像归档（以 x86_64 为例）

docker load -i nanzi-ai-agent_1.0.15.0_linux-amd64_*.tar

# （或在本地自主构建镜像：cd docker && ./build_linux_x86.sh 1.0.15.0）

# 3. 重启容器服务

cd docker && ./start-nanzi-ai-agent.sh
