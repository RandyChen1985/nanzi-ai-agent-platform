🚨 必须先做（顺序不能错）

  • 1. 7 组迁移跑完，再启动新代码：MySQL V202 ~ V208、PostgreSQL V102 ~ V108，两套一一对应、不可跳号。新代码会读新增的列与配置，迁移没跑完会直接报错。执行 bash db-prod/apply-sql.sh（MySQL）或 bash db-prod-pg/apply-sql.sh（PostgreSQL），脚本自带进度、断点续跑与结构校验。
  • 2. V205 必须排在 V206 前面：前一个给权限表补一列并回填历史数据，后一个紧接着撤销它对「菜单与功能权限」那批记录的误回填。跳过 V206，平台会把菜单权限当成全员授权——提权级错误，不是显示问题。

⚠️ 升级后行为会变

  • 3. 数据集范围从「只打日志」变成硬拦截：手选与会话固定的范围，此前只记录不生效；现在检索与执行两处真拦截，范围外的表直接拒绝，委派给子智能体也继承同一范围。此前靠「跨数据集补全」查关联表的智能体，升级后会看到拒绝提示——请把这些数据集一并授权，这是设计使然。
  • 4. 知识库不再直接收图片：改为「多模态模型读成 Markdown → 用户确认 → 入库」。升级前请确认「系统设置 → 模型服务」配了可用的多模态模型；原图不再放在可直接访问的静态目录，只能通过带鉴权的接口读取，外部直接引用过旧图片地址会失效。
  • 5. 委派只剩一个开关：「子智能体批量调用」并入「子智能体调用」，勾一次两者都开；历史只配了批量开关的名单会在保存时自动合并清理，不用手工迁数据。委派上限改为系统设置可调（批量任务默认 4、单专家每轮默认 2），改完即时生效。
  • 6. 主助手不能再当团主，也不能被委派：存量白名单里的主助手保存时自动剔除。这条是故意的——主助手是兜底入口，被当成专家会出现「专家把问题丢回给兜底」的循环，且它被委派进来时深度已是 1，再往下必然超限。

🔧 视环境处理

  • 7. 沙箱资源上限只对新建容器生效：现在会下发内存（默认 2 GiB）、内存交换、CPU 核数（默认 2 核）、进程数（默认 512）四项限制，已运行的容器不会自动套用。要立即生效就等空闲回收重建；配置语义是「留空沿用默认、填 0 表示该项不限、非法值回退默认」——清空输入框不等于关掉保护。
  • 8. 定时任务的「星期」恢复标准写法：此前填 1-5 实际落成「周二到周六」（周一漏跑、周六多跑），本版改按标准 crontab 解释。数据不需要迁移，但如果当初为了「跑对」而手工把表达式往后挪了一天，现在要挪回来。

🚀 核心特性 (Key Features)

01 · 数据集权限：谁能看哪些表的哪些列、哪些行、到什么时候

同一个数据集，不同的人能看到不同的表、不同的列、不同的行，还能到期自动失效。

  • 四层收窄：一条授权说清「谁 × 哪些表 × 哪些列 × 哪些行 × 到哪天」；表级只做白名单，没配的表默认看不见，新加的表不会自动对所有人开放。
  • 字段级取交集：组织层面禁掉的列，别人单独授权也放不开；查询里用到被禁列直接拒绝，只出现在结果列里就剔掉并说明。
  • 行级不再靠猜：过滤条件改按查询语句结构判断，不再靠猜列名，「状态 = ADMIN」这类写法不会再把条件悄悄丢掉。
  • 一页看清风险：谁都没权限、哪些快到期、哪些被收窄，按风险排序，点进去就能改。
  • ChatBI 真拦截：会话固定的数据集在检索和执行两处都拦住，委派给子智能体也继承同一范围；指标口径里藏着的完整 SQL 不再透给无权的人。

  • 团主 + 成员：成员直接复用委派范围，团里有几个人和实际能调几个永远一致。
  • 专家中心分三类：系统专家 / 自定义专家 / 专家团，支持按团主、子专家、所属团筛选，改名后筛选不会失效。
  • 团队介绍会整段进提示词：写「不查不写」它就真的不干活——指引给出 6 种踩坑写法（各自说明会发生什么）与 5 个可直接套用的模板。
  • 委派能力分两栏回答：能调用的、有权限但暂时调不了的，后者逐条说明原因（没装工具 / 未就绪 / 不在白名单）。
  • 上限可调、边界明确：一次最多几个任务、单个专家每轮几次都在系统设置里改，改完即时生效；主助手不能当团主也不能被委派。

  • 新增工作空间页：浏览、上传、下载、预览、解压、回收站、批量操作都有，与聊天里的文件抽屉同源。

  • 检索质量回到控制台水平：纠正了对上游召回参数的误解，候选池不再被压成个位数。

🐛 重点缺陷修复 (Bug Fixes)

⏰ 调度、定时任务与 Cron

· 「工作日」的任务周六也跑了：排期是标准周一到周五，底层调度器给星期编号的方式却少一天，结果周一漏跑、周六多跑，界面还按标准显示、看不出错。现在进调度前统一换算。

· 带秒的表达式能保存，却永远不执行：保存时只校验了前几段，调度器解析时直接失败，表现为「配置成功、从不运行」。现在保存前就拦住，并指出是哪一段写错。

· AI 说「任务创建成功」，任务却从不运行：工具建任务时不校验排期，非法值先入库再被悄悄跳过，界面还显示「运行中」。现在先校验再入库。

· 一条配错的订阅拖垮后面所有订阅：逐条装载没有相互隔离，出错还会连累整个服务起不来。现在单条失败只跳过这一条。

· 四处手输排期的提示不一致：现在统一成「输入框标红 + 说清哪一段错 + 保存前拦住」。

🌊 会话、时间线与交互

· 流式输出时突然不跟底：内容一长高，浏览器会自己微调滚动位置，被误判成「用户往上滚了」，从此只提示不跟随。现在只认真实的滚动动作。

· 「思考过程」的开关等于没用：几处监听互相覆盖、判断顺序也写反了，导致「生成完自动折叠」永不生效——这段逻辑已改错过两次。现在收敛成一条明确规则，并加断言防止再排错。

· 工具卡片跑完一直摊着：一轮几个工具就把整屏铺满执行明细。现在结束即折叠，用户正在看的那张不会被抢走。

· 准备阶段先展开再收起，闪一下：同一个节点在流式过程中先摊开几行，状态收敛后又收回去。现在默认收起，只有出错或用户点开才展开。

· 打开长会话没定位到最后一条：消息行按固定高度估算，历史越长偏差越大。现在强制贴底并补帧。

· 点浮层外面收不起来：侧栏按钮拦下了点击事件，用户模式还多一层内嵌页面的隔断。现在按下即判定，并用一层透明遮罩兜住嵌套区域。

· 概览页三处数字失真：图例被裁成「mcp_r…」、最长一项显示 100% 而旁边写 40%、空白时段被压成两根竖刺。现在图例可读、百分比与条形同源，失败项能点进明细。

🛡️ 平台、权限与登录

· 「一键初始化 default 角色」必定失败：创建接口把所有系统角色码都当成保留字，实际只有管理员这一个码带特权，其余三个可以创建、只是不许删。现在只拦真正会提权的。

· 密码快到期提示闪一下就不见：后端用「最后更新时间」算密码年龄，而它每次登录都会被刷新，已过天数永远归零。现在改按「密码最后修改时间」算。

· MCP 连接测试必然报参数错误：探测沿用了保存时的必填校验，而新建向导第一步根本没有名字输入框——「填地址 → 点验证」100% 失败，且请求都没发出去。现在探测不再要求名字。

· 分享里「永久」按钮不高亮：其实已经生效，只是选中态没覆盖这个选项，点完五个按钮全是灰的，让人以为点不动。现在选中态与提交值同源。

· Docker 部署的配置静默失效：环境变量文件只参与了模板替换、没注入容器，跨域白名单等配置会悄悄退回默认值。现在统一注入，同名项仍以显式配置优先。

🛠️ 工具、沙箱与嵌入

· 沙箱容器被删掉后永不自愈：存活标志只是个普通变量，容器被清理、内存耗尽或别的实例替换后它仍显示「活着」，而缓存命中时根本不去问 Docker，报错会一直抛给用户。现在定期确认容器还在，不在就就地重建。

· 图片一律被当成 png：上游生成的是 jpeg / webp，转换环节写死了 png，严格一点的模型直接判「图片无效」；验证码识别走同一条链，表现为「偶发识别不了」。现在按真实类型传。

· 技能说明被悄悄截断：读进来二十多万字符、进上下文前砍到六万多，截断处没有任何提示，日志还写着「已完整加载」，被砍掉的尾段恰好是禁止事项与输出格式。现在保留首尾并标注省略了多少。

· 知识库链路核实的 10 处问题：「同步」按钮点了毫无变化、部门成员看得到批量按钮却选不中任何文档、删库漏清收藏与待审批申请、数据集过千后排在后面的库被漏删成孤儿、删文档后目录记录只增不减。

· 上游返回非 JSON 时直接崩：网关返回 HTML 错误页会让解析抛异常。现在提取诊断信息，给出可读的提示。

📖 平滑升级指南 (Upgrade Guide)

遵循以下标准步骤即可平滑无缝升级至 v1.0.22.0。请务必注意：本版本新增 7 组数据库迁移必须按序执行，知识库图片链路需要可用的多模态模型。

方式一：源码拉取升级（开发与虚机部署）

# 1. 同步拉取主分支最新代码

git fetch origin && git checkout main && git pull origin main

# 2. 执行数据库结构平滑迁移 (MySQL / PG，务必按序)

bash db-prod/apply-sql.sh # PG: bash db-prod-pg/apply-sql.sh

# 3. 更新依赖环境并启动本地服务

poetry install --no-root && ./dev.sh

方式二：Docker 容器化升级（生产环境推荐）

# 1. 执行数据库增量升级 (宿主或临时容器)

bash db-prod/apply-sql.sh # PG: bash db-prod-pg/apply-sql.sh

# 2. 导入官方 Release 镜像归档（x86_64 / ARM64 按架构选择）

docker load -i nanzi-ai-agent_1.0.22.0_linux-amd64_*.tar

docker load -i nanzi-ai-agent_1.0.22.0_linux-arm64_*.tar

# 3. 确认 .env 与 compose 的 env_file 生效（本版修掉静默失效）

cd docker && docker compose config | grep -E "ALLOWED_ORIGINS|LOG_LEVEL"

# 4. 重启容器服务

./start-nanzi-ai-agent.sh

方式三：沙箱重建与升级后自检（若启用沙箱）

# Docker 沙箱：cgroups 上限只对新容器生效，需等空闲回收或主动重建

bash sandbox/docker/build-docker-sandbox-image.sh

# K8s 沙箱：重新构建并导入预置镜像，再重建运行中的 Pod（已关闭 SA Token 挂载）

bash k8s_deploy/build-k8s-sandbox-image.sh

# K8s 沙箱：集群就绪与 RBAC 权限健康检查

bash k8s_deploy/nanzi-k8s.sh health

✅ 升级后请依次自检：① 知识库操作权限范围已按预期生效（详情页头部「可编辑 / 只读」徽标）；② 数据集权限总览可打开、字段级 tab 有数据；③ 会话固定数据集后，模型无法查范围外数据集；④ 沙箱容器已带 cgroups 上限（docker inspect 看 Memory / NanoCpus）；⑤ 角色界面模式黑名单按预期禁用而非隐藏。
