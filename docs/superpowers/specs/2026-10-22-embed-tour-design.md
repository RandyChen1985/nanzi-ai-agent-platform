# EmbedChat 功能引导（Feature Tour）设计

## 目标

给 `/embed/chat` 加一套一次性的分步引导：聚光灯高亮目标区域，气泡解释该区域能做什么，10 步讲完即结束。同一账号只自动播一次，跨设备不重播；中途退出下次从断点继续；用户随时可以在设置里重新播放。

## 范围与决策

已确认的产品决策：

| 决策点 | 结论 |
|---|---|
| 引导区域 | 顶部状态、右上功能、欢迎卡片、输入框、+ 入口、输入框浮标、沙箱、专家委派、模型/审批，共 10 步 |
| 沙箱讲法 | 单独一步：引导主动点开「上下文用量」胶囊，高亮弹层里的 Sandbox 区块，结束后收起 |
| 播放范围 | 所有进入者首次自动播；宿主可用 `?tour=0` / `?tour=off` 关闭 |
| 中断处理 | 断点续播：记录步骤序号，下次接着走 |
| 高亮风格 | 聚光灯：全屏压暗 + 目标镂空 |
| 实现方式 | 自研轻量 Tour 组件，不引入 driver.js 等依赖 |
| 移动端 | 不自动播；设置里可手动播放 |
| 播放前置 | 起播前若当前会话有内容，先开一个空会话（内容自动进历史），保证欢迎卡片步骤可见 |

不做的事：不覆盖 Dashboard 内的其他页面；不做引导视频/多语言；不改 EmbedChat 现有布局。

## 步骤定义

固定 10 步，`step` 为 0 基索引。目标缺失时跳过但**不改变索引**，保证断点语义稳定。

| # | `data-tour` | 标题 | 正文 |
|---|---|---|---|
| 1 | `header-status` | 智能体状态 | 这里显示智能体是否在线；有会话在跑时会出现「进行中的会话」，点开可以切换查看。 |
| 2 | `history-toggle` | 会话历史 | 点这里展开或收起历史会话，可以搜索、切换和置顶；快捷键 ⌘H / Ctrl+H。 |
| 3 | `header-actions` | 全局工具 | 快捷指令、帮助、设置、服务器浏览都在这里。设置里可以改主题、模型和功能开关。 |
| 4 | `welcome-cards` | 从这里开始 | 不知道问什么，先点一张常用任务卡片；也可以直接在下面输入。 |
| 5 | `composer` | 输入你的问题 | Enter 发送，Shift+Enter 换行。可以直接描述业务问题，不用写 SQL。 |
| 6 | `composer-plus` | 挂载上下文 | 点这里添加文件、技能、知识库、记忆或 MCP 工具，本轮对话会优先使用它们。 |
| 7 | `composer-pills` | 状态浮标 | 反幻觉校验和上下文用量都在这里；点开用量胶囊可以看 Token 构成与压缩记录。 |
| 8 | `sandbox-block` | 沙箱 | 上下文弹层下半部分是沙箱：运行状态、终端入口、重启与停止；连续空闲会被自动回收。 |
| 9 | `composer-routing` | 专家委派 | 默认由主助手处理；点这里可以指定常驻专家，也可以在输入框用 @ 临时选专家或挂文件。 |
| 10 | `composer-approval` | 模型与审批 | 右侧可以切换模型；这里设置审批模式——高风险操作会先确认再执行。 |

第 8 步的 `beforeEnter`：若弹层未打开，记录「由引导打开」并点击上下文胶囊，等待弹层渲染（`nextTick` + 最多 300ms 轮询）。引导结束时仅收起自己打开的那一次。

## 渲染与交互

- **遮罩**：四块固定定位的半透明层（上/下/左/右）围出镂空，避免 `box-shadow` 在滚动容器里被裁。遮罩 `pointer-events: auto`，点击不关闭引导。
- **高亮框**：2px 品牌蓝描边 + 8px 圆角 + 轻外发光，`pointer-events: none`，绘制在遮罩之上。
- **气泡**：白底、圆角 12、阴影，宽度 300–340px；优先放在目标下方，空间不足翻到上方；箭头指向目标水平中心。滚动或窗口尺寸变化时重新定位，目标滚出视口则临时收起气泡。
- **进度**：底部显示 `当前 / 8` 和可点击的小圆点（跳到已播放过的步骤）。
- **键盘**：`Esc` 退出并保存断点；`←` 上一步；`→` / `Enter` 下一步。
- **动画**：遮罩淡入 160ms，高亮框与气泡 180ms 内位移淡入；关闭时反向 120ms。
- **目标定位**：`scrollIntoView({ block: 'center' })` 后再测量；位置一律用 `getBoundingClientRect()` 计算，不改动目标元素样式。

## 持久化（Redis）

复用现有 key `agent:portal_prefs:{user_id}`，在 `PortalPrefs` / `PortalPrefsUpdate` 中新增：

```python
embed_tour_version: int = 0          # 引导内容版本，当前 TOUR_VERSION = 1
embed_tour_step: int = 0             # 已进行到第几步（0 基）
embed_tour_completed_at: str = ""    # ISO 时间，空 = 未完成
```

更新走专用端点，避免旧页面全量回写覆盖：

```
PUT /api/portal/portal-prefs/embed-tour
body: { "version": 1, "step": 4, "completed_at": "" }
```

服务端合并写入并返回最新三字段。读取走现有 `GET /api/portal/portal-prefs`。

判定逻辑（前端）：

- `version !== TOUR_VERSION` → 视为未开始（不写回，避免多端竞争覆盖）；
- `completed_at` 非空且版本一致 → 不自动播；
- `step > 0` 且版本一致 → 从 `step` 继续；
- 其余 → 从 0 开始。

写入时机：每次离开一步时防抖 500ms 上报；最后一步点「完成」时上报 `step = 9` 和 `completed_at`。页面直接关闭导致最后一次防抖丢失属于可接受损耗（最多回退一步）。

## 触发与生命周期

- `EmbedChat` 挂载后等待 `hasPermission` 与首屏渲染完成，再延迟 600ms 启动。
- 自动播放条件：非移动端、无 `?tour=0|off`、Redis 判定为未完成、页面上至少存在 4 个可用锚点（防止页面结构异常时播出一套残缺引导）。
- 引导期间锁定页面交互（遮罩拦截），`Esc` 或「跳过」退出并保留断点；「跳过」文案为「跳过引导」，不写 `completed_at`。
- 用户从设置里点「重新播放」：先清零 `step` 与 `completed_at`（保留 `version`），关闭设置弹窗，立即开播。

## 设置入口

`ChatSettings.vue` 在「智能特性」分组之后新增分组：

```text
功能引导 / Feature Tour
  首次使用会自动播放一次，之后可以在这里重看
  [重新播放功能引导]    上次完成：2026-10-22 20:15（或「尚未完成」）
```

按钮在移动端同样可用（手动播放模式）。

## 移动端

不自动播放。手动播放时：气泡贴底、宽度铺满 `calc(100vw - 24px)`，遮罩仍聚光；`header-actions` 在窄屏收进「更多」弹层，该步自动跳过。

## 边界与约定

- **步骤索引与跳过**：跳过某步不改变索引，断点恢复时若目标仍不存在则继续前进，直到下一个可用步。
- **弹层归属**：只有引导主动打开的上下文弹层才由引导收起；用户自己打开的，退出时保持原状。
- **iframe**：遮罩相对 iframe 视口定位，宿主页面的滚动不影响；`position: fixed` 即可。
- **欢迎卡片与空会话**：第 3 步只在空会话可见；自动播与设置内重播都会先新建空会话（内容保存进历史，不弹确认框），断点在卡片之后时跳过这一步新建动作。
- **多标签页**：同一账号两个标签同时开着，各自会播；任一标签完成写入后，其他标签下次进入不再播（当前已播放的不强制中断）。
- **接口失败**：上报失败时写 `localStorage`（键 `embed_tour_state`），下次启动先读 Redis，取不到再读本地；成功后以 Redis 为准。
- **权限不足**：`hasPermission` 为 false 或页面处于无权限遮罩时不启动。
- **版本升级**：`TOUR_VERSION` 提升即视为全员重新播放；步骤文案大改才提升版本。

## 验收

- 新账号首次进入 `/embed/chat`，桌面端自动从第 1 步播放，10 步后写完成；再次进入不播。
- 同一账号换浏览器 / 清 localStorage，不重播（Redis 生效）。
- 第 5 步关闭页面，再次进入从第 5 步继续。
- 设置里点「重新播放功能引导」，关闭设置后立即播放；播完不再自动播。
- 第 7 步引导自行点开上下文弹层并高亮沙箱；退出时弹层恢复。
- `?tour=0` 进入不自动播；设置里仍可手动播。
- 移动端不自动播；手动播时气泡贴底、无横向溢出。
- 契约测试覆盖：10 个 `data-tour` 锚点、`ChatTour` 挂载、3 个 Redis 字段与版本比对、`?tour=0` 短路、移动端不自动播、设置入口文案。
