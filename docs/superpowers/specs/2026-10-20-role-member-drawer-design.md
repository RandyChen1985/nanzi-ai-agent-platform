# 角色成员抽屉（角色页就地管理成员）设计

- 日期：2026-10-20
- 状态：待评审
- 关联迁移：无（不涉及表结构变更）

## 1. 背景

角色管理页的「用户数」目前是一个只读徽标（`frontend/src/views/Roles.vue` 桌面表格约 174–178 行、
移动端卡片约 264–266 行）。管理员想确认"这个角色里到底有谁"、或想把某个人摘出角色时，
必须跳到「用户管理」页搜索该用户、打开编辑弹窗、在业务角色多选框里取消勾选、保存。

一条"看成员"的路径要跨两个页面、四次点击。角色页已有的绿色「分配用户」按钮虽然能改成员，
但它打开的是双栏勾选弹窗（`Roles.vue` 660–1050 行），采用**整集替换**语义（提交完整成员 ID 列表，
后端 diff 后增删），必须点"保存"才生效，且该弹窗已经承载了跨页全选、未保存态、加载失败禁用保存
等状态，功能上不适合再叠加入/移出的即时操作。

本次要补的是**反向视角**：以角色为主体，看成员、管成员，并顺手处理账号状态。

### 现状接口盘点

| 能力 | 接口 | 位置 |
| --- | --- | --- |
| 读角色成员 | `GET /api/portal/roles/{role_id}/users` | `app/api/portal/endpoints/roles.py` 209 行 |
| 整集替换成员 | `POST /api/portal/roles/{role_id}/users` | 同文件 276 行 |
| 改账号状态 | `PATCH /api/portal/management/users/{user_id}/status` | `management.py` 787 行 |
| 代设密码 | `POST /api/portal/management/users/{user_id}/set-password` | `management.py` 1143 行 |

读成员接口已经支持 `search` 与服务端分页，并额外返回不受分页影响的**全量** `user_ids`
（该设计要求见 `roles.py` 的 docstring）。缺的是：单点/批量移出接口、成员行展示所需的字段、
以及一个能容纳列表和行操作的容器。

### 已知缺口

1. **读权限与页面准入不一致**：`GET /roles/{id}/users` 要求 `element:role:edit`，但角色列表页允许
   `menu:system:roles` 进入（`roles.py` 56–61 行注释已说明为何放开列表读权限）。只读管理员能进页面、
   看得到用户数，点开却 403。
2. **整集替换存在并发覆盖窗口**：A 打开弹窗时成员 10 人，B 期间移出 1 人，A 保存后 B 的移出被撤销。
3. **成员行信息不足**：`items` 只有 `id / user_name / real_name / status / created_at`，看不到邮箱、
   最后登录时间，更看不到"该用户还属于哪些其他角色"。多角色权限是并集，缺这一列会让管理员
   把"在此角色里的权限"误当成"此人的全部权限"。

## 2. 目标与非目标

### 目标

1. 角色列表「用户数」可点击，右侧抽屉展示该角色成员，支持搜索与分页。
2. 抽屉内可就地完成：移出成员（单个/批量）、启用/禁用账号、重置登录密码、跳转用户管理。
3. 移出是**只做减法**的幂等操作，不存在并发覆盖。
4. 动作按权限点分别收敛，不出现"看得到但点了 403"。
5. 系统角色（尤其 `miniprogram_user`）的移出有明确约束与提示。
6. 桌面与移动端都可用；不影响现有「分配用户」双栏弹窗的任何行为。

### 非目标

1. 不把「编辑用户」「禁用资源」「智能体级限制」「2FA 关闭」「删除用户」搬进抽屉——这些是重表单，
   搬进来会与用户管理页长期漂移。仅提供跳转入口。
2. 不改造、不拆解现有「分配用户」双栏弹窗。
3. 不做跨页全选成员、不做"批量加入其他角色"。
4. 不做表结构变更，不新增权限点。
5. 不实现抽屉内的角色权限/配额 tab（预留给后续）。

## 3. 交互设计

### 3.1 入口

- 桌面表格「用户数」列：数字 + chevron，包成一个按钮；`user_count = 0` 时样式弱化但仍可点
  （用于进入后直接加人）。
- 移动端卡片：`{{ role.user_count }} 用户` 徽标改为可点。
- 无读权限（既无 `menu:system:roles` 也无 `element:role:edit`）时不可点——实际上能进页面就至少有前者，
  因此正常情况恒可点；后端仍按权限拒绝（见 4.1）。

### 3.2 抽屉骨架

```
┌─────────────────────────────────────────────┐
│ 小程序用户  系统        miniprogram_user  × │
│ 1 位成员                                    │
├─────────────────────────────────────────────┤
│ [🔍 搜索姓名或账号…]            [+ 添加成员] │
│ 已选 2 人                    [批量移出]      │
├─────────────────────────────────────────────┤
│ (张) 张三  @zhangsan   [启用]                │
│      还属于：默认角色 +1                     │
│      2026-10-15 加入   [禁用][重置密码][移出]│
├─────────────────────────────────────────────┤
│ 共 23 人 · 第 1/1 页          [上一页][下一页]│
└─────────────────────────────────────────────┘
```

- 桌面：右侧滑出，`w-[min(720px,100vw)]`，左侧圆角与阴影；移动端：全屏（沿用 `Roles.vue` 现有
  `isMobile` 分支，与其它弹窗一致）。
- 层级：抽屉 `z-[9990]`（与现有弹窗同层，二者不会同时打开）；抽屉内"重置密码"小弹窗用更高层，
  确保可覆盖抽屉。
- 头部：角色名 + 系统角色徽标 + `code` + 成员总数；关闭按钮。
- 工具条：搜索框（300ms 防抖）、「添加成员」按钮（仅在 `canEditRole` 时显示）、批量选中计数与
  「批量移出」按钮（仅 `canEditRole` 且选中数 > 0 时显示）。
- 成员行：首字母头像 / `real_name || user_name` / `@user_name` / 状态徽标 / 「还属于」chips
  （最多 2 个 + `+N`，全部角色名走 `title` 显示）/ 加入时间 / 行操作。
- 分页：服务端分页，50/页，展示 `共 N 人 · 第 x/y 页`。

### 3.3 选中语义

勾选**只作用于当前页**。翻页或改变搜索条件时清空选中并给出提示（"已切换页面，选中已清空"）。
这是刻意设计：跨页全选会让"批量移出"重新变成一次整集替换，抹掉本次新增单点接口的意义。

### 3.4 动作表

| 动作 | 接口 | 所需权限 | 行为 |
| --- | --- | --- | --- |
| 读取成员 | `GET /roles/{id}/users` | `menu:system:roles` 或 `element:role:edit` | 搜索 + 分页 |
| 移出（单/批） | `POST /roles/{id}/users/remove`（新增） | `element:role:edit` | 立即生效，成功后刷新抽屉与主表计数 |
| 添加成员 | 复用 `POST /roles/{id}/users` + 现有双栏弹窗 | `element:role:edit` | 弹窗保存后刷新抽屉与主表 |
| 启用/禁用 | `PATCH /management/users/{id}/status` | `element:user:edit` | 立即生效；禁用自己由后端拦截，前端隐藏按钮 |
| 重置密码 | `POST /management/users/{id}/set-password` | `element:user:edit` | 抽屉内小弹窗；提交前提示"会吊销该用户全部会话" |
| 跳转用户管理 | `router.push('/system/users?q=<user_name>')` | `menu:system:users` | 用户页预填搜索 |

按钮显隐一律由 `hasPermission(...)` 驱动，不做"先展示后报错"。

### 3.5 系统角色保护

| 角色 code | 移出行为 |
| --- | --- |
| `miniprogram_user` | 移出按钮置灰 + tooltip「小程序静默登录会自动重新加入该角色，此处移出无效」 |
| `default` / `admin` / `system` | 允许移出，但二次确认「移出后该用户将没有任何业务角色，确定继续？」 |
| 其它自定义角色 | 直接移出，不确认 |

口径与 `roles.py` 的 `SYSTEM_ROLE_CODES`、前端 `isSystemRole()` 保持一致（三处同一份清单）。

约束只在前端生效：具备 `element:role:edit` 的主体都是管理员，后端不额外拦 `miniprogram_user` 的移除，
保持接口通用性。此取舍写入代码注释，避免后来者误以为后端有保护。

## 4. 接口设计

### 4.1 放宽 `GET /roles/{role_id}/users` 读权限

```python
admin: dict = Depends(require_any_permission(
    ("menu", "menu:system:roles"),
    ("element", "element:role:edit"),
))
```

写接口（整集替换、新增 remove）保持 `require_permission("element", "element:role:edit")` 不变。

### 4.2 `items` 扩充字段

在现有字段基础上增加：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `email` | `str \| null` | 已做小写归一化存储 |
| `last_login_at` | `str \| null` | ISO 字符串 |
| `role` | `str` | 系统角色 `admin` / `user` |
| `role_names` | `list[str]` | 该用户**全部**业务角色名，用于「还属于」chips |

`role_names` 取法：对当前页用户的 id 集合做一次
`select(UserRoleRelation.user_id, Role.name).join(Role, ...).where(UserRoleRelation.user_id.in_(page_user_ids))`，
在内存里按 user_id 分组。**不允许**在列表推导里逐行查询（N+1）。

### 4.3 新增 `POST /roles/{role_id}/users/remove`

```jsonc
// 请求
{ "user_ids": [12, 34] }
// 响应
{ "removed": 1, "skipped": 1, "user_ids": [12] }
```

- 语义：**只删不增**，只影响 `role_id` 这一条关系的成员集合，不触碰这些用户的其他角色。
- 幂等：重复提交同一批 `user_ids` 不会报错，`removed` 仅统计实际删除行数。
- 空数组：返回 `{"removed": 0, "skipped": 0, "user_ids": []}`，不报 400。
- 角色不存在：404 `Role not found`（与现有接口一致）。
- 事务：单次 `delete(...).where(role_id == X, user_id.in_(ids))`，一次 commit。
- 缓存：删除后必须调用 `PermissionService.invalidate_cached_permissions_for_users(实际删除的 id)`。
  漏掉会让被移出者在缓存 TTL（1 小时）内继续持有角色权限——现有整集替换接口已这么做，新接口同口径。
- `skipped` 表示传入但本就不是成员的数量，供前端提示"部分成员已不在该角色中"。

### 4.4 `Users.vue` 读取 `route.query.q`

新增：挂载时若存在 `route.q`，写入 `searchQuery` 并触发一次 `fetchUsers()`。
只做搜索预填，不自动打开编辑弹窗（自动打开需要先按 id 取回完整 user 对象，收益不足以扩大改动面）。

## 5. 权限矩阵

| 主体能力 | `menu:system:roles` | `element:role:edit` | `element:user:edit` |
| --- | --- | --- | --- |
| 进入角色页 | ✓ | — | — |
| 打开抽屉、读成员 | ✓ | ✓ | — |
| 移出 / 添加成员 | — | ✓ | — |
| 启用 / 禁用 / 重置密码 | — | — | ✓ |

行操作列只要 `element:role:edit` 与 `element:user:edit` 至少具备其一就展示；两者都没有时整列显示 `—`。

无 `element:role:edit` 也无 `element:user:edit` 时，抽屉只读，操作列显示 `—`（与现有表格的空操作占位一致）。

## 6. 错误处理

| 场景 | 处理 |
| --- | --- |
| 抽屉打开时角色已被删除（404） | 关闭抽屉 + toast「角色不存在或已被删除」 |
| 成员加载失败 | 抽屉内错误态 + 「重试」，不渲染空列表（避免误判为"没有成员"） |
| 移出失败 | toast 错误详情，保留选中态，不刷新列表 |
| 移出自己且失去角色编辑权限 | 不特殊处理；后续操作由后端 403 自然暴露 |
| 重置密码复杂度不足 | 前端 `checkPasswordPolicy` 拦截，不发请求 |
| 禁用自己 | 按钮隐藏（后端另有 403 兜底） |
| 搜索无结果 | 空态文案区分"角色暂无成员"与"没有匹配的用户" |

## 7. 测试计划

### 后端（pytest）

1. `remove` 幂等：连续两次移除同一成员，第二次 `removed == 0`、`skipped == 1`，无异常。
2. 不误删：移除 A 在角色 R1 的关系后，A 在 R2 的关系仍在。
3. 缓存失效：移除后 `invalidate_cached_permissions_for_users` 以实际删除的 id 被调用一次。
4. 空数组与全非成员：返回 0，不抛 500。
5. `items.role_names` 覆盖多角色用户，且不产生逐行查询（可用查询计数断言或代码结构断言）。
6. 读权限：仅有 `menu:system:roles` 时可读成员；无任何相关权限时 403。
7. 写权限：仅有 `menu:system:roles` 时调用 remove 返回 403。

### 前端契约测试（`pytest --confcutdir=tests/frontend`）

1. `Roles.vue` 模板含抽屉组件与可点用户数按钮。
2. 抽屉内动作按钮均绑定 `hasPermission` 条件（防止后续改动把权限控制删掉）。
3. `Users.vue` 引用 `route.query.q`。
4. 系统角色移出保护：`miniprogram_user` 分支存在且带禁用条件。

### 手动验证清单

- 桌面：0 成员角色、20+ 成员角色、搜索、翻页、批量移出、禁用后行内状态更新。
- 移动端：全屏抽屉、行操作折叠方式、密码弹窗层级。
- 只读管理员：抽屉可看不可改。
- `vue-tsc --noEmit` 通过。

## 8. 实施顺序

1. **后端**：读权限放宽 → `items` 扩字段 → 新增 remove 接口 → pytest。
2. **前端抽屉**：抽 `components/system/RoleMembersDrawer.vue` → `Roles.vue` 接入入口 →
   实现列表/搜索/分页 → 接入移出、启用禁用、重置密码 → 移动端适配。
3. **收尾**：`Users.vue` query 预填 → 前端契约测试 → 更新 `tests/CHECKLIST.md`。

> `Roles.vue` 已 2446 行，抽屉必须独立成组件，不在此文件内继续堆叠。

## 9. 风险与取舍

| 风险 | 说明与对策 |
| --- | --- |
| 与整集替换双栏弹窗职责重叠 | 两者入口与语义都不同：弹窗=批量编排（需保存），抽屉=即时单点。抽屉的「添加成员」直接复用弹窗，不加第二套添加逻辑。 |
| `role_names` 引入的性能开销 | 每页一次 `IN` 查询；50 人规模可忽略。 |
| 权限不对称导致操作失败 | 所有动作按权限点显隐，矩阵见第 5 节。 |
| 系统角色移出仅在 UI 层约束 | 已在设计中显式声明，避免误判为后端保护。 |
| `Roles.vue` 继续膨胀 | 强制抽组件。 |
