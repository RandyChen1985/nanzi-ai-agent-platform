# 模块化流水线回归修复设计

## 背景

当前待提交代码把 AI 聊天主流程从 `AgentService` 拆分为 Preflight、Context、Route、Assemble、Execution、Finalize 六个步骤，并抽出了上下文压缩、技能注入、恢复处理和多智能体编排。拆分方向保留，但迁移过程中遗漏了旧主流程的若干权限、状态、流事件和持久化契约。

本次修复只恢复这些既有契约，不改变公开 API、不新增业务能力、不回退模块化架构，也不修改数据库结构。

## 设计目标

1. 权限、用户上下文和数据范围初始化失败时必须立即停止，不能降级执行。
2. 单智能体与多智能体使用一致的异步流和内容累加协议。
3. 可复用结果、知识增强、长期记忆和技能提示完整传递到实际执行器。
4. 取消、等待、错误和成功路径都经过统一且幂等的收尾逻辑。
5. 客户端事件、历史记录、过程时间线、Todo 状态和审计状态与旧流程兼容。
6. 生产入口由真实六步流水线测试覆盖，而不是只测试兼容方法或假步骤。

## 架构边界

### PipelineContext

`PipelineContext` 是跨步骤关键状态的唯一可信来源，包括用户问题、身份、长期记忆、路由决策、执行状态、累积内容、过程时间线和性能追踪器。`shared_state` 只承载现有执行器尚未迁移的兼容数据，写入时必须同步到对应的类型化字段，避免同一状态出现两个互相矛盾的版本。

### Preflight 与 Context

Preflight 继续负责输入清洗、身份校验和并发预加载。Context 负责对齐历史消息、压缩上下文和恢复待处理任务。用户 ID 必须使用已经校验过的 `lane_user_id`，规范化后的问题同时写入 `context.user_query`。

### Route

路由返回权限错误时立即产生终止错误事件，不绑定智能体、不解析模型、不进入执行步骤。可复用结果在轮次类型确定后按允许的结果类型解析，解析结果完整写入 `TurnDecision`，客户端状态事件与执行器收到的决策必须一致。

### Assemble

`AgentContextManager.setup_context()` 是权限和数据范围边界，其异常必须向上传播并终止流水线。知识轮次恢复专用知识增强和显式数据集校验。Preflight 得到的长期记忆直接从 `PipelineContext` 传入提示词组装；技能匹配日志和原始提示词调试事件继续按旧协议发送。

### Execution

多智能体包装器直接返回可供 `async for` 消费的异步迭代器。单智能体与多智能体共用既有内容累加器，支持 `answer_delta`、过程叙述提升、撤回和兼容文本事件。每个流事件到达时立即更新 PipelineContext、过程时间线和性能指标，取消或异常时也保留已经产生的部分输出。

### Finalize 与 Runner

Finalize 是唯一的终态收尾位置，负责：

- 成功时完成 Todo；等待、取消或失败时保留正确状态；
- 汇总并持久化过程时间线；
- 在持久化前过滤非法下载地址，并在客户端已经收到相关内容时发送撤回事件；
- 取消时使用现有独立任务机制完成必要的历史持久化；
- 将 `awaiting_user`、权限等待和外部执行等待记录为非完成审计状态；
- 输出性能快照。

PipelineRunner 捕获的未处理异常必须交给现有终端错误清洗逻辑，不能直接向客户端返回原始异常字符串。

## 兼容性要求

- 保持 `AgentService.chat_completion_stream()` 的参数和流事件外形不变。
- 保持现有执行器、恢复处理器和前端消费者可识别的事件顺序。
- 不放宽用户、智能体、数据集、附件、工具和 MCP 权限。
- 不改变 MySQL/PostgreSQL Schema，不引入新依赖。
- 不启动服务或执行部署脚本。

## 测试策略

每项修复遵循先失败测试、后最小实现：

1. 权限拒绝和 `setup_context` 异常均证明执行器未被调用。
2. 多智能体现有测试覆盖 async-for 协议、过程叙述提升和最终内容。
3. 可复用结果测试同时断言客户端事件和 `TurnDecision`；知识测试断言增强调用、显式数据集校验和 LTM 入参。
4. 取消、等待、失败、成功分别断言部分内容、Todo、时间线、历史、审计和撤回事件。
5. 异常测试断言密码样式信息和内部路径不会出现在客户端响应。
6. 从 `chat_completion_stream()` 进入真实六步流水线，断言步骤顺序、性能追踪和终态持久化。
7. 运行相关 pytest、前端契约测试（如事件协议受影响）以及 `git diff --check`。

## 验收标准

- 已确认的权限绕过、上下文 fail-open、多智能体 TypeError、结果复用丢失、知识/LTM 丢失、终态协议和异常泄漏均有回归测试且通过。
- 现有定向回归无新增失败；已有基线失败单独记录，不以本次改动掩盖。
- `tests/CHECKLIST.md` 只记录实际完成且有测试证据的项目，不再声明未经证明的“100% 向后兼容”。
- `git diff --check` 通过。

## 非目标

- 不重新设计路由策略、提示词内容或前端交互。
- 不重构与本次回归无关的执行器和工具实现。
- 不进行真实模型、浏览器、数据库、Redis、多进程或部署验收；这些需要用户在服务环境中另行确认。
