# 用户管理：Excel 批量导入用户设计

- 日期：2026-10-23
- 范围：用户管理页「更多 → 导入用户」，后端 `app/api/portal/endpoints/user_import.py`
- 状态：已实现

## 1. 背景与目标

管理员目前只能逐个「创建用户」，批量开户需要手工重复几十次表单填写。目标是在用户管理页提供一条完整的批量开户链路：

1. 下载固定格式的 Excel 模板并填写「账号、姓名、邮箱、角色」；
2. 上传后先在确认页逐行预览、修正，确认无误再建号；
3. 建号完成后回显账号与初始密码，支持复制或下载。

## 2. 范围

**做**：

- .xlsx 模板下载（含字段说明与当前业务角色清单）；
- 上传解析（表头别名、空行跳过、500 行 / 2MB 上限）；
- 确认页：角色调整、勾选删除、补充新增、重复与格式校验；
- 批量建号：API Key、随机或固定初始密码、业务角色绑定；
- 可选把「账号 + 初始密码」自动发到每个用户的邮箱，并在结果页显示逐行发送状态；
- 结果页：账号密码复制、CSV 下载、失败明细。

**不做**：

- 覆盖更新已存在账号（默认跳过，避免误改存量用户）；
- 导入账号固定为普通用户；如需系统管理员，导入后到用户管理中单独调整；
- 短信通知；邮件仅发送账号与初始密码，不发送其他营销/通知内容；
- 部门归属导入（建号后仍走现有「编辑用户 → 部门」）。

## 3. 交互流程

### 3.1 第一步：上传

- 入口：用户管理 →「更多」→「导入用户」，仅 `element:user:edit` 可见。
- 页面提供「下载模板」、拖拽/点选 `.xlsx`、字段规则说明。
- 上传即请求 `POST /users/import/preview`，成功后进入确认页，**不写库**。

### 3.2 第二步：确认

表格列：勾选、Excel 行号、账号、姓名、邮箱、角色、校验结果、删除。

- 角色：下拉选择平台业务角色，展示「名称（编码）」；
- 勾选删除：支持单行删除与「删除所选」；删除列固定在表格右侧，窄屏横向滚动时仍可见；
- 补充新增：在表格末尾追加空白行；
- 重新上传：回到第一步并清空本次确认数据；
- 未匹配角色、重复账号、占用邮箱、空账号/邮箱、文件内重名都会在行内提示；
- 确认页顶部按类型汇总「账号已存在 / 邮箱被占用 / 角色未匹配」的行数，明确说明这些行**不会被导入**，并给出「取消勾选」「修改账号名」「更换邮箱」的处理指引；已存在账号仍被勾选时，提交按钮禁用并提示先取消勾选；
- 初始密码二选一：
  - **随机密码**（默认）：每个账号独立生成 12 位密码；
  - **固定密码**：所有本次导入账号共用同一个密码，输入框支持显示/隐藏，实时校验长度 8-32、至少 3 类字符、不含空白、不包含任一待导入账号名；
- 「发送密码到用户邮箱」开关（默认关闭）：开启后建号成功即通过平台全局 SMTP 把「账号 + 初始密码」发到该用户邮箱；关闭时由管理员复制/下载后自行分发；预览接口返回 `email_service_available`，全局邮件服务未启用时开关置灰禁用，并提示去「系统配置 → 邮件服务」开启；
- 改账号或邮箱后，前端 450ms 防抖调用 `POST /users/import/check` 重新查库，实时刷新「已存在 / 邮箱被占用」标红，不必等到提交后才发现重名；
- 点击「确认导入」时再强制查一次：仍有占用则停留在确认页并提示修改，不进入建号；
- 未勾选任何行、所选行仍有校验问题、或固定密码不合法时，「确认导入」禁用。

### 3.3 第三步：结果

- 汇总成功 / 失败数量；开启邮件时增加「密码邮件」成功/失败统计；
- 成功表格：账号、姓名、邮箱、角色、初始密码（等宽显示）、密码邮件状态（仅开启时显示）；
- 支持单行复制密码、「复制全部」（TSV）与「下载 CSV」（带 BOM）；
- 失败明细：账号、邮箱、失败原因；
- 邮件失败时单独提示「账号已创建成功，请复制/下载密码后通过其他安全渠道发送」，并逐行展示失败原因；
- 明确提示「密码仅本次显示，离开本页后无法再次查看」。

## 4. Excel 模板

Sheet1「用户导入」：

| 列 | 必填 | 说明 |
| --- | --- | --- |
| 账号* | 是 | 全平台唯一，不含空格，≤ 50 字符；整列设为文本格式防前导零丢失 |
| 姓名 | 否 | ≤ 50 字符；不填时界面显示账号名 |
| 邮箱* | 是 | 全平台唯一，导入时统一小写归一化 |
| 角色 | 否 | 业务角色 code 或 name；留空使用 `default` |

Sheet2「填写说明」：字段规则、示例、账号身份说明（均为普通用户）、密码说明，以及当前全部业务角色（编码 / 名称 / 描述）。

表头解析支持常见别名（用户名、用户账号、姓名、真实姓名、电子邮件、业务角色、`username`、`real_name`、`email`、`role` 等），并忽略空格、下划线、连字符、星号与冒号。

## 5. 后端接口

全部要求 `element:user:edit`，注册在 `/api/portal/management` 下，且先于 `management` 的动态用户路由注册。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/users/import/template` | 生成并下载模板（动态填充角色清单） |
| POST | `/users/import/preview` | 解析 xlsx，返回逐行校验结果与角色列表 |
| POST | `/users/import/check` | 确认页编辑账号/邮箱后实时查重（只读，不写库） |
| POST | `/users/import/confirm` | 按确认行批量建号，返回账号密码、邮件发送状态与失败明细 |

### 5.1 预览返回

`items[]` 包含：`row`、`user_name`、`real_name`、`email`、`role_input`、`role_id`、`role_code`、`role_name`、`role_from_default`、`role_matched`、`system_role`、`existed`、`email_taken`、`importable`、`issues[]`；响应顶层另有 `email_service_available`，用于在确认页决定是否禁用「发送密码到用户邮箱」开关。

所有导入账号的系统身份固定为 `user`；确认页不再提供身份切换。

### 5.2 实时查重

`POST /users/import/check` 接收当前确认页的全部行（最多 500 行），一次查询账号与邮箱占用，返回与请求同序的：

```json
{"items": [{"user_name": "alice", "existed": false, "email_taken": true}]}
```

- 只回答「账号是否已存在」「邮箱是否已被占用」，格式与角色仍由前端/confirm 校验；
- 邮箱先做 `normalize_email`，大小写不敏感；
- 前端按 450ms 防抖调用，并在提交前强制再查一次，避免 450ms 窗口内直接点下一步；
- 最终仍以 `confirm` 的落库校验为准（并发场景无法完全消除）。

### 5.3 确认请求

```json
{
  "rows": [{"user_name": "alice", "real_name": "爱丽丝", "email": "alice@example.com", "role_id": 1}],
  "password_mode": "random",
  "fixed_password": null,
  "send_password_email": false
}
```

- `password_mode`：`random`（默认）/ `fixed`；
- `fixed_password`：仅 `fixed` 模式必填；建号前对全部行统一校验，不通过直接 400，避免半批创建；
- `send_password_email`：默认 `false`；为 `true` 时逐行返回 `email_sent` / `email_error`，并汇总 `email_sent_count` / `email_failed_count`。

### 5.4 角色匹配

1. 先按业务角色 `code` 精确匹配（忽略大小写与首尾空格）；
2. 再按 `name` 精确匹配；
3. 仍匹配不上：`role_id = null`，行内提示「未匹配到内置角色，请在确认页选择」；
4. 角色留空：使用 `default`；系统里没有 `default` 时提示手选。

## 6. 校验规则

- 账号：非空、≤ 50 字符、不含空白；
- 姓名：选填、≤ 50 字符，保存到 `users.real_name`；空值不写，界面回退显示账号名；
- 邮箱：非空、格式校验、统一小写；
- 账号唯一：文件内重复（所有重复行都标出）+ 与库内账号重复；已存在账号在确认页标红并默认不勾选，不会静默跳过；
- 邮箱唯一：与库内邮箱重复（大小写不敏感）；
- 身份：固定 `user`，请求体不接受 `system_role`；
- 角色：确认提交时再次校验 role_id 存在。

预览只做提示，最终以 `confirm` 的二次校验为准；重复行不会静默覆盖。

## 7. 密码与安全

- 随机密码 12 位，必含大写、小写、数字、特殊符号；
- 固定密码复用 `AuthService.validate_password_complexity`，并在建号前检查是否包含任一账号名；固定密码天然是「一码多用」，确认页明确提示风险，建议用户首次登录后修改；
- 特殊字符集合排除引号、逗号、分号，避免破坏 TSV / CSV；
- 库里只存 bcrypt 哈希；明文仅出现在 `confirm` 响应与（开启时的）密码邮件中，不写日志、不落库；
- bcrypt 哈希放入 `asyncio.to_thread`，避免批量导入阻塞事件循环；
- 密码邮件只使用**全局** SMTP，避免用户个人 SMTP 配置影响开户通知；邮件正文包含初始密码，因此仅在管理员显式打开开关时发送，并在正文提示「请勿转发、首次登录后改密」。

## 8. 数据一致性

- 每行一个独立事务：失败行回滚，成功行保留；
- 建号、密码、角色关系在同一次提交内完成，避免「账号建了但没密码」；
- 用户名 / 邮箱在提交前预取集合，成功后同步更新集合，减少重复查询；
- 单行未知异常只记 warning 日志，对外返回通用失败原因，不泄露 SQL 细节；
- 邮件发送在账号提交之后：单封失败只标注 `email_error`，不回滚账号；并发上限 5，避免串行拖死请求或把邮件网关打爆。

- `frontend/src/components/user/UserImportDialog.vue`：三步弹窗、上传解析、确认编辑、结果复制/下载；

## 11. 已知限制

- 单次 500 行；bcrypt 成本较高时，500 行导入需要数十秒；
- 固定密码由所有导入账号共用，安全性低于随机密码；关闭邮件时需管理员自行安全分发；
- 邮件发送会延长请求耗时（并发 5），且依赖全局 SMTP 已启用；SMTP 不可用时账号仍创建，结果页标注发送失败；
- 实时查重与 confirm 之间仍有并发窗口（别人同时建号），最终以 confirm 的落库校验为准；
- 角色为单选；多角色用户需导入后再编辑；
- 不导入部门、备注、API Key 是否展示等扩展字段。
