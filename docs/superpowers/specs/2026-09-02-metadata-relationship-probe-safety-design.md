# 元数据关系推荐安全修复设计

## 目标

修复 `cc796c8a` 引入的关系推荐问题：关系推荐不读取业务数据行；保留数据库外键等结构化元数据证据；无外键时交给 AI 根据字段元数据兜底；同时修正关系方向、复合外键、schema 前缀、API 契约测试和诊断统计。

## 方案

1. 数据库探测服务只执行各数据库的系统目录查询，不再生成或执行抽样值、`IN (...)` 回查和业务表行统计 SQL。由于当前适配器没有统一的当前用户数据源权限上下文，禁止新增绕过权限的服务账号行读取。
2. 外键结果按候选表对方向输出完整的列对。复合外键仅在候选关系能够完整表达全部列对时确认，不截断为第一列。
3. 候选关系保留左/右表顺序供 UI 展示，但 AI/元数据判断使用明确的 child/parent 语义，避免把主表当成子表。
4. 关系 API 测试 fixture 补齐 `data_source`，并增加边界测试；前端提示与实际行为统一为“不查询业务数据行”。
5. 诊断统计改为按实际候选数量统计，补充跨数据库系统查询和 schema 前缀回归测试。

## 验收标准

- 关系推荐流程不调用业务表抽样 SQL。
- 外键关系支持单列和复合列，输出完整连接条件。
- MySQL、PostgreSQL、SQL Server、Oracle 的系统目录查询分别保留现有适配器方言。
- API 关系推荐定向测试全绿，原有纯服务层和前端契约测试全绿。
- `git diff --check` 通过；不执行服务启动、真实数据库或部署验收。
