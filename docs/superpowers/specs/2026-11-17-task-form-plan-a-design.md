# 定时任务表单整页重设计（方案 A 落地）

**需求（用户原话）：** 附截图后「如果要你重新设计整个页面样子，你有什么好的想法或建议，你 mockhtml 原型给我看看」→ 三方案原型（A 两栏+摘要 / B 四步向导 / C 模板起步）→ 用户选定 **「按方案 a 来实现吧」**。
**原型：** [`prototypes/2026-11-17-task-scheduler-form-redesign.html`](../../../prototypes/2026-11-17-task-scheduler-form-redesign.html)

---

## 1. 先更正一处原型误判

原型里把「时间从 cron 表达式改成人话选择器」列为待做项，**这是错的**：`TaskCenter.vue` 里 `cronMode` + `cronConfig` 早已实现每天 / 每周 / 每月 / 间隔 / 高级五种模式，并有双向同步（`watch([cronMode, cronConfig])` 生成表达式、`parseCronToUI` 回填）。本次**不重做**这块，只在它下方补「接下来三次运行时间」。

## 2. 现状的四个结构问题

| # | 问题 | 证据 |
| --- | --- | --- |
| 1 | 没有复核面 | 意图散在 6 个字段（时间在 cron 区、对象在提示词、格式在约束、去向在通知），保存前无法一句确认 |
| 2 | 没有具体运行时间 | 只有 `Auto-Translate` 的中文回译，没有日期，用户无法确认填的是本周四还是下周四 |
| 3 | 低频项占前排 | 重试次数/间隔与「要做什么」同级平铺在弹窗中部 |
| 4 | 8 段平铺无分组 | 名称、智能体、运行周期、失败策略、要做什么、输出要求、结果通知等权重从上排到下 |

## 3. 落地方案（全部前端，零后端、零数据结构）

### 3.1 字段重排为三组

原顺序：名称 → 智能体 → **运行周期** → **失败策略** → 要做什么 → 输出要求 → 结果通知。

新顺序（把「什么时候跑」整组前移到「做什么」之后）：

```
[做什么]      任务名称 → 执行大脑 → ① 要做什么 → ② 输出有什么要求
[什么时候跑]  运行周期配置 → 接下来三次运行 → 执行失败策略（折叠）
[结果发到哪]  结果通知
```

分组标题是浅色分隔条（`border-dashed` + 主色小标题 + 一句说明），组内仍保留 ①/② 序号（那是「两栏指令」的语义，不动）。

### 3.2 新增「接下来三次运行」

复用 `@/utils/cronSchedule` 的 `nextCronRunTimes` / `formatCronRunTime`（与后端调度共用平台业务时区，**不自行做星期偏移**，见该文件头注释）。

### 3.3 失败策略折叠

`showAdvancedRetry` 默认 false，收起时行内显示当前策略（`失败重试 N 次 / 间隔 M 分钟` 或 `默认不重试`）。**控件与 `v-model` 绑定一字未改**，只是视觉收起。

### 3.4 右侧粘性摘要栏

- 弹窗宽度 `max-w-3xl`(768) → `max-w-[1080px]`；内容区改 `grid-cols-[minmax(0,1fr)_290px]`，左表单滚动、右摘要栏独立滚动。
- 摘要内容：一句话复述（时间 + 智能体 + 要做什么首句 + N 条交付要求 + 通知渠道）+ 下次运行 / 任务名 / 交付要求条数 / 结果发到 + 自动批准风险提示 + 「保存后可在列表点立即执行试跑」。
- **窄屏（`isMobile`）退回单列**，摘要回到表单顶部（同一份内容两个位置，`v-if` 互斥）。

### 3.5 「试跑一次」的处理

原型右侧有「试跑一次」按钮，需要后端支持「用未保存的配置立即执行、结果只回创建人、不写正式投递记录」。**本次不做**，改为在摘要栏提示「保存后可在任务列表里点『立即执行』试跑一次」（该能力已存在：`runTaskNow` → `taskApi.run(id)`）。

> 过程中曾写下「结果只发给你自己」，核实 `runTaskNow` 只是 `taskApi.run(id)`、结果去向由后端按任务配置决定，**该承诺无依据已删除**。

## 4. 实现约束与风险

| # | 项 | 说明 |
| --- | --- | --- |
| 1 | 模板块搬动 | 「运行周期 + 失败策略」整块（158 行）用脚本按行切出、按锚点插入，**任何绑定、`v-model`、事件均未改动**；模板编译 334 SFC / 0 problem 验证结构完整 |
| 2 | Tailwind 任意值类 | `max-w-[1080px]` 与 `grid-cols-[minmax(0,1fr)_290px]` 已用 `npx tailwindcss --content` 实测生成（`max-width: 1080px` / `grid-template-columns: minmax(0,1fr) 290px`） |

| 4 | 摘要措辞 | 只陈述确定事实；`cronDescription` 无值时显示「（还没选执行时间）」，未写提示词显示「（还没写『要做什么』）」 |

## 6. 方案 C「模板起步」入口（追加实现）

用户在方案 A 落地后追加要求：「方案 c 可以加一下」。实现为**新建流程的第一屏**，不是第三套表单。

### 6.1 流程

```
点「新建任务」 → 模板卡（5 个业务模板 + 「从空白开始」） → 落到方案 A 的两栏表单 → 保存
点「编辑」     → 直接进两栏表单（不进模板页）
```

`openCreateModal` 里 `showTemplatePicker = true`；`openEditModal` 里显式置 `false`（弹窗状态可能从上一次「新建」残留）；`closeEditModal` 统一关闭并复位（`@close` 与「取消」按钮都走它）。

### 6.2 模板内容

| 模板 | 时间 | 预填输出要求 |
| --- | --- | --- |
| 📊 每日 / 每周指标报表 | `0 8 * * *` | 无序列表、不要图表、两位小数 |
| 🚨 阈值巡检 / 告警 | `0 */1 * * *` | 异常前置加粗、正常一句话 |
| 📝 周期汇总简报 | `0 9 * * 1` | 三段结构、只写结论 |
| 🔍 失败盘点 / 质量复查 | `0 18 * * 5` | 按原因分组给条数与占比 |
| 🌤 外部信息巡检 | `30 7 * * *` | 三行以内、直接给结论 |

- **只预填，不锁字段**：四个字段（名称 / cron / 提示词 / 输出要求）写完即落到正常表单，全都能改。
- **占位符统一用 `【】`**：套用后 toast 提示「把【】里的内容换成你的对象就行」。留着不改也能保存，只是提示词里带【】。
- **cron 必须可回填**：五个表达式分别命中「每天 / 间隔(小时) / 每周」，落不到「高级」cron 模式；`applyTaskTemplate` 里调 `parseCronToUI` 同步人话控件，避免出现「控件显示每天、表达式是每周」的错位。
- **模板页不显示「确认保存」**（`v-if="!showTemplatePicker"`），避免没填就保存。

### 6.3 契约测试

新增 `tests/frontend/test_task_template_entry_contract.py`（5 个用例）：模板四件套齐全、cron 是标准 5 段且能回填人话模式、新建/编辑/关闭三处状态正确、模板页有「从空白开始」与【】提示、`applyTaskTemplate` 同时写 4 个字段并同步 cron 控件。
