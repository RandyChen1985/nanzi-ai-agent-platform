# MCP 五项问题修复设计

## 目标

修复 MCP 集成中已确认的五项问题：认证凭据暴露、连接失败缓存残留、SSE 工具调用恢复、嵌套 JSON Schema 丢失，以及工具结果非标准序列化和无上限输出。

本次不新增数据库字段、不执行数据迁移，并兼容已有 `auth_headers` 数据。

## 设计

### 1. 凭据保护

- `auth_headers` 写入时使用现有应用加密能力保存；读取时兼容历史明文值。
- MCP Server 列表和普通创建/更新响应不返回认证头原文。
- Authorization 改为独立的 MCP 级开关；开启时页面固定显示 `Bearer` 前缀，用户只填写 Token 内容。
- 其他 Header 与 Authorization 分区管理；编辑时已有值只显示 `********`，点击“编辑”后才能录入新值，更新请求提交增量或删除标记。
- 编辑表单不依赖接口回显旧凭据；未修改的凭据由后端保留，新填写的 Token 或 Header 才覆盖旧配置。
- 固定 Token 和静态 Header 均使用现有加密能力保存；读取时兼容历史明文值，不需要数据迁移。

### 2. 会话连接失败清理

`McpClientService.get_session()` 建立连接失败时，关闭当前会话并仅移除仍指向该对象的缓存项，避免并发请求误删后来建立的有效会话。补充连接失败后的缓存清理测试。

### 3. SSE 工具调用恢复

SSE `tools/call` 仅对连接/传输类异常执行一次关闭、重连和重试；MCP 返回的业务错误不重试。重试次数固定为一次，避免非幂等工具无限或重复执行。现有 `tools/list` 重连逻辑保持不变。

### 4. 原始 JSON Schema 保留

MCP 工具保留缓存中的原始参数 Schema，并让 MCP 工具的 OpenAI/AgentScope Schema 导出优先使用原始 Schema，保留嵌套对象、数组 items、required 和约束信息。动态 Pydantic 模型继续用于参数兼容和本地调用校验。

### 5. 工具结果序列化与截断

工具返回的字典、列表等结构化结果使用 `json.dumps(..., ensure_ascii=False, default=str)` 转换为合法 JSON 文本；字符串结果保持原样。统一应用现有工具上下文最大长度，并在截断时增加明确提示，避免超大远端结果无限进入模型上下文。

## 测试策略

- API/模型契约：确认响应不含凭据原文，更新未触碰认证字段时保持原配置。
- MCP 会话：确认连接失败会关闭并移除缓存对象；现有并发和 Direct HTTP 恢复测试继续通过。
- SSE：确认传输异常只重连一次，业务错误不重试。
- Schema：确认嵌套 object/array 原样出现在导出的工具 Schema 中。
- 结果：确认结构化结果为合法 JSON，超长结果被截断并带提示。
- 运行定向单元测试、前端类型检查和相关前端契约测试；不启动服务、不连接真实 MCP/数据库。

## 非目标

- 不实现 MCP Resources/Prompts。
- 不实现公共 MCP 挂载策略调整、模板市场、Schema 示例生成或测试历史。
- 不修改数据库结构、不执行迁移、不改变已有 MCP 工具命名规则。
