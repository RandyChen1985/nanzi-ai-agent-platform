2 分组往哪存：sys_mcp_servers 里没有能直接用的字段

现有字段 真实用途（读码与迁移注释得出） 谁在依赖 能不能当业务分组
remark VARCHAR(500) 自由备注，用户在新建向导里随手写的一句话，可空可重复。 服务卡片上 `line-clamp-2` 展示。 不行：自由文本不属于「枚举式归属」，用它当分组等于把备注当分类，改一次文案就换一次分组。
scope VARCHAR(20) global / personal——这条服务是平台共享的还是某个人的。 列表过滤、分享、绑定校验全在用。 不行：这是归属范围，不是业务域。混用会让「个人服务」和「平台服务」再也没法按同一个业务域聚合。
credential_mode / auth_headers / user_assertion_* 服务怎么认我们：静态 Token、凭据中心绑定、用户身份断言。 凭据面板、运行时注入。 不行：安全配置，与导航无关。
enabled_status / last_sync_at 运行状态与上次同步时间。 「仅运行中」筛选、排序、状态开关。 不行：这是状态，已经是筛选维度。
新增 group_name VARCHAR(64) NULL 这个服务属于哪个业务域（单值），只服务左栏页签与筛选，不参与权限、不影响运行时。 新加，没有历史包袱。 可以：与 tools.group_name / meta_datasets.group_name / ai_agents.group_name 同构，四处页签共用同一套组件与计数口径。

落地成本与前三处一样小：db-prod/V215 + db-prod-pg/V115 各一条 ALTER TABLE ... ADD COLUMN group_name VARCHAR(64) NULL，存量行落 NULL 按「未分组」统计，不需要回填。 设置入口两个：服务卡片「⋯ → 设置分组」、添加服务向导第一步。

为什么不能顺手复用现有的 PUT /api/portal/mcp/servers/{id}

那条接口是「编辑服务」的整表单保存，用它改分组会连带三件事：

  1. 整表单覆盖：server_name / sse_url 必填，前端每次都靠 buildServerPayload(server) 回传全部字段。前端少传一个字段就是一次静默清空（remark 就是因此才单独做了 model_fields_set 保护）。
  2. 改名会迁移工具引用：智能体是按工具名绑定的，服务改名时后端要同步改写引用。分组跟名字毫无关系，不该走进这条重活。
  3. 服务是启用状态时会触发一次 sync_tools：真的去外部拉工具列表并覆盖缓存。用户只是想归个类，不该顺手打一次远端。

所以照智能体中心的做法单开一个轻端点：PUT /api/portal/mcp/servers/{id}/group，只写 group_name 一列，返回持久化后的值。

推荐

  • 搜索行下面加一行分组页签（全部 / 各分组 / 未分组），溢出收进「更多分组 ▾」
  • 与工具注册表、元数据管理、技能工作台、智能体中心同一套组件与计数口径

B · 分组折叠清单

  • 把分组做成手风琴标题，一屏看到所有分组名 + 数量

  • 代价：展开/收起状态要记，搜索时分组结构会被打散；分组标题已表达归属，卡内徽标要关掉

  • 代价：与「我的 MCP」两栏形态分裂；改造面最大

6 需要你拍板的四件事

  1. 方案选哪个？建议 A（左栏分组页签）：与工具注册表 / 元数据管理 / 技能工作台 / 智能体中心完全一致，一套组件、一套计数口径。B 只在分组超过 15 个时才更优，C 留给「服务破百」。
  2. 分组存哪？建议新增 sys_mcp_servers.group_name（V215 / V115）。remark（自由备注）与 scope（全局/个人）都不能顶替。
  3. 右栏空态要不要改成分组分布 + 待办？建议要：这是全页最大的一块闲置面积，改成分布图 + 4 个可点待办，等于白送一个总览。
  4. 「我的 MCP」是否同一套？建议是：同组件同分组，但页签数字只算当前 scope（个人服务与平台服务不混成一个分组计数）。另外「我的 MCP」左栏已可折叠，分组页签跟着一起收。

若按建议全做，本期范围是：V215/V115 迁移 专用 PUT /mcp/servers/{id}/group 左栏分组页签 卡片分组徽标 右栏空态概览 密度切换； 批量操作与键盘切换列为下一步。
