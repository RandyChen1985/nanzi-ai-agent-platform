智能体中心 · UI / UX 优化 对照原型：可切视图 / 可筛选 / 可点卡片
现状 当前实现 页头 4 行 + 常驻 5 步指引 + 两条警示 + 筛选 chips；每张卡片最多 15 个视觉信号。 （打开标注可对照下方 6 条问题）

逐条问题（对应页面上的红色编号）

  1. 页头与横幅吃掉首屏。标题行 + 搜索行 + 筛选 chips + 孤儿提示 + 配置异常 + 5 步指引（常驻、默认展开）合计约 420px，12 个智能体在 1440×900 下首屏只能看到第一行卡片的一半。
  2. 两条警示与筛选 chips 无归属。「权属人已停用」「配置异常」都只在有问题时出现，但和「已筛选」混在同一竖列，用户分不清哪条是全局状态、哪条是自己刚点的筛选。
  3. 卡片信号过载。色条、头像、系统徽标、类型·引擎、就绪度、启用开关、描述、待完善、工具/MCP/技能/数据集/知识库/调用次数、冻结条、基线说明、创建者、更新时间、主按钮——同一张卡 15 个信号，扫读时无法排序注意力。
  4. 同一件事说三遍。「就绪度小圆点 = 尚未就绪」+ 描述下方「待完善：未绑定知识库、未发布版本」+ 主按钮变成橙色「完善配置」，三处都在表达「这个不能跑」。
  5. 主按钮语义不稳定。按状态在「配置与发布 / 完善配置 / 继续配置 / 启用 / 复制一份」之间跳，颜色还有蓝 / 橙 / 绿 / 白四套；用户每次都要重新读一遍按钮在说什么。
  6. 没有排序与分组，治理无入口。顶部只有「共 12 个」，没有「几个能跑、几个待修、几个在审核」的分布；管理员想先处理异常，只能一张张翻。
方案 A · 已落地 页头减重 页头两行 + 状态摘要；5 步指引改为按需展开；两条警示合并为一条「待处理」；卡片去掉色条与三枚彩色 pill，状态收成一行，主按钮统一「配置与发布」。 取舍：不动信息架构、不新增筛选维度；「先处理谁」靠状态摘要 + 合并提示，不再靠满屏颜色。
方案 B 治理视图 状态优先：指标条回答「平台现在什么情况」，分组回答「先看谁」，卡片只保留 6 个信号，异常统一收敛成一条「去修复」。 取舍：多一层分组与排序（纯前端可算），换来 20+ 智能体时仍然能一眼定位问题。
方案 A+ · 已落地 专家团 tab 团 = 主专家 + 它的 sub_agent_call 调度范围；列表页多一个 tab，进去是「团」而不是「单个智能体」。 取舍：子专家不在新页面维护，直接复用调度白名单——一个真相，两个视图。
落地对照（2026-11-03） 实现与这份原型的差异都记在这里，不另开文件

✓ 已按原型实现

tab 数字混合策略（「全部 / 我的」不带，分享类 >0 才显示，专家团常显）； 团卡片展开 / 收起与成员明细（主专家排第一，带主专家 / 子专家与未发布标签）； 抽屉里 TEAM 与 MAIN / SYS 正交、独立判断； 委派白名单里团主专家置灰 + 「改用这 N 位成员」。

⚠ 实现时改了

健康度 4 档 → 6 档：新增「未发布」「待配置」。成员取自已发布版本的调度范围， 没发布等于没配，只报「可用 / 部分可用」会把这种情况藏起来。
编辑入口：原型是「编辑页新增页签」，实现为列表页直接打开的独立弹窗 （团信息是智能体级元数据，不该混在版本编辑流程里）；基本信息表单里另留同名区块，供新建时一次填完。
配置调度范围：原型直接开白名单弹窗，实现是打开「配置与发布」抽屉 + 一句指引—— 调度范围存的是 versionForm.tools，离开版本编辑上下文没有地方可存。
卡片按钮：合并成底部一行三个（配置调度范围 / 编辑专家团 / 进入团队对话）； 原型把「配置」放在展开区里，收起时找不到入口。

⬜ 未实现

子专家卡片上的「🔗 被 N 个专家团引用」：反向引用要扫全部团的调度范围， 列表接口拿不到这个信息，先不做。不显示也能用，代价只是改子专家前不知道会影响谁。

＋ 原型没有、实现补了

会话头部：进对话后标题旁也标 👥 TEAM， 否则用户以为自己在跟一个普通专家聊。
抽屉副标题：团主专家那行第二行直接显示「团名 · N 位子专家」， 只给一枚徽标还是不知道是哪个团、有几个成员。
团介绍注入提示词：原型把它定位成纯展示文案，实现里还会作为「你的团队」段 进团主专家自己的系统提示词（流程约束 + 被委派时的委派边界声明）； 父级路由上下文仍只看 description，否则介绍里的「先找谁」会把主助手带偏。
