日期标签规则（三方案一致）

  • 今天 → 今天；昨天 → 昨天
  • 同年 → 11月24日 + 星期在右侧小字
  • 跨年 → 2025年12月30日，避免「12月30日」误读成今年
  • 排序：按 at 倒序分组；组内沿用现有 at / requested_at / reviewed_at 三级时间显示

版本号在组头上的规则

  • 只统计带版本号的记录：启用状态变更 / 变更权属人 / 分享类是会话级或账号级动作，没有版本，不参与汇总
  • 按版本号升序去重，最多显示 3 个，多余的折叠成 +N
  • 跨年 / 跨天不影响版本表达：同一天既有 v4 申请又有 v4 发布，只出现一次
  • 只有一条记录且无版本时（如 11月10日 的权属变更），组头不出现版本 chip，不留空位

为什么不做「日期 → 版本」二级分组

  • 版本不是稳定的分组维度：同一天会连续发多个版本（11/24 一天内 v3、v4、v5），会切出一堆只剩 1 条的残组
  • 同一个版本的完整故事（申请 → 审核通过 → 发布）往往跨天，按版本分组反而把它拆散
  • 版本更适合做成筛选器：工具条加一个「全部版本 / v6 / v5 …」下拉，选中即只留涉及该版本的记录，跨天串成一条版本线

折叠交互约定（建议）

  • 组头整行可点（尺寸 ≥ 44px 高），右侧箭头 90° 旋转表示展开
  • 折叠只隐内容，不动竖线：每组时间线独立，收起后不留断头线
  • 「全部展开 / 全部收起」放工具条，跟着当前分组状态走
  • 展开状态记 sessionStorage，同一次会话内重开抽屉保持
  • 事件行里的「查看内容快照」与分组折叠互不影响

推荐方案 B

  • 理由：抽屉高度有限、历史最多 100 条，全展开（A）还是要长滚动；C 的组头摘要要多算一次、且值类型多（申请/事件混排）容易误导
  • B 的做法：默认只展开最近 1 组，其余折叠但显示「N 条 · 最近一条是 X」
  • 组头：日期 + 条数 + 版本 chip + 「最近一条是 X」，折叠时这四样都留着
  • 改动面：只动 AgentSystemHistoryDrawer.vue 一个文件，加两个纯函数 groupEntriesByDay() / versionsOf()（可单测）+ 组头模板
  • 后端无需改动：现有接口已按 at 倒序返回全量（page_size=100）
