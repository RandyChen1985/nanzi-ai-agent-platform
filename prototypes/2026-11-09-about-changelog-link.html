关于面板 · 更新日志入口

把「更新日志：后续版本提供。」换成真实链接。规则：版本号去掉 v 前缀，四段的 1.0.22.0 去掉最后一段构建号得到 1.0.22，再拼到 Releases tag 地址上。 下面四种入口形态，都是这块面板内可直接落地的写法。

01链接规则四段去掉构建号，三段原样

v1.0.22.0 — 去掉 v 与最后一段构建号 → 1.0.22 + …/releases/tag/ = …/releases/tag/1.0.22
taghttps://github.com/RandyChen1985/nanzi-ai-agent-platform/releases/tag/1.0.22

⚠️链接文字里带版本号会略长，英文界面下要确认不换行。
看 Vue 写法 
<!-- AccountMenu.vue：替换现有最后一行的 <p> -->
<p class="mt-0.5">
  更新日志：
  <a v-if="changelogUrl"
     :href="changelogUrl" target="_blank" rel="noopener noreferrer"
     class="font-medium underline underline-offset-2"
     :class="lightTheme ? 'text-primary' : 'text-blue-300'"
  >{{ changelogTag }} ↗</a>
  <span v-else class="opacity-80">后续版本提供。</span>
</p>

// 两个 computed，四种形态共用
const changelogTag = computed(() => {
  const raw = props.version.replace(/^v/i, '').trim()
  if (!raw || /^dev/i.test(raw)) return ''
  const parts = raw.split('.')
  if (parts.length < 2) return ''
  // 1.0.22.0 的第 4 段是构建号，tag 只到三段
  return (parts.length > 3 ? parts.slice(0, 3) : parts).join('.')
})
const changelogUrl = computed(() =>
  changelogTag.value && props.repoUrl
    ? `${props.repoUrl.replace(/\/$/, '')}/releases/tag/${changelogTag.value}`
    : ''
)

03边界情况这些输入都会遇到

版本号输入推导 tag行为
v1.0.22.01.0.22显示链接 —— 常规发版，四段去掉构建号 .0
1.0.221.0.22显示链接 —— 本来就是三段，原样用
v1.0.21.01.0.21显示链接 —— 历史版本同样成立
v1.0.22.3（hotfix）1.0.22显示链接 —— 构建号变化不影响 tag
dev / dev build—不显示链接 —— 回退为「开发版本，无更新日志」
v1.0（只有两段）1.0显示链接 —— 段数不足三段时原样拼
空字符串 / 单段 7—不显示链接 —— 段数不足，安全回退
品牌定制 hide_version_link—整块隐藏 —— 与「代码仓库」一致，白标部署时不外链
tag 未发布（404）1.0.22链接照旧显示 —— 打开是 GitHub 404 页，发版前可接受
