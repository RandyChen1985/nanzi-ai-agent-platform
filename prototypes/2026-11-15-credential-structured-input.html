凭证录入 · 结构化 JSON 与内置模板编辑

现状：「凭据值」是一个自由文本框（截图里标红箭头的位置），粘贴什么就存什么，用户得自己记住格式。 这里把录入改成两档：自由输入（原样保留）＋结构化模板（选模板 → 渲染可视化字段 → 自动拼成 JSON）。 入库仍然是 JSON 文本，加密、脱敏、审计链路一行不动。

1只改「录入方式」，不改「存储契约」 结构化视图只是把字段拼成 JSON 文本，落库还是 value 这一个字段（加密后）。旧的自由文本记录 value_format=text，新建结构化记录 value_format=json＋value_template，两条路共存，不做数据回填。
2模板是「录入期的渲染骨架」 模板定义（字段、类型、必填、默认值）只活在前端，后端只校验「合法 JSON」。模板升级不会追溯老记录，也不会因为模板变了把用户已存的凭据读不出来。
3结构化 ≠ 可见化 字段标了 secret（密码/私钥/AK）依然整段加密、建完不可读；只有非敏感字段（host/port/用户名）能在列表里做「摘要展示」。这条要在模板定义里显式声明，不能自动猜。

A存储形态：字符串 → JSON 文本

加密链路、value_masked、审计、轮换全部不变，只多了两个描述性字段。

# 现状：value 就是一串字符
secret.value      = "ghp_9f2c...e41"          # 加密后
secret.value_format = —（没有这个概念）

# 结构化后：value 是 JSON 序列化结果，仍然一列
secret.value      = '{"host":"smtp.exmail.qq.com",
                    "port":465,"security":"ssl",
                    "username":"alert-bot@nanzi.ai",
                    "password":"…"}'
secret.value_format   = "json"      # text | json
secret.value_template = "smtp"      # 模板标识，仅用于回显
secret.value_schema   = 1           # 模板版本

B取用语法：多一层「字段」

后端 ${secret:x} 解析已有；结构化后需要支持点号取子字段，否则工具只能拿到整段 JSON 字符串。

# 整段（兼容旧写法，拿到 JSON 字符串）
Authorization: Bearer ${secret:mail.smtp}       ✗ 会带上花括号

# 取子字段（新增）
header  X-SMTP-Host = ${secret:mail.smtp.host}
param   password    = ${secret:mail.smtp.password}

# 兜底写法：解析后取值，取不到则原样
${secret:mail.smtp:json.host}

待定 非 JSON 的旧记录遇到点号引用时，建议解析失败即报错，不要静默回退成整串——否则密码会以 JSON 原文注入到请求头里，排查起来极其难受。

C列表摘要：preview 不能再取「前 8 个字符」

现在变量类型会存 value[:8] 做预览。JSON 化之后前 8 个字符就是 {"host":，等于没信息。

# 现状
preview = value[:8]              → '{"host":'

# 结构化后：只拼非敏感字段
preview = "smtp.exmail.qq.com:465 · alert-bot"
# 生成规则：模板里 secret:false 的字段，按 display 顺序取前 2 个

前提：模板定义里必须显式标注哪些字段敏感（secret:true），后端才知道能摘什么。 这条与「凭证建完不可读」不冲突——摘要里只有 host / 用户名这类本来就会出现在报错日志里的东西。

D轮换与编辑

  • 轮换值：不能回显原文，所以仍然是从空表单重填；但会带上模板，字段名对得上，比重新粘贴 JSON 省事。
  • 改元数据（名称 / 场景 / 域名白名单）：完全不受影响，走现有 PATCH /api/portal/secrets/:id。
  • 换模板：只在录入期允许。建完之后不允许换模板（字段结构一变，绑定的注入点就全错了），要换就新建 + 重新绑定。
  • 后端校验：只校验 value_format=json 时能否 json.loads，不校验 schema。模板升级、字段增删都不会让老记录打不开。

需要你拍板的 4 件事（确认后我再动实现）

  1. 模板定义放哪：纯前端常量（改模板要发版）／后端下发（可运行时加模板，但要新接口 + 缓存）。原型按「前端常量 + 后端存 template 标识」写的。
  2. 是否要子字段引用语法（${secret:mail.smtp.host}）。不做的话，结构化录入只是「好看」，工具侧还是得自己 JSON.parse。
  3. 凭证类型要不要也存摘要。现在 credential 一律 ********；如果同意只摘非敏感字段，列表可读性会明显提升。
  4. 「高级 JSON 直编」要不要开。开了对老手友好（粘一大段现成 config），但校验责任就回到用户身上；原型里放在「自定义 JSON」模板下。
