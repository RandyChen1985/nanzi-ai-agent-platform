怎么看这四列

  • 先把视线放到最后一行「进行中」：A 里它和上面七个点一样重，你得靠转圈的图标才能找到「现在跑到哪」；B/C/D 里它是全屏唯一的蓝点，而且线在那里渐隐——不用读字就知道进度到这儿为止。
  • 为什么用蓝而不是更亮的灰：只靠灰度时，完成态和进行态只差 1.6~3 倍，截个图或开了「减少动态效果」就分不出来。行内的状态点本来就是 #0ea5e9，轨道点用同一个色是呼应同一个语义，不算多一种颜色。
  • 再看左侧那条线：A 的线从头画到尾，中间跨过旁白、工具子层，其实没表达任何分组；C/D 断成三段，准备 / 拉取 / 统计 的边界自己就浮出来了。
  • 最后数行数：A/C 是 8 行，D 是 6 行。用户在长过程里最先感到累的是行数，不是灰度——这也是为什么 D 的观感提升最大。
  • 点「深色主题」再看一遍：C/D 的分段在深底上差距比浅色更明显，A 的贯穿线在深底会糊成一整条。

实现代价

  • B（低）：模板里已有 status，加 done / running 两个 class 分支即可，样式只改 --w 变量值。
  • C（中）：要在渲染前算分组边界——按「同一层级的连续同类项 + 有子项的旁白自成一组」切。逻辑放 processTimeline.ts 里可单测。
  • D（中）：折叠复用已有的准备阶段合并逻辑，只是把阈值从「毫秒级」定得更明确：同一阶段且单项 < 500ms 的连续项合成一行。
  • 四条都不动数据结构，只动渲染与样式，回滚容易。

还没画的备选

  • hover 点亮：静止再压淡一档，鼠标停到哪行哪行恢复。原型里 A/B 两列的样式已经埋了 .hoverlit，想试可以在控制台给 .rail 加上这个类。
  • 轨道承载耗时：线段长度或节点大小反映真实耗时，能一眼看出瓶颈。但毫秒与秒差三个数量级，要取对数或分段，容易失真，我先没放进对比。
