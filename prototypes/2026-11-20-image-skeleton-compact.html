现状：能适配，但太高、太窄

  • 宽 420 上限：桌面气泡内还有 200+px 空白，骨架像贴在左边的方块。
  • 高 420：占掉近半屏，下面的输入框和后续文字被顶走。
  • 比成品还大：成品最高 320px，骨架 420px，图出来时要缩一下——观感是「画面塌了一下」。
  • 移动端：宽度跟着气泡收（✓），但方形/竖图仍高 300px 上下，靠 60vh 才不会溢出屏幕。

顺带一个真相：改图（edit_image）没传 size 时后端才「跟随原图比例」，前端拿不到原图比例，兜底画的是方形——所以「比例必须一致」这条契约现在只是尽力而为，并非保证。

V1 矮横幅 + 幽灵框推荐

  • 高度 −69%：420 → 132px；宽度 +33%：420 → 560px 上限，桌面气泡基本铺满。
  • 信息没丢：阶段 + 尺寸/张数 + 秒表原样保留，另外用幽灵框把「目标比例」可视化。
  • 比例未知时说真话：虚线框里写「?」，而不是画个方形让用户以为要出方图。
  • 移动端更稳：高度用 clamp(104px, 28vw, 132px)，不再依赖 60vh；宽度 100% 自动收。
  • 汇聚环按短边取半径，在矮横幅里集中在中间一段，视觉仍是「散点往中间收」。

代价：框不再与成品同比例，图落地时会有一次「长出来」的变化（小→大，方向是自然的）。需要同步改一条契约测试：现在钉着「骨架必须按 size 定高 + 必带 60vh」。

最省事的做法：只把尺寸算式换掉，文案位置、徽标、点阵动画全不动。

V2 纯矮横幅

  • 实现只有一条：width: min(100%, 560px); height: clamp(104px, 28vw, 120px)，删掉 aspect-ratio 与 60vh。
  • 文案仍挤在左上角、点阵会从字后面穿过——宽了之后这份拥挤更明显。
  • 没有任何比例提示：竖图横图看起来一模一样，用户只能从下面那行「928x1664」去读数字。

什么时候选它：只想快点把高度降下来，不想动文案排版和契约测试的量。

「保持比例、只缩小」——它会同时满足高度减半，但做不到宽度增加，列出来是为了把取舍摆明。

V3 保比例缩小

  • 高度减半 ✓，但宽度跟着缩水：竖图只剩 133px（桌面），比现在的 420 窄了三倍多。
  • 框和成品同比例，图落地时不会跳——这是它唯一比 V1 强的地方。
  • 和成品尺寸仍不一致（成品 320 高），所以「不跳」本来也只是近似。

结论：「高度减半」和「宽度增加」在「框=图同比例」这个前提下数学上矛盾，必须二选一。你要的是窄高变矮宽，那就得放开比例锁定。
