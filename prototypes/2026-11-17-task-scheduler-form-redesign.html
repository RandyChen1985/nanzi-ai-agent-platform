任务中心 · 新建 / 编辑定时任务

整页重设计：把「8 个平铺字段」拆成「意图 → 时间 → 交付」

现在这一个弹窗里塞了 8 段：任务名称、执行大脑、执行计划、执行失败策略、要做什么、输出有什么要求、结果通知、保存。 它们机会均等地从上排到下，用户保存前没有任何地方能一眼复核「这个任务到底会在什么时候、对谁、做什么、发到哪」。 下面三套重设计按改造强度递增，都能在一个 HTML 里点开对比。

问题 1

没有复核面

意图散落在 6 个字段里（时间在 cron、对象在提示词、格式在约束、去向在通知），保存前无法用一句话确认。

问题 2

时间表达门槛高

核心输入是 cron 表达式，靠 `Auto-Translate` 回译成中文。只说「每周一 8 点」，得先学会 `0 8 * * 1`。

问题 3

没有下次运行时间

只有文字翻译，没有具体日期。用户无法确认「我是不是填成了下周一还是本周一」。

问题 4

低频项占着前排

重试次数 / 间隔与通知、提示词同级平铺，把「要做什么」这个真正的重心挤到弹窗中部。

方案 A 的四个关键动作

  • 把「意图」排在第一位：名称 → 谁执行 → 要做什么 → 输出要求，四段连成「做什么」，不再是 8 段里的一段。
  • 时间从 cron 变成人话选择器：频率 / 时间 / 星期三个控件，cron 只作为「高级」旁注展示；要改表达式仍可点开。
  • 右侧粘性摘要：一句话拼出「什么时候 / 谁 / 做什么 / 什么格式 / 发到哪」，并给出具体下次运行时间与批准模式的风险提示。
  • 重试策略折叠：低频技术项收进「执行失败怎么办」，默认收起，需要时才展开。

代价：弹窗从单列变两栏，窄屏（<1100px）要退回单列并把摘要移到顶部一条通栏，或收成「查看任务摘要」抽屉。

方案 B 的取舍

  • 一屏一个问题：首次创建的用户不会被 8 段表单吓退，每步都有「为什么问这个」的一句话。
  • 时间步给出三次真实运行时间：比 cron 回译更能防止「周四 / 周五」选错。
  • 第 4 步是纯确认页：一句话复述 + 关键项表格 + 试跑，替代现在的「8 段表单再读一遍」。
  • 代价：编辑已有任务时不能直接改，需要点「跳到第 2 步」之类的快捷入口；熟练用户会觉得多点了几次。

方案 C · 先选模板，再改具体对象

大多数定时任务都属于下面几类。选一个，时间、提示词、输出要求、通知都会预填，你只需要改对象和时间。

选「每日 / 每周指标报表」后，会预填成这样：

要做什么：查 ____（对象） 在 ____（时间范围） 的 ____（指标），给出核心结论与关键数据。
输出要求：用无序列表，不要图表；金额统一按万元（可删改）
时间：每天 08:00　·　通知：站内消息

模板只是预填，保存前每一栏都可以改

方案 C 适合解决什么

  • 「不知道该填什么」的根问题：用户不会写提示词，但会认「我要一份日报」。模板把提示词、约束、cron、通知一次性给到位。
  • 和方案 A 不冲突：模板选完落到 A 的两栏编辑界面，「从空白开始」也进 A。C 更像 A 的入口页，而不是第三套表单。
  • 代价：模板内容要有人维护（提示词质量直接决定任务质量）；模板分类过细会变成新的选择负担，建议只保留 4–6 个。

三方案对比

按「改造成本 / 解决什么 / 是否伤熟练用户」排
维度方案 A · 两栏 + 摘要方案 B · 三步向导方案 C · 模板起步
解决的核心问题没有复核面、时间门槛高、低频项占前排首次创建时的信息过载不知道提示词该写什么
前端改造量中：表单重排 + 摘要组件 + 人话调度器大：分步状态机 + 4 个面板 + 回填小：一个入口页 + 模板常量
熟练用户的感受更好：信息密度更高、少滚动变慢：每次都要点下一步更快：直接套模板
编辑已有任务天然支持，直接改需要「跳到某一步」的快捷入口不适用（只在新建时出现）
窄屏 / 移动端摘要需改成顶部通栏或抽屉天然适合：一屏一个问题模板卡两列即可
风险摘要句子由前端拼，措辞要和后端真实行为一致步骤间来回跳转易丢焦点，需保留草稿模板维护成本、模板与平台规范可能打架

我的建议：A 为主体，C 作入口，B 的「三次运行时间」并进 A

  • 主结构用 A：两栏 + 实时摘要，是唯一同时改善「新建」和「编辑」的方案，也不需要把现有字段重做成状态机。
  • 入口加 C 的模板卡：新建时先给 4–6 个模板，选完落到 A；这对「不知道该填什么」的收益最大，成本最小。
  • 把 B 的两次借鉴搬过来：① 时间选择器下方直接给接下来三次运行时间；② 保存前给一张一句话复述 + 关键项表格（A 的右侧摘要已经承担了这个职责）。
  • B 整页向导暂不做：编辑场景要额外做跳转与草稿保存，而收益主要集中在首次创建，性价比不如 A + C 组合。

落地顺序建议：① 先做 A 的「人话时间选择器 + 下次/后三次运行时间」（改动最小、见效最快，且不依赖布局调整）； ② 再做 A 的右侧摘要；③ 最后加 C 的模板入口。①单独做也是完整可交付的一步。
