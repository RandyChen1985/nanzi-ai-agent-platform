原型 · 参数设置

单值凭据 / 多值凭据，拆成两个 tab

两种配法的思维模型根本不同：单值凭据是「一个参数配一条凭据」，多值凭据是「一条凭据供一组参数」。 混在同一张表里，多值那半只能靠额外弹窗补救——用户得先点一次「按凭据批量配置」，才能看到字段映射。 拆开之后，选凭据和分字段在同一个面上完成。

单值凭据

一个参数一条绑定

模型填写 / 固定凭据 / 按规则，逐个参数配。今天的样子，逻辑不动。

多值凭据

一条凭据分给多个参数

先选一条结构化凭据，再把它的字段分给表中各参数。落库仍是「每个参数一条固定绑定」，只是换了个填写顺序。

两者不是两份数据

同一张 sys_secret_bindings

tab 只是同一批记录的两种看法。多值 tab 配完，切回单值 tab 也能看见、也能改。

两个 tab 背后是同一份数据

    
这一层必须讲清，否则实现时最容易被做成「两套配置各存一份」，然后谁也说不清哪个生效。


    

      

        
场景单值 tab 显示多值 tab 显示

        
          

            参数 A 绑了单值凭据
            固定凭据 · 凭据名
            灰显「已用单值凭据」，不参与映射
          

          

            参数 A 绑了结构化凭据的某个字段
            结构化 · 模板名 · 取 password

            4 行，各自显示固定凭据 + 字段
            一处集中展示
          

          

            清空某个参数的映射
            该行回到「模型填写」
            同一件事，只是在这里点的
          

        
      

    


    

      
已定 ①：多值 tab 用「按规则」时，规则就是单值页那条规则

      

        不多引入任何概念——规则仍是「按身份挑一条凭据」，只是这里每个参数多了「取哪个字段」。
        落库是每参数一条规则绑定：规则 JSON 相同、value_path 各自不同。
        运行时逐槽位求值，规则确定性 + 同一次调用身份不变 → 各槽位必然命中同一条凭据，
        只是各取不同字段；解密有 per-call 缓存，只解一次。
      

    


    

      
已定 ②：没参与映射的参数 = 模型填写

      

        多值 tab 保存是整页覆盖：选中的参数绑凭据，没选的一律回到「模型填写」。
        「这张表就是这个工具的参数配置」比「只改动过的」更符合这里的心理模型。
        实现上没选的那行提交 strategy: "none"，由后端把固定绑定与规则绑定两条都清掉——
        只清一条，另一条还会继续生效。
      

    


    

      
已定 ③：单值页已配的参数，切到多值 tab 要提示

      

        多值页顶部给一条琥珀色提示：「这些参数在单值凭据页已经配了凭据，本页保存会把它们改回模型填写」，
        并逐条点名。只提示，不自动改写——真要覆盖由人在多值页里显式选。
