诉求：元数据管理（数据集）也支持业务分组——新建/编辑能填、顶部能按它筛、页面能按分组多 Tab，搜索也要能配合分组。 先说结论：数据集页现在已有搜索（名称 / ID / 描述）与「状态」筛选，卡片上还挂着业务标签； 但数据库里没有分组字段（meta_datasets 只有 tags）。所以这次的核心不是画页签，而是先回答 「分组和已有的业务标签是什么关系」——标签是多值、还会进 AI 提示词；页签需要单值归属。 下面三个方案的差别全在这一点上，页面里的数据与控件都点得动。

关键分歧：分组 ≠ 标签

标签多值、一个数据集可挂多个，还进提示词；页签要的是单值归属。直接拿标签当页签会出现「一个数据集出现在 3 个页签、计数相加大于总数」。

适合「分组只是偶尔用来收窄范围」的场景；你的诉求是「多 Tab 浏览」，C 差一截。

顺带修的：新建 / 编辑弹窗太高，底部按钮看不到

你截图里的问题是两层叠加：① 6 个字段全竖排（每行一个，天然就高）；② 弹窗是「垂直居中 + overflow:hidden」—— 内容一旦比视口高，上下会被同时裁掉且无法滚动，所以底部按钮不是「要滚一下」而是彻底点不到。 只缩字段不改第 ② 点，换个矮屏幕（笔记本 768px）照样会复发。

  • 字段两列并排：物理名称 ↔ 显示名称、业务分组 ↔ 业务标签；数据源 ID 与描述仍占整行（一个带下拉按钮，一个是多行文本）。
  • 弹窗限高 + body 内滚动：容器 max-h-[calc(100vh-2rem)] + flex flex-col，中间区 overflow-y-auto，头尾 shrink-0。按钮从此永远在视口里，矮屏幕也一样。
  • 窄屏回单列：grid-cols-1 sm:grid-cols-2，手机/窄窗不会把两列挤成细条。
  • 弹窗加宽 max-w-lg → max-w-2xl：两列才不憋屈，输入框不至于只剩半截。
  • 描述从 3 行降到 2 行并挪到最后（次要信息，而且它最容易把弹窗顶高）。
  • 数据源 ID 改成只能选、不能手输（见上：右侧已无输入框，只有一个下拉）。手输一个拼错的名字不会报错，只会在真正查数时连不上；存量数据集若带着「未在数据源管理登记」的值，该值仍原样留在选项里，避免打开弹窗一保存就把配置清掉。
  • 外层允许滚动 items-start sm:items-center + overflow-y-auto：极端情况（超小屏 + 长标签）仍能滚到按钮，不会再出现「整块被裁」。新建与编辑两个弹窗一起改。

需要你拍板 4 件事

  1. 分组是新增单值字段，还是复用现有业务标签？ 建议：新增 group_name（方案 A），标签继续管「AI 选库的多维度打标」，两者分工不同。
  2. 分组要不要也写进 AI 提示词？ 建议：不写——数据集目录里已经带着标签（[财务, 核心]），再加分组会让同一件事说两遍、还会占上下文。若确实需要 AI 按业务域理解，把分组加进「已授权数据集目录」那一行的前缀比新增字段更省。这条影响 ChatBI 行为，需要你确认。
  3. 分组名允许自由输入还是受控字典？ 建议：本次自由输入 + 已有分组候选（datalist），与 API 工具页保持一致；近义组合并留给后续「分组管理」。
  4. 页签在「卡片视图」和「列表视图」都常驻吗？ 建议：都常驻，两种视图共用同一个 groupFilter，切视图不会把筛选丢了。
