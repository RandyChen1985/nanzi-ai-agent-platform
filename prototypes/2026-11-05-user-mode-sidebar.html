二、实现要点

1. 菜单写死，权限决定「置灰」还是「隐藏」

新增 userModeMenu.ts 常量数组（不请求 nav 接口）。知识库没权限时保留位置并置灰，点击提示联系管理员（用户能知道有这么个能力）；其余入口没权限直接不渲染。工作空间按用户自己的目录，不需要权限。专家 / 技能 / 连接器在用户模式下不挂菜单权限（浏览性质，数据边界在页面内），专业模式仍按 menu:* 控制。

2. 模式存 Redis，默认值写死

用户偏好写 Redis（portal:ui_mode:{user_id}），登录后随 /me 下发；本机 localStorage 只做加载前的乐观值。默认值不做系统配置项：管理员 = 专业模式，其他 = 用户模式。

3. 切换入口：个人中心（正式）+「更多」快捷

EmbedChat 不做模式切换（嵌入场景没有门户侧栏，切了也看不到变化）。侧栏「更多」里的快捷切换只是同一入口的快捷方式。

4. 路由和守卫不动

用户模式只是「另一种侧栏」，页面、meta.perm、落地页逻辑全部保持原样。切模式不触发重新登录，也不改 URL。

5. 「任务（n）」就是历史会话

沿用 /api/chat/history：计数取会话总数，列表显示最近 6 条，底部「查看全部会话」进完整历史。点开走 conversation_id；hover 的「⋯」保留重命名 / 置顶 / 分享 / 删除。

6. 专业模式回到动态菜单

专业模式继续走 useNavigation() 的动态渲染，一份代码两个视图，可以按角色灰度。

7. 顶栏去掉，动作下移，默认亮色

用户模式不再渲染右侧顶栏（面包屑 + 在线人数 + 通知 + 主题 + 退出），页面直接从标题开始；通知角标、深浅色、退出收进侧栏底部用户卡，省下的高度与宽度都还给内容。主题默认亮色——简化布局是白底 + 灰底的层级，深色下反而糊在一起；切回专业模式时再回到深色。

8. 旧链接不破

老菜单里的「技能工作台 / 知识库管理」等深链仍可直接打开；用户模式只是少入口，不做重定向。

三、已定方案

设计上已确认

  • 不做「助理」入口
  • EmbedChat 不做模式切换
  • 模式存 Redis，下次进入生效
  • 默认值写死：普通用户 = 用户模式，管理员 = 专业模式
  • 知识库无权限 → 置灰 + 提示联系管理员
  • 定时任务只显示自己的任务，不需要权限
  • 「更多」去掉我的记忆与系统管理，新增系统概览（跳 /dashboard）
  • 移动端默认用户模式，用户可自行切换
  • 个人中心入口用方案 B（左侧「界面偏好」），不占用 tab 行
  • 子菜单展开时父项不加高亮，只高亮子项
  • 方案 C（「更多」里的快捷切换）一起做，作为补充入口
  • 「专家 / 技能 / 连接器」措辞不变
  • 用户模式隐藏右侧顶栏（面包屑那一行）
  • 通知 / 主题切换 / 退出收进左下角用户卡
  • 进入用户模式默认亮色、切回专业模式默认深色（之后手动切主题不会被覆盖）

建议实现顺序

  • 1. 侧栏视图：userModeMenu.ts 常量 + 用户模式侧栏组件（含任务列表）
  • 2. 模式存取：Redis 读写 + /me 下发 + 前端切换
  • 3. 个人中心入口：方案 A 分段控件
  • 4. 快捷入口：侧栏「更多 → 切换到专业模式」
  • 5. 权限态：知识库置灰、定时任务按本人过滤、工作空间按本人目录
