元数据管理

3 个数据集

维护 ChatBI 查数依赖的表结构语义、表关系与指标口径；支持从已有数据集复制新建。

保存时怎么写「初始化变更日志」，以及接口怎么设计

1前端落点

  • 入口：MetadataDatasets.vue 卡片菜单与列表菜单各加一项，权限 element:metadata:edit。
  • 组件：新增 CopyDatasetWizard.vue，草稿态在组件内维护，关闭即丢弃。
  • 查重：输入防抖 350ms 调 check-unique，返回前显示「校验中」，冲突时给推荐 ID 一键替换。
  • 数据源：下拉数据来自 GET /metadata/db-connections，只传 name，不提供自由输入；不可用的连接置灰。
  • 保存：只在第 6 步发一次 clone 请求，进度按后端返回的阶段推进。

2后端契约

  • GET /metadata/datasets/check-unique?name=&display_name= → {name:{available,reason}, display_name:{…}}
  • POST /metadata/datasets/{source_id}/clone，body 带 name / display_name / copy_options / overrides。
  • data_source 必须是 db_connection_configs.name 里的值（不存在 → 400），不信任前端传任意字符串。
  • 单事务：唯一校验(409) → 建数据集 → 批量插表与字段 → 按 旧表ID→新表ID 映射重写关系 → 插指标 → 写日志 → 提交。
  • 服务层放 metadata_clone_service.py；冲突返回 409，其余异常整体回滚，不留半成品数据集。

3关键取舍

  • 权限策略默认不复制：行级过滤常绑定具体人员/部门，复制后容易越权，改为可选并给出警示。
  • 质量分不复制：属于源数据集的巡检结果，新数据集置空，等下一轮巡检重新打分。
  • RAG 状态重置：新数据集 rag_sync_status=0，不影响源数据集的同步状态。
  • 日志粒度可选：默认「汇总+明细」共 N 条，表特别多时可切成只写 1 条汇总，避免日志被刷屏。
  • 规模上限：超过 200 张表建议走异步任务，同步接口先返回任务 ID。
