P0 复刻参考

  • 点阵间距 14px、点径 1px；亮的点 1.15px 且不透明度 0.95——靠点的粗细与浓淡差形成层次，不靠底色。
  • 三圈波纹差 1s / 2s 错开，从 scale .16 扩散到 1.55 并淡出，看起来像波在点阵里连续推出去。
  • 文字在框内左上、徽标在右下，中间完全留给视觉，没有卡片、没有描边。

问题：百分比是假的。后端目前只有阶段文案，没有真实进度上报，写「24%」就是我们一直拒绝的假进度。 视觉照抄没问题，数字要换成下面 P1 的秒表，除非先让图像工具上报进度。

视觉与 P0 完全一致，只把假百分比换成「不确定点 + 真实秒表」——这是现在就能上的一版。

P1 波纹 + 秒表推荐

  • 徽标 = 三个跳动的小点 + 秒表：「正在发生」由点承担，时长由数字承担，两者都真实。
  • 顶部「正在创建图像 / 正在重绘」继续用现有阶段文案（提交请求 / 绘制 / 取回图片），超 45 秒换「上游较慢，仍在等待」。
  • 整体信息密度和参考图几乎一样，但没有一个假数字。

这就是我建议落地的版本。以后真做了进度上报，只需把徽标内容从「秒表」换成「环 + 百分比」，视觉不用再改。

P2 扫描亮带

  • 一条 30% 高度的亮带以 2.9s 匀速从上往下推，重复即「一遍遍扫」。
  • 方向固定、速度均匀，比波纹更像机器在工作，节奏感更稳。
  • 实现最省：一个 mask 位置动画，没有 transform 缩放，点和间距始终不变形。

缺点是单向、单调，长尾（比如 40 秒）会显得机械；波纹那种「一圈圈推出去」更像在生成。

没有明显的波，只有两团淡光在点阵上此起彼伏地呼吸（主光斑 + 左上偏移的一团）。

P3 双光斑呼吸

  • 两团光斑周期不同（5.2s / 6.4s 且相位差 2.6s），叠出的明暗不会明显重复，看着更自然。
  • 没有位移、没有扫动，是最安静的一版：适合一次要等十几秒、又不想让页面一直「动」的场景。

安静的另一面是存在感弱：用户可能看不出它在工作，得靠角标秒表跳数字确认。

反过来：一圈亮点从外向内收缩，像散落的点被收拢到中心——「正在成形」。

P4 汇聚成形

  • 亮环从 scale 1.9 收到 .35，两端都淡出，中间还有一段空心的环带（不透满），像一圈点被吸向中心。
  • 语义最贴「图像正在成形」，和扩散波纹正好相反：收缩 = 汇聚，扩散 = 渲染。

很多人看到「向内收」会下意识觉得在「缩小 / 取消」。扩散比收缩更安全，这条建议只作备选。

点阵分两层：底色是灰点铺满，中心区域换成蓝点并缓慢明暗——颜色即层次，不靠动效也能看出重点。

P6 星点闪烁

  • 14 颗星点随机落位、延迟错开（0–2.6s），每颗 2.6s 一个明灭周期，大小 1.6–2.6px 不等。
  • 底噪（点阵波纹）压到 .5 不透明度，让闪烁成为主角。

闪烁的随机感最像「AI 在思考」，但也最容易抢注意力，且每帧都在变，长时间盯着会累。若要用，星点数量压到 8 颗以内。

我的建议组合：P1（点阵 + 中心波纹扩散）× P5（中心蓝 / 边缘灰的双色层次）。 动效只保留波纹，徽标用「不确定点 + 秒表」，不出现任何百分比。

不做的事：不加假进度、不加水印图标、不加卡片描边。文字固定左上、徽标固定右下， 中间区域完全留给点阵——这样出图时把 <img> 铺满同一块区域，画面不跳。

尺寸相关：点阵间距固定 14px（不随容器缩放），所以大图和缩略图看起来点一样密； 硬编在 CSS 变量 --dot-step 里，手机上如果嫌密可降到 12px。
