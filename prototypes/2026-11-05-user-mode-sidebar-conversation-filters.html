会话列表搜索 · 把筛选条件放进筛选面板

侧栏的放大镜现在只能按关键词搜（/api/v1/chat/history?keyword=），但接口其实已经支持 scope / agent_id / status / start_date / end_date。聊天页右侧的历史面板已经有一套完整筛选， 这里要定的是：在 260px 宽的侧栏里，这些条件怎么放。

浮层贴侧栏右边缘滑出，不遮挡列表

推荐方案 A：搜索框旁的漏斗按钮 + 浮层面板

  • 与聊天页历史面板同一套条件（来源 / 智能体 / 状态 / 时间），用户不用学两遍；
  • 浮层向右展开、盖住内容区，不受 260px 侧栏宽度限制；移动端降级为底部抽屉；
  • 筛选生效时标题行显示「筛选 · 2」+ 一键清除，不至于筛完忘了自己筛过什么；
  • 成本：把 ChatHistorySidebar 里的面板抽成公共组件，两处复用。

备选方案 B：只做来源 / 状态 / 时间

  • 侧栏不请求智能体列表，零额外接口，面板也更窄（260px 内可放下）；
  • 代价：与历史面板条件不一致，用户想按智能体筛还得去聊天页；
  • 适合「只想快速收窄，不做精细筛选」的定位。

备选方案 C：搜索行下方常驻筛选 chips

  • 一行 chips：全部 / 任务会话 / 普通对话 / 今天 / 失败 …，点一下即时生效，零浮层、零遮挡；
  • 最省事也最快，但条件一多就放不下（侧栏一行只够 3～4 个），「更多筛选」最终还是要回到浮层。

实现要点（三个方案共用）

  • 请求参数直接扩到 scope / agent_id / status / start_date / end_date，后端已支持，无需改接口；
  • 浮层不要放在 overflow-y-auto 的列表容器里，会被裁剪 —— 挂在侧栏根部或用 teleport；
  • 智能体列表懒加载：首次打开面板才请求，失败就只剩「全部智能体」，不阻塞列表；
  • 筛选变化后与关键词一样走 300ms 防抖 + 回到第一页，沿用现有分页与「已加载全部」逻辑。
